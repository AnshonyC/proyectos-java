Apéndice BChuleta de Git y gh

Los comandos de Git y de GitHub CLI del libro, ordenados por el momento del trabajo en que se usan, con los que deshacen cosas marcados según su riesgo.

Todos se ejecutan desde la carpeta del repositorio ($HOME\Proyectos\Totito). Lo que va entre < y > se reemplaza por tu valor.

Configurar (una sola vez por computadora)

ComandoQué hace
git config --global user.name "Tu Nombre"El nombre que firmará tus commits (capítulo 7).
git config --global user.email "tu@correo.com"El correo de los commits. Usa el de tu cuenta de GitHub (o la dirección noreply que GitHub te da) para que los commits aparezcan a tu nombre.
git config --global init.defaultBranch mainQue los repositorios nuevos empiecen con la rama main.
git config --global core.autocrlf trueConvierte los saltos de línea de Windows y Unix de forma automática (el instalador de Git para Windows suele dejarlo así).
git config --global pull.rebase falseQue git pull una las ramas con un merge cuando hayan divergido (evita el error «Need to specify how to reconcile divergent branches»).
git config --global --listMuestra toda tu configuración.
gh auth loginConecta GitHub CLI con tu cuenta (GitHub.com → HTTPS → autenticar Git con tus credenciales de GitHub → navegador).
gh auth statusComprueba con qué cuenta estás conectado.

Empezar un repositorio

ComandoQué hace
git initConvierte la carpeta actual en un repositorio (crea la carpeta oculta .git).
git init -b mainIgual, con la rama principal llamada main aunque no hayas configurado init.defaultBranch.
gh repo create totito --public --source=. --remote=origin --pushCrea el repositorio en GitHub, lo conecta como origin y sube lo que ya tiene commits (capítulo 8). Usa --private para uno privado.
git clone <url> · gh repo clone <usuario>/<repo>Descarga una copia completa de un repositorio existente.
git remote -vMuestra a qué repositorio remoto está conectado.
git remote add origin <url>Conecta un remoto a mano (si no usaste gh repo create).

El ciclo de cada día

ComandoQué hace
git statusQué cambió, qué está preparado y en qué rama estás. Úsalo antes y después de todo.
git diffLos cambios que aún no preparaste, línea por línea.
git diff --stagedLos cambios ya preparados: lo que entrará en el próximo commit.
git add <archivo>Prepara un archivo para el commit (lo pasa al área de preparación, capítulo 6).
git add . · git add -APrepara todo lo de la carpeta actual / todo el repositorio, incluidos los archivos borrados.
git commit -m "Mensaje en imperativo"Guarda una foto de lo preparado con un mensaje (capítulo 9).
git log --onelineEl historial, un commit por línea.
git log --oneline --graph --allEl historial con las ramas dibujadas.
git show <commit>Qué cambió en un commit concreto (los primeros 7 caracteres del identificador bastan).
git pushSube los commits nuevos de la rama actual a GitHub.
git pullTrae y une los cambios de GitHub a tu rama.
git fetchTrae la información de GitHub sin tocar tus archivos (para mirar antes de unir).

Ramas

ComandoQué hace
git branchLista las ramas; la actual lleva *.
git switch -c interfaz-neonCrea una rama y se cambia a ella (capítulo 9).
git switch mainSe cambia a una rama existente.
git push -u origin interfaz-neonSube una rama nueva y la deja enlazada; después basta git push.
git merge interfaz-neonUne esa rama con la actual.
git merge --abortCancela un merge con conflictos y deja todo como estaba.
git branch -d <rama>Borra una rama ya unida. (Con -D la borra aunque no esté unida: cuidado.)

Cuando hay un conflicto, Git marca el archivo así (es la salida real de un conflicto provocado a propósito):

<<<<<<< HEAD
linea de uno
=======
linea de dos
>>>>>>> f8f3c8cd9ba757f2a6c3fd0af6c911648238d3d8

Arriba está tu versión, abajo la que llega. Edita el archivo para dejar el resultado correcto, borra las tres líneas de marcas y termina con git add <archivo> y git commit (capítulo 9).

Guardar a un lado y etiquetar

ComandoQué hace
git stashGuarda tus cambios sin commit «en un cajón» y deja la carpeta limpia.
git stash popSaca del cajón lo último guardado.
git stash listLo que hay en el cajón.
git tag -a v1.0.0 -m "Totito 1.0.0"Pone una etiqueta con mensaje en el commit actual (capítulos 9 y 67).
git tagLista las etiquetas.
git push origin v1.0.0 · git push --tagsSube una etiqueta / todas. git push a secas no sube etiquetas.

Deshacer, de menos a más peligroso

ComandoQué haceRiesgo
git restore --staged <archivo>Saca un archivo del área de preparación. Tus cambios siguen en el archivo.Ninguno
git commit --amend -m "Mensaje corregido"Corrige el último commit (mensaje o archivos olvidados). Solo si aún no hiciste push.Bajo
git revert <commit>Crea un commit nuevo que deshace otro. Es la forma segura de deshacer algo que ya está en GitHub.Bajo
git reset --soft HEAD~1Deshace el último commit pero conserva sus cambios preparados. Solo si no hiciste push.Medio
git restore <archivo>Descarta los cambios no guardados de un archivo y lo deja como en el último commit. Lo descartado no se recupera.Alto
git reset --hard HEADDescarta todos los cambios sin commit del repositorio.Muy alto
git push --forceReemplaza la historia de GitHub por la tuya. En una rama compartida borra el trabajo ajeno. No lo uses en main.Muy alto
Antes de un comando peligroso Haz git status y git stash (o un commit en una rama aparte). Mientras algo tenga commit, Git casi siempre puede recuperarlo; lo que nunca tuvo commit, no.

Archivos que no se suben

ComandoQué hace
.gitignoreArchivo con los patrones que Git ignora (target/, out/, dist/…, capítulo 5).
git check-ignore -v <archivo>Dice qué línea del .gitignore ignora ese archivo.
git rm --cached <archivo>Deja de seguir un archivo que se subió por error, sin borrarlo de tu disco. Agrégalo luego al .gitignore.

GitHub CLI (gh)

ComandoQué hace
gh repo view --webAbre el repositorio en el navegador.
gh browseIgual; con un archivo, gh browse src/Tablero.java, abre ese archivo.
gh pr create --base main --head interfaz-neon --title "…" --body "…"Abre un Pull Request (capítulos 10 y 61). Sin --title ni --body, te los pregunta.
gh pr list · gh pr view <n>Lista los PR / muestra uno. Con --web, en el navegador.
gh pr checkout <n>Baja la rama de un PR para probarlo.
gh pr merge <n> --mergeUne el PR con un commit de merge (también --squash o --rebase). Después: git switch main y git pull.
gh issue create --title "…" --body "…"Crea un issue (una tarea o un error anotado).
gh issue list · gh issue close <n>Lista issues / cierra uno. Un commit con Fixes #3 en el mensaje lo cierra solo al llegar a main.
gh release create v1.0.0 dist\instalador\Totito-1.0.0.exe --title "Totito 1.0.0" --notes "…"Publica una Release con el instalador adjunto (capítulo 67). Si la etiqueta no existe, la crea.
gh release list · gh release view v1.0.0Lista las Releases / muestra una.
gh repo fork <dueño>/<repo> --cloneHace un fork y lo descarga, para contribuir a un proyecto ajeno (capítulo 69).
