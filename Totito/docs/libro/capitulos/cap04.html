Capítulo 4Instalar las herramientas

En este capítulo instalas, con cuatro comandos de PowerShell, todo lo necesario para programar el Totito: el kit de desarrollo de Java, Git, el comando de GitHub y el editor NetBeans. Además vas a entender qué hace cada instalación por dentro (en especial PATH y JAVA_HOME), cómo comprobar que todo quedó bien y qué hacer si algo falla.

¿Por qué Temurin y por qué la versión 21?

Java no es un único programa de una única empresa. El lenguaje es abierto, y varias organizaciones publican su propia «distribución» del JDK, todas compatibles entre sí: Oracle, Microsoft, Amazon, Eclipse… Eclipse Temurin, de la fundación Eclipse Adoptium, es gratuita para cualquier uso (también comercial), está muy probada y es una de las más usadas. Por eso la elegimos.

Java saca una versión nueva cada seis meses, pero solo algunas son LTS (Long-Term Support, «soporte a largo plazo»): versiones que reciben correcciones de seguridad durante muchos años. Java 21 es LTS, así que es una base estable para aprender: lo que escribas hoy seguirá funcionando igual dentro de varios años. El proyecto Totito está configurado para funcionar con Java 17 o cualquier versión más nueva, así que el JDK 21 le sobra (verás por qué en el capítulo 5).

winget: el instalador de programas de Windows

Normalmente, para instalar un programa buscas su página web, descargas un instalador, lo abres y haces clic en «Siguiente» varias veces. winget (de Windows Package Manager, «administrador de paquetes de Windows») hace todo eso con un solo comando: sabe de dónde descargar cada programa, comprueba que la descarga no esté alterada y ejecuta el instalador con las opciones adecuadas. Piensa en él como una tienda de aplicaciones que se usa escribiendo.

Cada programa del catálogo de winget es un paquete con un identificador (ID) único, con la forma Editor.Producto: Git.Git, GitHub.cli, Apache.NetBeans. El catálogo es público y lo revisan personas antes de aceptar cada paquete.

Comprobar que tienes winget

Abre PowerShell (capítulo 3) y escribe:

winget --version
v1.29.380

Si ves un número de versión (el tuyo será distinto), lo tienes. Si en cambio ves esto:

winget : El término 'winget' no se reconoce como nombre de un cmdlet, función, archivo de script o programa ejecutable.

es que falta o está desactualizado el paquete que lo contiene, llamado Instalador de aplicación (App Installer). Para instalarlo:

  1. Abre la Microsoft Store desde el menú Inicio.
  2. Busca Instalador de aplicación (de Microsoft Corporation).
  3. Haz clic en Obtener o Actualizar.
  4. Cierra PowerShell, vuelve a abrirlo y repite winget --version.

Si tu Windows es anterior a Windows 10 22H2, primero actualízalo (capítulo 2).

Buscar antes de instalar

Antes de instalar, conviene ver qué hay en el catálogo. Por ejemplo:

winget search Temurin
Nombre                                     Id                              Versión
--------------------------------------------------------------------------------------
Eclipse Temurin JDK with Hotspot 21        EclipseAdoptium.Temurin.21.JDK  21.0.8.9
Eclipse Temurin JRE with Hotspot 21        EclipseAdoptium.Temurin.21.JRE  21.0.8.9
Eclipse Temurin JDK with Hotspot 17        EclipseAdoptium.Temurin.17.JDK  17.0.16.8
...

Fíjate en que hay un JDK y un JRE. El JRE (Java Runtime Environment) solo sirve para ejecutar programas Java; el JDK además permite crearlos, porque incluye el compilador. Necesitas el JDK. Este es el motivo de que el libro te dé siempre el ID exacto: con nombres tan parecidos, es fácil instalar el equivocado.

La primera vez, winget pide aceptar unos términos. Al usar winget por primera vez puede preguntarte si aceptas los contratos de los orígenes de paquetes (el catálogo de la comunidad y la Microsoft Store), con una pregunta que se responde con Y (sí) o N (no). Escribe Y y presiona Enter. Solo lo pregunta una vez.

Instalar el JDK

winget install --id EclipseAdoptium.Temurin.21.JDK -e

Desarmemos el comando, palabra por palabra:

ParteQué significa
wingetEl programa al que le hablas.
installLa acción: instalar. Otras acciones son search (buscar), list (ver lo instalado), upgrade (actualizar) y uninstall (desinstalar).
--idUn parámetro que dice «lo que viene a continuación es un identificador de paquete», no un nombre aproximado. Los parámetros largos empiezan con dos guiones.
EclipseAdoptium.Temurin.21.JDKEl ID: editor Eclipse Adoptium, producto Temurin, versión 21, el JDK (no el JRE).
-eAbreviatura de --exact: «busca exactamente este ID, respetando mayúsculas y minúsculas». Sin -e, winget busca IDs que contengan el texto, y si hay varios parecidos podría quejarse o elegir otro. Con -e no hay ambigüedad.

Al presionar Enter verás algo parecido a esto (los textos exactos cambian con la versión de winget):

A mitad del proceso, Windows mostrará la ventana del Control de cuentas de usuario preguntando si permites que el instalador haga cambios. Comprueba que el editor sea Eclipse Adoptium y responde Sí. Si respondes No, la instalación se cancela (puedes repetir el comando).

La línea «Se comprobó correctamente el hash del instalador» merece una explicación: un hash es una especie de huella digital de un archivo, calculada a partir de todo su contenido. El catálogo de winget guarda la huella del instalador original; al terminar la descarga, winget calcula la huella del archivo que recibió y las compara. Si alguien hubiera alterado el instalador, aunque fuera un solo byte, las huellas no coincidirían y winget se negaría a instalarlo.

Qué hizo el instalador del JDK por dentro

  • Copió el JDK en una carpeta como C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot\ (los números serán los de tu versión). Dentro hay una subcarpeta bin con java.exe, javac.exe y las demás herramientas.
  • Agregó esa carpeta bin al PATH, para que puedas escribir java desde cualquier carpeta.
  • Creó la variable JAVA_HOME, que apunta a la carpeta del JDK.
  • Asoció los archivos .jar con Java, para que se abran con doble clic (te servirá en el capítulo 63).

Enseguida verás qué son PATH y JAVA_HOME y cómo comprobarlos. Antes, instala lo demás.

Instalar Git y GitHub CLI

winget install --id Git.Git -e
winget install --id GitHub.cli -e

Misma estructura: Git.Git es Git para Windows (el editor y el producto se llaman igual) y GitHub.cli es la herramienta de línea de comandos de GitHub, cuyo comando se llama gh. Fíjate en las mayúsculas: GitHub.cli, con cli en minúsculas. Con -e, una mayúscula de más o de menos hace que winget no encuentre el paquete.

Git para Windows trae, además del comando git, una terminal propia llamada Git Bash. No la necesitas: en este libro todo se hace desde PowerShell.

La configuración de Git viene después. El instalador deja Git con sus opciones de fábrica. Tu nombre, tu correo, el editor que abrirá Git y el nombre de la rama principal (main) se configuran en el capítulo 7, cuando entiendas para qué sirve cada cosa.

Instalar NetBeans

winget install --id Apache.NetBeans -e --skip-dependencies

El ID es Apache.NetBeans y la versión que instala winget es la 25. Este comando tiene un parámetro más, --skip-dependencies («saltar dependencias»), y conviene entender por qué.

Una dependencia es otro programa que un programa necesita para funcionar. NetBeans está escrito en Java, así que necesita un JDK para arrancar. El paquete de NetBeans en winget declara como dependencia otra distribución de Java (Liberica JDK 23) y, si no le dices nada, la instala junto con NetBeans. Pero tú ya tienes un JDK, el Temurin 21 que acabas de instalar, y NetBeans 25 funciona perfectamente con él. Tener dos JDK distintos en la misma computadora no rompe nada, pero confunde: según el orden del PATH, al escribir java podría responder uno u otro, y al principio es mejor que haya uno solo. Por eso le pides a winget que no instale la dependencia.

El orden importa: primero el JDK, después NetBeans. Con --skip-dependencies, el instalador de NetBeans busca un JDK que ya esté en la computadora. Si instalas NetBeans antes que el JDK, no encontrará ninguno y fallará o NetBeans no arrancará. Si eso te pasa, instala el JDK y luego repite la instalación de NetBeans.

Si tu versión de winget es antigua y responde que no reconoce el argumento --skip-dependencies, quítalo: winget install --id Apache.NetBeans -e. Se instalará también Liberica JDK 23; más abajo, en «Problemas típicos», verás cómo comprobar cuál de los dos responde y por qué no es grave.

La descarga de NetBeans es la más pesada (unos 400 MB) y su instalación tarda unos minutos. Puede que no veas ventana alguna mientras tanto: winget lo instala en modo silencioso. Espera a que aparezca «Instalado correctamente».

Cerrar y volver a abrir PowerShell

Este paso es pequeño pero imprescindible: cierra la ventana de PowerShell y abre una nueva.

¿Por qué? Cuando se abre un programa, Windows le entrega una copia de las variables de entorno (entre ellas, el PATH) tal como están en ese instante. Los instaladores modificaron el PATH «oficial» de Windows, pero tu ventana de PowerShell sigue trabajando con la copia vieja, tomada cuando la abriste, en la que todavía no existen Java, Git ni gh. Una ventana nueva recibe una copia nueva, ya actualizada. Es como una fotocopia de una lista de teléfonos: si alguien agrega un número al original, tu fotocopia no se entera; tienes que sacar otra.

«No se reconoce como nombre de un cmdlet» justo después de instalar. Es el síntoma clásico de no haber reabierto PowerShell. Y ojo: si usas Windows Terminal, cerrar una pestaña no basta en algunos casos; cierra la ventana completa. Si aun así no funciona, cierra sesión en Windows y vuelve a entrar.

Verificar que todo quedó bien

En la ventana nueva de PowerShell, escribe estos cuatro comandos, uno por uno:

java -version
javac -version
git --version
gh --version

Deberías ver algo así (con tus números de versión, que serán iguales o más nuevos):

openjdk version "21.0.8" 2025-07-15 LTS
OpenJDK Runtime Environment Temurin-21.0.8+9 (build 21.0.8+9-LTS)
OpenJDK 64-Bit Server VM Temurin-21.0.8+9 (build 21.0.8+9-LTS, mixed mode, sharing)

javac 21.0.8

git version 2.55.0.windows.5

gh version 2.102.0 (2026-09-30)
https://github.com/cli/cli/releases/tag/v2.102.0

Lo que dice cada línea de java -version, porque vas a volver a verla muchas veces:

  • openjdk version "21.0.8" … LTS: la versión de Java. El primer número (21) es lo importante; los demás son correcciones. LTS confirma que es de soporte largo. OpenJDK es el proyecto abierto del que parten todas las distribuciones.
  • OpenJDK Runtime Environment Temurin-…: el «entorno de ejecución», es decir, las bibliotecas que trae Java (para ventanas, archivos, red…). Aquí confirmas que es Temurin.
  • OpenJDK 64-Bit Server VM …: la máquina virtual de Java (JVM), el motor que ejecuta los programas Java, en su versión de 64 bits. En el capítulo 11 verás qué es exactamente y por qué Java la necesita.

java -version comprueba que puedes ejecutar Java; javac -version comprueba que puedes compilar. Si el primero funciona y el segundo no, instalaste un JRE en lugar de un JDK, o tienes otro Java antiguo delante en el PATH (mira «Problemas típicos»). Ambos números deberían coincidir.

Un solo guion o dos. Fíjate en que Java usa -version (un guion) y Git y gh usan --version (dos). No hay una regla universal: cada programa decide cómo se escriben sus opciones. Java conserva el estilo antiguo de un guion por compatibilidad (aunque las versiones nuevas también aceptan --version). Cuando dudes, prueba con --help o consulta su documentación.
Hito Si los cuatro comandos respondieron con su versión, tu computadora ya es una computadora de programador: tiene el compilador de Java, el control de versiones y la conexión con GitHub. Anota las cuatro versiones en tu ficha técnica del capítulo 2.

PATH y JAVA_HOME: cómo encuentra Windows a Java

PATH

En el capítulo 3 viste que $env:Path es la lista de carpetas donde Windows busca los programas. Cuando escribes java, Windows recorre esas carpetas en orden y ejecuta el primer java.exe que encuentra. Comprueba que el instalador agregó la carpeta del JDK:

$env:Path -split ";" | Select-String "Adoptium"
C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot\bin\

Aquí combinas lo que ya sabes: partes el PATH en líneas y, con la tubería, filtras solo las que contienen «Adoptium». Para saber qué java.exe se ejecuta exactamente cuando escribes java:

where.exe java
C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot\bin\java.exe

where.exe lista, en orden, todos los java.exe que hay en las carpetas del PATH. El primero es el que se usa. Si aparece más de una línea, tienes varios Java instalados, y el de arriba gana. Fíjate en el .exe: en PowerShell, where a secas es un alias de otro comando (Where-Object, que filtra datos) y no haría lo que buscas. Otra forma de preguntar lo mismo es Get-Command java, que muestra la ruta en su columna Source.

JAVA_HOME

JAVA_HOME es una variable de entorno que no usa Windows, sino las herramientas de Java: Maven, NetBeans y muchas otras la consultan para saber dónde está el JDK. A diferencia del PATH, no es una lista, sino una sola ruta, y apunta a la carpeta raíz del JDK, no a bin:

$env:JAVA_HOME
C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot\
VariableApunta aLa usaPara
Path…\jdk-21…\bin (entre muchas otras carpetas)Windows, PowerShellEncontrar java.exe cuando escribes java.
JAVA_HOME…\jdk-21… (una sola ruta)Maven, NetBeans y otras herramientas de JavaSaber qué JDK usar y encontrar todo lo que trae.

El instalador de Temurin, tal como lo ejecuta winget, crea JAVA_HOME automáticamente. Si al escribir $env:JAVA_HOME no aparece nada (una línea vacía), créala tú con estos comandos:

$jdk = Split-Path (Split-Path (Get-Command javac).Source)
$jdk
[Environment]::SetEnvironmentVariable("JAVA_HOME", $jdk, "User")

Qué hace cada línea:

  1. (Get-Command javac).Source da la ruta completa de javac.exe, por ejemplo C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot\bin\javac.exe. Cada Split-Path le quita el último trozo: el primero quita javac.exe y el segundo quita bin. El resultado se guarda en una variable nueva, $jdk.
  2. $jdk muestra la ruta calculada, para que compruebes que termina en la carpeta del JDK y no en bin.
  3. La última línea guarda la variable JAVA_HOME de forma permanente para tu usuario ("User"). No necesita permisos de administrador.

Como siempre que cambias variables de entorno, cierra y vuelve a abrir PowerShell para que $env:JAVA_HOME muestre el valor nuevo.

Ver y editar las variables con el ratón

Todo lo anterior también se puede ver en una ventana: presiona Win, escribe variables de entorno y elige Editar las variables de entorno del sistema. En la ventana que se abre, haz clic en Variables de entorno…. Verás dos listas: arriba, las variables de usuario (solo para ti) y abajo, las variables del sistema (para todos los usuarios). Seleccionando Path y pulsando Editar… aparece la lista de carpetas, una por renglón, con botones para subir y bajar cada una. Mira, pero no cambies nada si no estás seguro: un PATH dañado puede hacer que muchos programas dejen de encontrarse.

Primer arranque de NetBeans

Abre el menú Inicio y busca Apache NetBeans IDE 25 (también quedó un acceso directo en el escritorio). El primer arranque tarda más de lo normal: NetBeans prepara su configuración. Si te pregunta si quieres importar la configuración de una versión anterior, responde que no. Si Windows Defender o el firewall preguntan algo, permite el acceso en redes privadas.

Para comprobar que NetBeans usa tu JDK 21, abre Help → About (Ayuda → Acerca de). Verás algo como:

Product Version: Apache NetBeans IDE 25
Java: 21.0.8; OpenJDK 64-Bit Server VM 21.0.8+9-LTS
Runtime: OpenJDK Runtime Environment 21.0.8+9-LTS
System: Windows 11 version 10.0 running on amd64; UTF-8; es_GT (nb)

La línea Java debe decir 21. Cierra NetBeans por ahora; en el capítulo 5 lo usarás de verdad. Si en cambio NetBeans no arranca y muestra un mensaje de que no encuentra un JDK, mira la tabla de problemas típicos.

Instalación manual (si winget no es una opción)

Si winget no funciona en tu computadora, cada herramienta se puede instalar descargando su instalador desde la página oficial. Usa solo estas direcciones: descargar programas de sitios no oficiales es una de las vías más comunes de infección.

Opcionales recomendados

Windows Terminal

winget install --id Microsoft.WindowsTerminal -e

Windows Terminal es una ventana moderna para PowerShell: pestañas (varias terminales en una ventana), mejor manejo de copiar y pegar, tildes y emojis bien dibujados, y temas de color. En Windows 11 ya viene instalado (si el comando dice que ya existe, perfecto). Ábrelo buscando Terminal en el menú Inicio; por defecto abre PowerShell. Todos los comandos del libro funcionan igual dentro de él.

Visual Studio Code

winget install --id Microsoft.VisualStudioCode -e

VS Code es un editor de texto para programadores, ligero y gratuito. No es necesario para el libro (NetBeans hace todo), pero es más cómodo que el Bloc de notas para archivos como el README.md o el .gitignore: colorea su contenido y muestra los caracteres invisibles. Tras instalarlo y reabrir PowerShell, code . abre la carpeta actual en VS Code.

Mantener las herramientas al día

winget upgrade

Sin más parámetros, winget upgrade solo lista los programas que tienen una versión más nueva; no instala nada. Para actualizar uno concreto: winget upgrade --id Git.Git -e. Una buena costumbre es revisarlo una vez al mes, y no actualizar el JDK ni NetBeans a mitad de un capítulo: hazlo entre capítulos, cuando todo compila, para que si algo cambia sepas que fue la actualización.

Resumen

  • winget instala programas con un comando: winget install --id <ID> -e, donde --id indica un identificador y -e exige coincidencia exacta.
  • Se instalan, en este orden: JDK 21 de Temurin, Git, GitHub CLI y NetBeans 25 (con --skip-dependencies para no añadir un segundo JDK).
  • El JDK incluye javac (compilar) y java (ejecutar); el JRE solo ejecuta. Java 21 es LTS.
  • Después de instalar hay que cerrar y volver a abrir PowerShell, porque cada ventana tiene una copia del PATH tomada al abrirse.
  • Se verifica con java -version, javac -version, git --version y gh --version.
  • PATH es la lista de carpetas donde Windows busca programas (gana el primero, mira where.exe java); JAVA_HOME apunta a la carpeta raíz del JDK y la usan Maven y NetBeans.
  • Si winget falla, cada herramienta se puede instalar a mano desde su página oficial.
Aplícalo fuera del Totito Lo que aprendiste sirve para montar cualquier entorno de trabajo:
  • Preparar una computadora nueva en minutos: guarda en un archivo de texto la lista de comandos winget install de los programas que usas (navegador, editor, Zoom, 7-Zip…) y ejecútalos de una vez cuando cambies de equipo.
  • Otros lenguajes: Python (Python.Python.3.12), Node.js (OpenJS.NodeJS.LTS) o Go siguen el mismo patrón: instalar, reabrir la terminal, verificar con --version y revisar el PATH si no aparece.
  • Diagnosticar «el programa no se encuentra»: con cualquier herramienta, where.exe y $env:Path te dicen si está en el PATH y cuál versión responde primero.
  • Herramientas de Java del mundo real: servidores como Tomcat, herramientas como Gradle o Android Studio buscan el JDK en JAVA_HOME; ya sabes comprobarla y crearla.
Ejercicios
  1. Ejecuta winget list y localiza en la lista las cuatro herramientas que instalaste. Pista: winget list Temurin filtra por nombre.
  2. Cuenta otra vez las carpetas de tu PATH con ($env:Path -split ";").Count y compáralo con el número que anotaste en el capítulo 3. ¿Cuántas agregaron los instaladores? Identifícalas.
  3. Usa where.exe para encontrar dónde están git.exe, gh.exe y javac.exe. ¿Están todos en C:\Program Files?
  4. Ejecuta winget show --id GitHub.cli -e y averigua quién publica el paquete, su licencia y su página oficial.
  5. Abre jshell (viene con el JDK; escribe jshell en PowerShell), escribe 2 + 3 y presiona Enter. Luego escribe /exit para salir. Acabas de ejecutar tu primera instrucción de Java; el capítulo 11 te explica qué pasó. Pista: si jshell no se reconoce, revisa el PATH como en este capítulo.
