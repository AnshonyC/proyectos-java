Capítulo 17Texto y entrada

El Totito muestra textos («Turno de Ana», «¡Tres en línea!»), recibe el nombre que escribes en la configuración y lo recorta si no cabe, y convierte sus colores en códigos como #FF3BD4. En este capítulo aprendes a trabajar con texto en Java (la clase String, sus métodos, la forma correcta de comparar, StringBuilder y String.format) y a leer lo que el usuario escribe en el teclado con Scanner, como hace PruebaConsola.

Qué es un String

Un String («cadena», de cadena de caracteres) es un texto: una secuencia ordenada de caracteres, como las cuentas de un collar. "Ana" es la cadena formada por 'A', 'n' y 'a'. Ya sabes tres cosas de ella:

  • Se escribe entre comillas dobles; un char suelto, entre simples (capítulo 12).
  • No es un tipo primitivo sino una clase (por eso la mayúscula), y cada texto es un objeto con métodos: nombre.length(), nombre.trim()…
  • El + pega textos con cualquier cosa.

Como los arreglos, los caracteres de un String se numeran desde 0: en "Ana", la posición 0 es 'A' y la 2 es 'a'. Y como Java usa Unicode, un String puede contener tildes, eñes, signos de apertura (¡, ¿) y símbolos como los puntos suspensivos … (un solo carácter) que usa Dibujo.recortar.

Los String son inmutables

Esta es la propiedad más importante de los textos en Java: un String nunca cambia una vez creado. Ningún método modifica el texto original; los que parecen hacerlo (pasar a mayúsculas, quitar espacios, recortar) devuelven un String nuevo y dejan el original intacto.

public class Inmutable {
    public static void main(String[] args) {
        String nombre = "ana";
        nombre.toUpperCase();                 // crea "ANA"... y se pierde
        System.out.println("1) " + nombre);
        nombre = nombre.toUpperCase();        // guardar el nuevo texto
        System.out.println("2) " + nombre);

        String original = "Totito";
        String otro = original;
        otro = otro + " neón";                // crea un String nuevo
        System.out.println("3) original: " + original + " | otro: " + otro);
    }
}
1) ana
2) ANA
3) original: Totito | otro: Totito neón
  1. nombre.toUpperCase(); fabricó "ANA", pero nadie lo guardó: se perdió. nombre sigue siendo "ana". Es el error más común con textos.
  2. Para «cambiar» una variable de texto hay que asignarle el resultado: nombre = nombre.toUpperCase();. La variable ahora apunta al texto nuevo; el viejo, si nadie más lo usa, lo recoge la memoria.
  3. otro y original apuntaban al mismo String (capítulo 15: referencias). Pero como nadie puede modificar un String, compartirlo es totalmente seguro: otro + " neón" crea uno nuevo y original no se entera. Con un arreglo, compartir era peligroso; con String, no.
Analogía: un letrero impreso. Un String es como un letrero impreso: si quieres que diga otra cosa, no lo corriges con marcador, imprimes uno nuevo y lo cuelgas en lugar del viejo. Quien tenía una foto del letrero viejo sigue viendo el viejo. Esa es la razón por la que Jugador puede entregar su nombre con getNombre() sin miedo: nadie podrá alterarlo desde fuera.

Dos detalles que confunden al principio:

  • substring(0, 3) da 3 caracteres, las posiciones 0, 1 y 2. El final es exclusivo, como en for (int i = 0; i < 3; i++). Ventaja: la longitud del trozo es b - a, y substring(0, largo - 1) es «todo menos el último», justo lo que hace Dibujo.recortar en cada vuelta de su while (capítulo 14). Si pides posiciones fuera del texto, obtienes StringIndexOutOfBoundsException, el primo de la excepción de los arreglos.
  • trim() no toca los espacios de en medio: " Ana Lucía " queda "Ana Lucía". Y un texto hecho solo de espacios queda vacío.

Cómo el Totito decide el nombre de un jugador

En la pantalla de configuración escribes tu nombre. TarjetaJugador lo entrega así:

/** El nombre escrito o, si se dejo vacio, el titulo ("Jugador 1"). */
public String getNombre() {
    String nombre = campo.getText().trim();
    return nombre.isEmpty() ? titulo : nombre;
}

Línea a línea: campo.getText() devuelve lo que hay escrito en la caja de texto; .trim() se aplica sobre ese resultado (las llamadas se encadenan de izquierda a derecha: cada punto actúa sobre lo que devolvió lo anterior) y quita espacios sobrantes. Después, el ternario del capítulo 13: si no queda nada, se usa el título de la tarjeta. ¿Por qué el trim()? Porque si alguien escribe solo espacios, sin él el nombre sería « » y el letrero diría «Turno de ». Con él, esa persona se llama «Jugador 1». Un método de cinco letras evita un letrero roto.

Desde Java 11 existen strip() (como trim(), pero entiende más tipos de espacios de Unicode) e isBlank() («¿está vacío o solo tiene espacios?»). nombre.isBlank() equivale a nombre.trim().isEmpty(). Puedes usarlos en tus proyectos; el Totito usa la forma clásica, que verás en todo el código antiguo.

Comparar textos: equals, nunca ==

Con int o char, == compara valores. Con objetos, == pregunta otra cosa: «¿son el mismo objeto?», es decir, ¿las dos variables guardan la misma referencia? Dos textos con las mismas letras pueden ser objetos distintos. Para saber si dos textos tienen el mismo contenido se usa el método equals:

public class Comparar {
    public static void main(String[] args) {
        String a = "Ana";
        String b = "Ana";
        String c = "Ana Lucía".substring(0, 3);   // tambien dice "Ana", pero es otro objeto

        System.out.println("c = " + c);
        System.out.println("a == b      : " + (a == b));
        System.out.println("a == c      : " + (a == c));
        System.out.println("a.equals(c) : " + a.equals(c));
        System.out.println("\"ana\".equals(a)           : " + "ana".equals(a));
        System.out.println("\"ana\".equalsIgnoreCase(a) : " + "ana".equalsIgnoreCase(a));

        String vacio = null;
        System.out.println("\"Ana\".equals(null) : " + "Ana".equals(vacio));
    }
}

a == b      : true
a == c      : false
a.equals(c) : true
"ana".equals(a)           : false
"ana".equalsIgnoreCase(a) : true
"Ana".equals(null) : false

Lo traicionero es la primera línea: a == b dio true. Java guarda una sola copia de cada texto literal escrito en el código (como los dos "Ana") y la reutiliza, así que a y b son de verdad el mismo objeto. Pero en cuanto el texto se fabrica durante la ejecución (con substring, con +, al leerlo del teclado o de una caja de texto), es un objeto nuevo y == da false aunque las letras sean idénticas. Por eso un programa que compara con == puede «funcionar» en tus pruebas y fallar con lo que escribe el usuario.

Regla sin excepciones: los textos se comparan con equals (o equalsIgnoreCase si no importan las mayúsculas). Y si uno de los dos es un literal, ponlo delante: "Ana".equals(nombre) funciona aunque nombre sea null (da false), mientras que nombre.equals("Ana") lanzaría NullPointerException. El Totito evita el problema en lo más repetido (las fichas son char, capítulo 12), y donde compara textos usa métodos que llaman a equals por dentro, como instaladas.contains(familia) en Tema.
Analogía: dos ejemplares del mismo libro. Tú y tu amiga tienen cada una un ejemplar de «Cien años de soledad». ¿Es el mismo libro? Depende de la pregunta. «¿Tienen el mismo texto?» Sí: eso es equals. «¿Es el mismo objeto físico, el que tienes en la mano?» No: eso es ==. Casi siempre quieres la primera pregunta.

Concatenar: el + y StringBuilder

El + con un String a un lado convierte lo del otro lado en texto y los pega. Reglas que ya viste en los capítulos 12 y 14, juntas:

public class Concatenar {
    public static void main(String[] args) {
        String nombre = "Ana";
        char ficha = 'X';
        int victorias = 3;
        System.out.println("Turno de " + nombre);
        System.out.println(nombre + " (" + ficha + ") lleva " + victorias + " victorias");
        System.out.println("Total: " + victorias + 2);
        System.out.println("Total: " + (victorias + 2));

        // Construir el tablero de texto con StringBuilder
        char[][] casillas = {
            {'X', 'O', ' '},
            {' ', 'X', ' '},
            {'O', ' ', 'X'}
        };
        StringBuilder sb = new StringBuilder();
        for (int fila = 0; fila < 3; fila++) {
            sb.append(' ').append(casillas[fila][0])
              .append(" | ").append(casillas[fila][1])
              .append(" | ").append(casillas[fila][2]).append('\n');
            if (fila < 2) {
                sb.append("---+---+---\n");
            }
        }
        String tablero = sb.toString();
        System.out.print(tablero);
        System.out.println("El texto mide " + tablero.length() + " caracteres");
    }
}

Por qué existe StringBuilder

Como los String son inmutables, cada + fabrica un texto nuevo copiando todos los caracteres anteriores. Para pegar tres o cuatro trozos en una línea da igual (el compilador ya lo optimiza), pero si construyes un texto largo pegando dentro de un bucle de miles de vueltas, estarías copiando y tirando miles de textos cada vez más largos. StringBuilder («constructor de cadenas») es un texto modificable: tiene un espacio interno que va creciendo, y append («añadir al final») escribe ahí sin copiar lo anterior. Al terminar, toString() te da el String definitivo.

Fíjate en el estilo: sb.append(' ').append(casillas[fila][0]).append(" | ")…. Cada append devuelve el mismo StringBuilder, así que se puede encadenar el siguiente; partir la cadena en varias líneas, con el punto al principio, hace que se lea como una lista. Acepta cualquier tipo: char, String, números. El '\n' es el salto de línea (capítulo 12), que aquí se añade a mano porque estamos fabricando un texto, no imprimiendo con println.

Analogía. Concatenar con + en un bucle es como reescribir a mano una carta entera cada vez que quieres añadirle una frase. StringBuilder es un cuaderno donde vas escribiendo al final de lo que ya hay, y solo al terminar lo pasas en limpio.

Úsalo cuando armes un texto dentro de un bucle: un informe, un archivo CSV, el tablero en consola de un tablero grande. Para una línea suelta, el + es más legible y el Totito lo usa así: "Turno de " + enTurno.getNombre().

String.format: texto con plantilla

Cuando un texto mezcla muchas variables, o necesitas controlar cómo se ven los números (decimales, ceros a la izquierda, anchos), es más claro escribir una plantilla con huecos y rellenarlos: String.format(plantilla, valores…). Cada hueco empieza con % y una letra que indica qué tipo de dato va ahí; los valores se colocan en orden.

public class Formato {
    public static void main(String[] args) {
        String nombre = "Ana";
        int victorias = 3;
        double porcentaje = 3 * 100.0 / 7;

        System.out.println(String.format("%s lleva %d victorias", nombre, victorias));
        System.out.println(String.format("Gana el %.1f %% de las veces", porcentaje));
        System.out.println(String.format("Ficha: %c", 'X'));
        System.out.println(String.format("[%5d] [%-5d] [%05d]", 42, 42, 42));
        System.out.println(String.format("[%-10s|%10s]", "Ana", "IA"));

        // Como Tema.hex: el color ROSA (255, 59, 212) en "#RRGGBB"
        int r = 0xFF, g = 0x3B, b = 0xD4;
        System.out.println(String.format("#%02X%02X%02X", r, g, b));
        System.out.println(String.format("con %%X: #%X%X%X", 5, 11, 0));
        System.out.println(String.format("con %%02X: #%02X%02X%02X", 5, 11, 0));
        System.out.println(String.format("con %%02x: #%02x%02x%02x", r, g, b));

        System.out.printf("printf: %s juega con %c%n", nombre, 'O');
        System.out.println("%s tiene %d empates".formatted("Luis", 2));
    }
}

Tema.hex y el misterioso "%02X"

Ahora puedes leer este método de Tema carácter por carácter:

/** "#RRGGBB", para usar los colores del tema dentro de texto HTML de un JLabel. */
public static String hex(Color color) {
    return String.format("#%02X%02X%02X", color.getRed(), color.getGreen(), color.getBlue());
}
  • #: un carácter literal; los colores web empiezan así.
  • %02X, tres veces: un hueco por cada componente del color (rojo, verde, azul, cada uno de 0 a 255, capítulo 35). X lo escribe en hexadecimal con letras mayúsculas; 2 exige al menos dos caracteres de ancho; 0 rellena con ceros, no con espacios.
  • Para el ROSA (255, 59, 212): 255 → FF, 59 → 3B, 212 → D4. Resultado: #FF3BD4, exactamente el código de color del diseño.

¿Por qué no basta con %X? Mira las líneas «con %X» y «con %02X» de la salida, con un color (5, 11, 0). Sin el relleno, 5 se escribe 5 y 0 se escribe 0: sale #5B0, que no tiene seis cifras y que un navegador interpretaría como otro color (#55BB00, porque los colores de tres cifras se leen duplicando cada una). Con %02X cada componente ocupa siempre sus dos posiciones: #050B00, el color correcto. Dos caracteres en la plantilla evitan un error de color sutil que nadie detectaría a simple vista.

¿Y para qué quiere el Totito un color como texto? PantallaInstrucciones escribe las instrucciones con un poco de HTML (las etiquetas de JLabel admiten HTML sencillo) y colorea la X de rosa y la O de azul dentro de la frase:

String x = "<font color='" + Tema.hex(Tema.ROSA) + "'><b>X</b></font>";

Que se convierte en el texto <font color='#FF3BD4'><b>X</b></font>. Gracias a hex, el color sale de la misma constante Tema.ROSA que usan las fichas: si algún día cambias el rosa del tema, también cambia en las instrucciones.

Decimales y configuración regional. %.1f usa el separador decimal de la configuración regional de la computadora. En Guatemala y México es el punto (42.9); en una computadora configurada para España saldría 42,9. Si un texto debe tener siempre el mismo formato (un archivo que leerá otro programa, por ejemplo), indica la región: String.format(Locale.ROOT, "%.1f", porcentaje), con import java.util.Locale;. Con %d y %X sin separador de miles, como en hex, no hay diferencia.

Dos variantes que verás: System.out.printf(…) formatea e imprime de una vez (ojo: no salta de línea solo; pon %n al final), y desde Java 15 "plantilla".formatted(valores) hace lo mismo que String.format escrito al revés.

Convertir entre texto y números

Lo que llega del teclado o de una caja de texto es siempre texto. "2" no es el número 2: "2" + 1 da "21". Para convertir:

public class Convertir {
    public static void main(String[] args) {
        String texto = "2";
        int fila = Integer.parseInt(texto);
        System.out.println("fila + 1 = " + (fila + 1));
        System.out.println("texto + 1 = " + (texto + 1));

        String deNumero = String.valueOf(450);
        System.out.println("450 como texto mide " + deNumero.length());

        char ficha = "o".toUpperCase().charAt(0);
        System.out.println("ficha = " + ficha + ", es char: " + (ficha == 'O'));
        String deChar = String.valueOf(ficha);
        System.out.println("como String: \"" + deChar + "\"");

        System.out.println(Integer.parseInt("dos"));
    }
}

Leer del teclado con Scanner

Hasta ahora tus programas solo hablaban. Para que escuchen, Java ofrece System.in, la entrada estándar: lo que se teclea en la terminal (la pareja de System.out). Pero System.in entrega bytes sueltos, muy incómodos. La clase Scanner (del paquete java.util) los envuelve y te los da ya convertidos: una línea, una palabra, un número.

import java.util.Scanner;

public class LeerJugador {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        System.out.print("¿Cómo te llamas? ");
        String nombre = teclado.nextLine().trim();
        if (nombre.isEmpty()) {
            nombre = "Jugador 1";
        }

        System.out.print("¿Con qué ficha juegas (X u O)? ");
        char ficha = teclado.next().toUpperCase().charAt(0);
        char rival = ficha == 'X' ? 'O' : 'X';

        System.out.print("¿Cuántas partidas quieres jugar? ");
        int partidas = teclado.nextInt();

        System.out.println(String.format("Hola, %s. Juegas con %c contra la %c, %d partida(s).",
                nombre, ficha, rival, partidas));
    }
}

Al ejecutarlo, el programa se detiene en cada pregunta hasta que escribes algo y pulsas Enter. Una sesión (lo que escribe el usuario va después de cada signo de interrogación):

¿Cómo te llamas?   Maria
¿Con qué ficha juegas (X u O)? o
¿Cuántas partidas quieres jugar? 3
Hola, Maria. Juegas con O contra la X, 3 partida(s).
  • import java.util.Scanner;: Scanner no está en java.lang, así que hay que importarlo.
  • new Scanner(System.in): crea un lector conectado al teclado. Se crea uno al principio y se reutiliza para todas las lecturas.
  • print en lugar de println para las preguntas: así el cursor se queda en la misma línea y la respuesta se escribe al lado.
  • nextLine(): lee la línea completa, con sus espacios, hasta el Enter (el Enter no se incluye). Ideal para nombres. Aquí, además, se le aplica trim() y la misma regla que TarjetaJugador: sin nombre, «Jugador 1».
  • next(): lee una sola palabra (un token: lo que hay entre espacios). toUpperCase().charAt(0) la convierte en ficha.
  • nextInt(): lee una palabra y la convierte a int. Si lo escrito no es un número, lanza InputMismatchException.
Cómo lee Scanner. Imagina que todo lo que tecleas cae en una cinta transportadora, letra por letra, incluido el Enter (que es un carácter más, '\n'). Scanner va tomando de la cinta: next() y nextInt() se saltan los espacios y Enters iniciales, toman una palabra y se detienen justo antes del siguiente espacio o Enter, dejándolo en la cinta. nextLine() toma todo hasta el próximo Enter y se lleva el Enter. Si la cinta está vacía, el programa espera a que escribas.

La trampa de nextInt() seguido de nextLine()

Esa forma de leer produce el error más famoso de Scanner:

import java.util.Scanner;

public class TrampaNextLine {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);
        System.out.print("Edad: ");
        int edad = teclado.nextInt();
        System.out.print("Nombre: ");
        String nombre = teclado.nextLine();
        System.out.println("edad=" + edad + ", nombre=[" + nombre + "]");
    }
}
Edad: 17
Nombre: edad=17, nombre=[]

¡Ni siquiera esperó al nombre! Al escribir 17 y Enter, la cinta tenía «17» y un Enter. nextInt() se llevó el 17 y dejó el Enter. Luego nextLine() encontró ese Enter y devolvió la línea vacía que había antes de él. Dos soluciones: añadir un teclado.nextLine(); suelto después del nextInt() para «tragar» el Enter sobrante, o leer siempre con nextLine() y convertir tú: int edad = Integer.parseInt(teclado.nextLine().trim());. En LeerJugador el problema no aparece porque el nextLine() va primero.

Validar lo que escribe el usuario: hasNextInt()

Nunca confíes en que el usuario escriba lo esperado. hasNextInt() mira la cinta sin consumir nada y responde si lo próximo es un número. Con eso se puede pedir una jugada hasta que sea válida, combinando el while y el continue del capítulo 14:

import java.util.Scanner;

public class LeerJugada {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);
        int fila = -1;
        int columna = -1;
        boolean valida = false;

        while (!valida) {
            System.out.print("Fila y columna (0 a 2): ");
            if (!teclado.hasNextInt()) {
                String basura = teclado.next();          // descartar lo que no es numero
                System.out.println("  \"" + basura + "\" no es un numero.");
                continue;
            }
            fila = teclado.nextInt();
            columna = teclado.nextInt();
            valida = fila >= 0 && fila <= 2 && columna >= 0 && columna <= 2;
            if (!valida) {
                System.out.println("  (" + fila + ", " + columna + ") esta fuera del tablero.");
            }
        }
        System.out.println("Jugada aceptada: fila " + fila + ", columna " + columna);
    }
}
Fila y columna (0 a 2): dos
  "dos" no es un numero.
Fila y columna (0 a 2): 1 5
  (1, 5) esta fuera del tablero.
Fila y columna (0 a 2): 1 2
Jugada aceptada: fila 1, columna 2

Si lo próximo no es un número, hay que sacarlo de la cinta con next() antes de volver a preguntar; si no, hasNextInt() seguiría viendo «dos» para siempre: un bucle infinito. Fíjate también en que 1 5 se escribe en una sola línea: nextInt() lee palabra por palabra, así que da igual escribir los dos números separados por un espacio o en dos líneas.

Hay una diferencia con LeerJugada: si lo próximo no es un número, PruebaConsola no lo descarta, sino que termina. Es una herramienta de prueba, y el caso que le importa es otro: cuando la entrada se cierra (no queda nada más que leer), hasNextInt() devuelve false y el programa sale limpio en lugar de lanzar una excepción. Tildes al teclear en la consola. En algunas consolas de Windows, las letras con tilde o la ñ que escribes pueden llegarle a Java mal (por ejemplo Mar?a), porque la consola y Java no siempre usan la misma codificación para la entrada. Si te pasa en estos ejercicios, escribe sin tildes; no es un fallo de tu código. La interfaz gráfica del Totito no tiene este problema: las cajas de texto de Swing reciben el texto ya convertido.
Un Scanner sobre System.in se crea una vez y no se cierra (cerrarlo cierra también System.in, y ya no podrías volver a leer el teclado en ese programa). NetBeans puede mostrar un aviso amarillo de «resource leak» en esa línea; para el teclado puedes ignorarlo. Cuando un Scanner lee un archivo, en cambio, sí hay que cerrarlo: lo verás con try-with-resources en el capítulo 26. Y si ejecutas desde NetBeans, lo que el programa lee se escribe en la ventana Output, haciendo clic en ella antes de teclear.

Resumen

  • Un String es un objeto de texto, con caracteres numerados desde 0, y es inmutable: sus métodos devuelven textos nuevos que hay que guardar (nombre = nombre.trim();).
  • Métodos clave: length(), isEmpty(), trim(), charAt(i), substring(a, b) (con b excluido), indexOf, contains, toUpperCase, replace. El Totito usa trim + isEmpty para el nombre y substring para recortar.
  • Los textos se comparan con equals (o equalsIgnoreCase), nunca con ==, que solo dice si son el mismo objeto. Literal delante: "Ana".equals(x).
  • + pega textos; dentro de bucles largos, usa StringBuilder con append y toString().
  • String.format rellena una plantilla: %s, %d, %c, %.1f, anchos y %02X, que en Tema.hex convierte (255, 59, 212) en #FF3BD4 con dos cifras por componente.
  • Integer.parseInt y String.valueOf convierten entre texto y números; texto.toUpperCase().charAt(0), entre texto y ficha.
  • Scanner lee el teclado: nextLine() (línea), next() (palabra), nextInt() (número), hasNextInt() (mirar sin consumir). Cuidado con el Enter que deja nextInt() antes de un nextLine().
Aplícalo fuera del Totito
  • Formularios de cualquier aplicación: trim() + isEmpty() antes de aceptar un nombre, equalsIgnoreCase para comparar correos o usuarios, contains("@") como validación mínima de un correo, y substring para limitar la longitud de un campo como hace CampoTexto.
  • Recibos e informes alineados: String.format("%-20s %8.2f", producto, precio) produce columnas perfectas para un ticket de una tienda; con StringBuilder armas el recibo completo antes de imprimirlo o guardarlo.
  • Colores para la web o para un editor: el mismo "#%02X%02X%02X" de Tema.hex sirve para exportar una paleta a CSS o mostrar el código de un color elegido en un selector.
  • Programas de consola interactivos: un menú de un gestor de tareas («1. Agregar, 2. Listar, 3. Salir») leído con Scanner y validado con hasNextInt(), o un juego de adivinar números que repite la pregunta hasta acertar.
Ejercicios
  1. En jshell, con String s = "Totito Neon";, predice y comprueba: s.length(), s.charAt(7), s.substring(0, 6), s.substring(7), s.indexOf("Neon"), s.toLowerCase(), s.replace('o', '0').
  2. Escribe un método static String iniciales(String nombreCompleto) que reciba «Ana Lucía Pérez» y devuelva «ALP». Pista: recorre el texto con charAt y toma la primera letra y cada letra que siga a un espacio; usa un StringBuilder.
  3. Escribe tu propio hex(int r, int g, int b) y pruébalo con los colores del Totito: AZUL (47, 132, 255), MORADO (160, 92, 255) y LAVANDA (200, 188, 246). Comprueba que obtienes #2F84FF, #A05CFF y #C8BCF6.
  4. Con Scanner, pide al usuario su nombre y su ficha; repite la pregunta de la ficha mientras no escriba X u O (en mayúscula o minúscula). Luego imprime un saludo con String.format.
  5. Reto: un marcador en consola. Pide los nombres de dos jugadores y luego, en un bucle, pregunta «¿Quién ganó? (1, 2, E para empate, S para salir)». Lleva la cuenta con un int[] victorias y un contador de empates, y al salir imprime una tabla alineada con %-12s %3d.
