La receta para cualquier proyecto nuevo

Antes de los proyectos, la receta que vas a seguir en todos. Es el mismo camino que recorrió el libro, resumido:

  1. Descríbelo en una frase y dibuja sus pantallas. En papel sirve. «Un Buscaminas de 9×9 con 10 minas, cronómetro y banderas». Haz un inventario de las piezas que se repiten, como en el capítulo 34.
  2. Busca los sustantivos y los verbos. Los sustantivos importantes de la frase suelen ser clases (casilla, tablero, mina, partida) y los verbos, métodos (abrir, marcar, ganar). Es un truco viejo y funciona.
  3. Escribe primero la lógica, sin Swing, y pruébala en la consola con un programa como PruebaConsola. Si las reglas no funcionan en texto, tampoco funcionarán con colores.
  4. Crea el proyecto y su repositorio (capítulos 5 y 8): pom.xml, .gitignore, README.md, primer commit, gh repo create.
  5. Copia el kit neón del Totito (la sección siguiente explica cuál es).
  6. Construye las pantallas de una en una, mirándolas con una VistaPrevia (capítulo 56).
  7. Únelas con tu propio PanelPrincipal y tu propia interfaz Navegacion.
  8. Empaqueta y publica con los comandos de los capítulos 63 a 67, cambiando el nombre, el icono y el UUID.
Un commit por paso de la receta Cada paso de la lista termina en algo que compila y que puedes enseñar. Ese es el momento del commit. Si algún día un paso se tuerce, vuelves al commit anterior y no pierdes nada (capítulo 9).

Crear un proyecto nuevo con el kit

Los cinco proyectos empiezan igual. Este es el ejemplo con Conecta 4; para los demás cambia solo el nombre de la carpeta. Abre PowerShell (no hace falta estar en ninguna carpeta concreta, porque todas las rutas son completas):

$origen = "$HOME\Proyectos\Totito"
$destino = "$HOME\Proyectos\Conecta4"
New-Item -ItemType Directory -Force "$destino\src" | Out-Null
Copy-Item "$origen\pom.xml", "$origen\.gitignore" $destino
$kit = "Tema", "Dibujo", "Iconos", "BotonNeon", "Tarjeta", "Rotulo", "CampoTexto"
foreach ($clase in $kit) { Copy-Item "$origen\src\$clase.java" "$destino\src\" }
Get-ChildItem "$destino\src"

Línea por línea:

  • $origen = … y $destino = … guardan las dos rutas en variables de PowerShell (capítulo 3) para no repetirlas. Las comillas dobles dejan que $HOME se reemplace por tu carpeta de usuario.
  • New-Item -ItemType Directory -Force "$destino\src" crea la carpeta del proyecto y, dentro, src, de una vez. -Force evita el error si ya existía. | Out-Null descarta el mensaje que imprime.
  • Copy-Item "a", "b" $destino copia varios archivos a la vez: la coma separa los elementos de una lista.
  • $kit = "Tema", "Dibujo", … es otra lista, ahora con los nombres de las clases.
  • foreach ($clase in $kit) { … } es el «for-each» de PowerShell, igual que el de Java del capítulo 14: repite la copia una vez por cada nombre.
  • Get-ChildItem lista lo que quedó en src, para comprobarlo.

Después abre el pom.xml nuevo en NetBeans o en el Bloc de notas y cambia tres cosas: el nombre del proyecto y, en los dos lugares donde aparece, la clase principal:

<artifactId>Conecta4</artifactId>
...
<exec.mainClass>Conecta4App</exec.mainClass>
...
<mainClass>Conecta4App</mainClass>

El artifactId es el nombre con el que NetBeans muestra el proyecto y el nombre del .jar (target\Conecta4-1.0-SNAPSHOT.jar). Si lo dejas como Totito, tendrás dos proyectos con el mismo nombre en NetBeans y el .jar se llamará igual que el del juego: una confusión segura. Escribe también un README.md nuevo (capítulo 5) y, al final, abre la carpeta en NetBeans con File → Open Project.

Git Cada proyecto es un repositorio propio, con su historia. Desde la carpeta del proyecto nuevo: 
cd $HOME\Proyectos\Conecta4
git init -b main
git add .
git commit -m "Estructura inicial y kit neon copiado del Totito"
gh repo create conecta4 --public --source=. --remote=origin --push
git init -b main crea el repositorio con la rama principal ya llamada main. El último comando crea el repositorio en GitHub, lo conecta como origin y sube el commit, todo de una vez (capítulo 8).
Copiar tiene un precio Al copiar el kit tienes dos BotonNeon.java: el del Totito y el de Conecta 4. Si mañana corriges un error en uno, el otro sigue con el error. Para dos o tres proyectos es aceptable. Cuando sean más, lo profesional es convertir el kit en una librería: un .jar propio que todos los proyectos usan como dependencia en su pom.xml. Para eso hacen falta los paquetes del capítulo 69.

Proyecto 1: Conecta 4

Qué es

Dos jugadores sueltan fichas por turnos en un tablero vertical de 6 filas y 7 columnas. La ficha cae hasta el hueco libre más bajo de la columna. Gana quien forme cuatro en línea: horizontal, vertical o diagonal. Es el pariente más cercano del Totito: casi todo lo que hiciste sirve, y lo nuevo cabe en dos ideas, la gravedad y la búsqueda de cuatro en un tablero grande.

El reto principal: la gravedad y el «cuatro en línea»

La gravedad parece física, pero en el código es solo el orden de un ciclo. En el Totito, marcarCasilla(fila, columna, ficha) recibía la fila. Aquí el jugador solo elige la columna y la fila se calcula: se recorre la columna de abajo hacia arriba (la fila 5 es la de abajo, la 0 la de arriba) y la ficha se queda en el primer hueco vacío. Si no hay ninguno, la columna está llena.

Para el cuatro en línea hay una idea mejor que revisar todo el tablero: la única ficha que puede haber formado una línea nueva es la que acaba de caer. Así que basta con mirar las cuatro direcciones que pasan por ella. Cada dirección se escribe como un par {df, dc}: cuánto cambia la fila y cuánto la columna en cada paso.

Dirección{df, dc}Se recorre hacia…
Horizontal —{0, 1}derecha y, con {0, −1}, izquierda
Vertical |{1, 0}abajo y arriba
Diagonal \{1, 1}abajo-derecha y arriba-izquierda
Diagonal /{1, −1}abajo-izquierda y arriba-derecha

Para cada dirección se cuentan las fichas iguales hacia un lado, luego hacia el otro (con los signos cambiados), y se suma 1 por la ficha recién puesta. Si da 4 o más, hay ganador. Este truco de «vectores de dirección» es el mismo que usan los programas de ajedrez para mover la torre o el alfil, y el que usarás en cualquier juego de cuadrícula.

Código de arranque

Primero la lógica, como en el capítulo 29. Crea src\TableroConecta.java:

import java.util.Arrays;

/**
 * Tablero de Conecta 4: 6 filas y 7 columnas. Las fichas "caen" hasta la
 * casilla libre mas baja de la columna elegida. Igual que Tablero en el
 * Totito, solo guarda el estado y sabe las reglas: no conoce la interfaz.
 */
public class TableroConecta {

    public static final int FILAS = 6;
    public static final int COLUMNAS = 7;
    public static final char VACIA = ' ';

    private final char[][] casillas = new char[FILAS][COLUMNAS];

    public TableroConecta() {
        reiniciar();
    }

    public void reiniciar() {
        for (char[] fila : casillas) {
            Arrays.fill(fila, VACIA);
        }
    }

    /**
     * La gravedad: recorre la columna DE ABAJO HACIA ARRIBA y deja la ficha
     * en la primera casilla vacia. Devuelve la fila donde cayo, o -1 si la
     * columna no existe o ya esta llena.
     */
    public int soltarFicha(int columna, char ficha) {
        if (columna < 0 || columna >= COLUMNAS) {
            return -1;
        }
        for (int fila = FILAS - 1; fila >= 0; fila--) {
            if (casillas[fila][columna] == VACIA) {
                casillas[fila][columna] = ficha;
                return fila;
            }
        }
        return -1;
    }

    public boolean columnaLlena(int columna) {
        return casillas[0][columna] != VACIA;
    }

    public boolean tableroLleno() {
        for (int columna = 0; columna < COLUMNAS; columna++) {
            if (!columnaLlena(columna)) {
                return false;
            }
        }
        return true;
    }

    public char obtenerCasilla(int fila, int columna) {
        return casillas[fila][columna];
    }

    /**
     * true si la ficha que acaba de caer en (fila, columna) forma cuatro en
     * linea. Solo se revisan las 4 direcciones que pasan por esa casilla.
     */
    public boolean hayCuatro(int fila, int columna) {
        char ficha = casillas[fila][columna];
        int[][] direcciones = {{0, 1}, {1, 0}, {1, 1}, {1, -1}};   // -  |  \  /
        for (int[] d : direcciones) {
            int seguidas = 1
                    + contar(fila, columna, d[0], d[1], ficha)
                    + contar(fila, columna, -d[0], -d[1], ficha);
            if (seguidas >= 4) {
                return true;
            }
        }
        return false;
    }

    /** Cuenta fichas iguales a partir de (fila, columna) avanzando (df, dc), sin contar la de partida. */
    private int contar(int fila, int columna, int df, int dc, char ficha) {
        int total = 0;
        int f = fila + df;
        int c = columna + dc;
        while (f >= 0 && f < FILAS && c >= 0 && c < COLUMNAS && casillas[f][c] == ficha) {
            total++;
            f += df;
            c += dc;
        }
        return total;
    }

    /** El tablero en texto, para probar en la consola. */
    public String comoTexto() {
        StringBuilder sb = new StringBuilder();
        for (char[] fila : casillas) {
            sb.append('|');
            for (char ficha : fila) {
                sb.append(ficha == VACIA ? '.' : ficha).append('|');
            }
            sb.append('\n');
        }
        sb.append(" 0 1 2 3 4 5 6\n");
        return sb.toString();
    }
}

Lo nuevo respecto a Tablero:

  • FILAS y COLUMNAS son constantes (capítulo 20). En Tablero el 3 estaba escrito en cada ciclo; aquí, si quisieras un tablero de 7×8, cambias dos números y nada más. Es la lección de los «números mágicos» del capítulo 27.
  • Arrays.fill(fila, VACIA) llena un arreglo entero con un valor. Hace lo mismo que el for interno de Tablero.reiniciar(), en una línea. PanelTablero ya lo usaba.
  • En soltarFicha, el ciclo for (int fila = FILAS - 1; fila >= 0; fila--) cuenta hacia atrás: empieza en 5 y baja hasta 0. Esa línea es la gravedad.
  • Devolver la fila (o -1) en lugar de true/false le da a quien llama dos datos en uno: si se pudo, y dónde cayó. hayCuatro necesita esa fila.
  • En contar, el while avanza mientras siga dentro del tablero y la ficha sea igual. El orden de las condiciones importa: Java evalúa && de izquierda a derecha y se detiene en la primera falsa (capítulo 13), así que nunca llega a leer casillas[f][c] fuera del arreglo.
  • comoTexto() usa un StringBuilder, que es la forma eficiente de armar un texto pedazo a pedazo con append.

Y su prueba en consola, src\PruebaConecta.java, que hace el papel de PruebaConsola:

/** Prueba de TableroConecta en la consola, como PruebaConsola en el Totito. */
public class PruebaConecta {

    public static void main(String[] args) {
        TableroConecta tablero = new TableroConecta();
        int[] columnas = {3, 3, 4, 4, 5, 2, 6};   // X y O se turnan; X empieza
        char ficha = 'X';
        for (int columna : columnas) {
            int fila = tablero.soltarFicha(columna, ficha);
            System.out.println(ficha + " cae en la columna " + columna + ", fila " + fila);
            if (tablero.hayCuatro(fila, columna)) {
                System.out.println("¡Cuatro en línea de " + ficha + "!");
                break;
            }
            ficha = ficha == 'X' ? 'O' : 'X';
        }
        System.out.print(tablero.comoTexto());
    }
}

La interfaz: lo que hereda de PanelTablero

PanelConecta se escribe copiando PanelTablero y cambiando tres cosas:

  • El tamaño: 7 columnas por 6 filas en lugar de 3×3. Los métodos centroX(columna) y centroY(fila) se quedan igual, solo cambian las cuentas.
  • El clic: ya no interesa la fila. La columna se calcula con la misma fórmula de actualizarCasillaEncima: (int) Math.floor((x - MARGEN - RELLENO) / tam). La interfaz del oyente pasa a ser void columnaPulsada(int columna).
  • El resaltado: en lugar de iluminar una casilla, se ilumina toda la columna bajo el ratón, y la ficha fantasma se dibuja arriba del tablero, donde «se sostiene» antes de soltarla.

Las fichas se dibujan como discos: un Ellipse2D relleno con Tema.conAlfa(color, 200) y su borde con Dibujo.trazoNeon. Para la animación de la caída sirve el mismo javax.swing.Timer de PantallaJuego.esperar (capítulo 59), pero repetido: cada 15 milisegundos aumenta la y de la ficha que cae y llama a repaint(); cuando llega a su fila, se detiene el temporizador y recién entonces se avisa a la partida.

La IA: Minimax ya no alcanza

En el Totito, IA_Minimax recorría todas las partidas posibles porque son pocas. En Conecta 4 hay unos 4,5 billones de posiciones posibles: recorrerlas todas tardaría años. La solución clásica tiene tres partes:

  1. Profundidad limitada. El método minimax recibe ya una profundidad. Se agrega un caso base más: si la profundidad llega, por ejemplo, a 6, se deja de simular.
  2. Una función de evaluación. Al cortar no hay ganador, así que hay que estimar qué tan buena es la posición: por ejemplo, +5 por cada grupo de cuatro casillas con tres fichas propias y una vacía, −5 por cada uno del rival y +3 por cada ficha en la columna central (la más valiosa).
  3. Poda alfa-beta. Un refinamiento de Minimax que deja de explorar ramas que ya se sabe que no se van a elegir. El resultado es idéntico y mucho más rápido.

Con profundidad 6 y probando primero las columnas del centro, la IA responde en una fracción de segundo y es difícil de ganar. Bajar la profundidad es la forma natural de hacer los niveles de dificultad que el README del Totito dejaba como idea pendiente.

Proyecto 2: Buscaminas

Qué es

Un tablero de casillas tapadas; algunas esconden minas. Al abrir una casilla sin mina aparece un número: cuántas minas hay en sus 8 vecinas. Con clic derecho se pone una bandera donde crees que hay mina. Ganas al abrir todas las casillas sin mina; pierdes al abrir una mina. Los niveles clásicos son Principiante (9×9, 10 minas), Intermedio (16×16, 40) y Experto (16×30, 99).

¿Cuándo un dato merece su propia clase? En el Totito cada casilla era un char: un solo dato. En el Buscaminas cada casilla tiene cuatro datos que van juntos. El reto principal: la apertura recursiva

Cuando abres una casilla con 0 minas alrededor, el juego abre sola cada una de sus vecinas; si alguna de esas también tiene 0, abre las suyas, y así hasta toparse con números. Es lo que hace que un solo clic destape media pantalla. Escribirlo con ciclos es enredado; con recursión (capítulo 16) es casi igual a como se dice en español:

Abrir una casilla es: si está fuera del tablero, o ya abierta, o tiene bandera, no hacer nada. Si no, abrirla. Si tenía mina, perdiste. Si tiene 0 vecinas con mina, abrir cada una de sus 8 vecinas.

La frase en cursiva aparece dentro de su propia definición: eso es la recursión. Igual que en IA_Minimax.minimax, la función tiene casos base que la detienen (fuera, ya abierta, bandera, mina) y un caso recursivo que se llama a sí misma con un problema «más pequeño» (cada llamada abre una casilla más, y las casillas no son infinitas). El caso base «ya abierta» es el que evita el ciclo eterno: sin él, la casilla A abriría a su vecina B, B volvería a abrir a A, A a B…, hasta que la pila de llamadas se llena y Java lanza StackOverflowError.

Otra decisión: las minas se reparten después del primer clic y lejos de él, para que nunca se pierda en la primera jugada (lo hacen casi todas las versiones del juego). Y el reparto usa un Random con semilla: el mismo número de semilla produce siempre el mismo tablero, lo que permite repetir una prueba exactamente igual. En el juego real se crea con System.nanoTime() como semilla para que cada partida sea distinta.

src\TableroMinas.java, con la recursión en abrirDesde:

import java.util.Random;

/**
 * Tablero del Buscaminas: reparte las minas, cuenta las vecinas y abre
 * casillas. Las minas se ponen DESPUES del primer clic, lejos de el, para
 * que nunca se pierda en la primera jugada.
 */
public class TableroMinas {

    private final Casilla[][] casillas;
    private final int filas;
    private final int columnas;
    private final int totalMinas;
    private final Random azar;
    private boolean minasPuestas;
    private int abiertas;

    /** @param semilla el mismo numero da siempre el mismo tablero (util para probar). */
    public TableroMinas(int filas, int columnas, int totalMinas, long semilla) {
        this.filas = filas;
        this.columnas = columnas;
        this.totalMinas = totalMinas;
        this.azar = new Random(semilla);
        casillas = new Casilla[filas][columnas];
        for (int f = 0; f < filas; f++) {
            for (int c = 0; c < columnas; c++) {
                casillas[f][c] = new Casilla();
            }
        }
    }

    /** Abre la casilla. Devuelve false si habia una mina (partida perdida). */
    public boolean abrir(int fila, int columna) {
        if (!minasPuestas) {
            ponerMinas(fila, columna);
        }
        return abrirDesde(fila, columna);
    }

    /**
     * El corazon del juego, RECURSIVO: si la casilla no tiene minas
     * alrededor, se abren tambien sus 8 vecinas, y las vecinas de esas...
     */
    private boolean abrirDesde(int fila, int columna) {
        if (!dentro(fila, columna)) {
            return true;                         // caso base 1: fuera del tablero
        }
        Casilla casilla = casillas[fila][columna];
        if (casilla.estaAbierta() || casilla.tieneBandera()) {
            return true;                         // caso base 2: ya abierta o marcada
        }
        casilla.abrir();
        abiertas++;
        if (casilla.tieneMina()) {
            return false;                        // caso base 3: ¡boom!
        }
        if (casilla.getMinasVecinas() == 0) {    // caso recursivo
            for (int df = -1; df <= 1; df++) {
                for (int dc = -1; dc <= 1; dc++) {
                    if (df != 0 || dc != 0) {
                        abrirDesde(fila + df, columna + dc);
                    }
                }
            }
        }
        return true;
    }

    private void ponerMinas(int filaSegura, int columnaSegura) {
        int puestas = 0;
        while (puestas < totalMinas) {
            int f = azar.nextInt(filas);
            int c = azar.nextInt(columnas);
            boolean cercaDelClic = Math.abs(f - filaSegura) <= 1 && Math.abs(c - columnaSegura) <= 1;
            if (!casillas[f][c].tieneMina() && !cercaDelClic) {
                casillas[f][c].ponerMina();
                puestas++;
            }
        }
        for (int f = 0; f < filas; f++) {
            for (int c = 0; c < columnas; c++) {
                casillas[f][c].setMinasVecinas(contarVecinas(f, c));
            }
        }
        minasPuestas = true;
    }

    private int contarVecinas(int fila, int columna) {
        int total = 0;
        for (int df = -1; df <= 1; df++) {
            for (int dc = -1; dc <= 1; dc++) {
                int f = fila + df;
                int c = columna + dc;
                if ((df != 0 || dc != 0) && dentro(f, c) && casillas[f][c].tieneMina()) {
                    total++;
                }
            }
        }
        return total;
    }

    private boolean dentro(int fila, int columna) {
        return fila >= 0 && fila < filas && columna >= 0 && columna < columnas;
    }

    public void alternarBandera(int fila, int columna) {
        casillas[fila][columna].alternarBandera();
    }

    /** Se gana cuando todo lo que no es mina esta abierto. */
    public boolean ganado() {
        return abiertas == filas * columnas - totalMinas;
    }

    /** # cerrada, F bandera, * mina, . sin vecinas, 1-8 minas alrededor. */
    public String comoTexto() {
        StringBuilder sb = new StringBuilder();
        for (Casilla[] fila : casillas) {
            for (Casilla casilla : fila) {
                char simbolo;
                if (!casilla.estaAbierta()) {
                    simbolo = casilla.tieneBandera() ? 'F' : '#';
                } else if (casilla.tieneMina()) {
                    simbolo = '*';
                } else if (casilla.getMinasVecinas() == 0) {
                    simbolo = '.';
                } else {
                    simbolo = (char) ('0' + casilla.getMinasVecinas());
                }
                sb.append(simbolo).append(' ');
            }
            sb.append('\n');
        }
        return sb.toString();
    }
}

Algunas líneas que merecen explicación:

  • casillas = new Casilla[filas][columnas]; crea la matriz, pero vacía: cada posición vale null. Por eso el doble for siguiente hace new Casilla() en cada una. Olvidarlo produce un NullPointerException en el primer clic (capítulo 18).
  • abrir es public y abrirDesde es private: el que usa la clase solo pide «abre aquí»; la recursión es un detalle interno.
  • (df != 0 || dc != 0) recorre las 9 posiciones del cuadrado de 3×3 y se salta la del centro, que es la propia casilla.
  • (char) ('0' + casilla.getMinasVecinas()) convierte el número 3 en el carácter '3': los dígitos están seguidos en la tabla de caracteres, así que '0' + 3 es '3' (capítulo 12, casting).

Recursión y tableros gigantes Cada llamada recursiva ocupa un lugar en la pila (capítulo 16). La solución es cambiar la pila de llamadas por una lista de espera propia (una cola): se mete la primera casilla y, mientras queden pendientes, se saca una, se abre y, si tiene 0, se meten sus vecinas.     private boolean abrirConCola(int fila, int columna) {
        if (casillas[fila][columna].tieneMina()) {
            casillas[fila][columna].abrir();
            return false;
        }
        ArrayDeque<int[]> pendientes = new ArrayDeque<>();
        pendientes.add(new int[]{fila, columna});
        while (!pendientes.isEmpty()) {
            int[] p = pendientes.poll();
            if (!dentro(p[0], p[1])) {
                continue;
            }
            Casilla casilla = casillas[p[0]][p[1]];
            if (casilla.estaAbierta() || casilla.tieneBandera()) {
                continue;
            }
            casilla.abrir();
            abiertas++;
            if (casilla.getMinasVecinas() == 0) {
                for (int df = -1; df <= 1; df++) {
                    for (int dc = -1; dc <= 1; dc++) {
                        if (df != 0 || dc != 0) {
                            pendientes.add(new int[]{p[0] + df, p[1] + dc});
                        }
                    }
                }
            }
        }
        return true;
    }

El reto principal: guardar los datos en un archivo

Todo lo que vive en variables desaparece al cerrar el programa: la memoria RAM se libera. Para que algo dure hay que escribirlo en el disco, en un archivo. Hay que decidir cuatro cosas:

  1. El formato: cómo se escribe una tarea como texto. Aquí, una línea por tarea con tres campos separados por punto y coma: hecha;PRIORIDAD;titulo. Es legible, se puede abrir con el Bloc de notas y es fácil de leer de vuelta.
  2. La codificación: UTF-8, siempre y escrita explícitamente, para que «capítulo» no se convierta en «capÃ­tulo» (es el mismo problema de las tildes del capítulo 5).
  3. El lugar: no junto al .exe —en C:\Program Files un programa normal no tiene permiso de escritura (capítulo 66)—, sino en la carpeta del usuario: C:\Users\<tu-usuario>\TareasNeon\tareas.txt. Java la obtiene con System.getProperty("user.home").
  4. Cuándo guardar: lo más seguro es guardar cada vez que algo cambia (agregar, marcar, borrar). Si solo guardas al cerrar, un corte de luz te hace perder todo lo de la sesión.

El detalle fino está en el formato: ¿y si el título tiene un punto y coma, como «Estudiar el capítulo 68; hacer ejercicios»? Si partieras la línea en todos los ; saldrían cuatro trozos y el título quedaría cortado. Por eso el título va al final y se usa split(";", 3): el 3 significa «como mucho tres trozos», así que todo lo que venga después del segundo punto y coma, incluidos otros ;, queda en el tercero.

src\Tarea.java:

/** Una tarea pendiente: lo que hay que hacer, su prioridad y si ya se hizo. */
public class Tarea {

    public enum Prioridad { ALTA, MEDIA, BAJA }

    private final String titulo;
    private final Prioridad prioridad;
    private boolean hecha;

    public Tarea(String titulo, Prioridad prioridad) {
        if (titulo == null || titulo.isBlank()) {
            throw new IllegalArgumentException("La tarea necesita un titulo");
        }
        this.titulo = titulo.strip();
        this.prioridad = prioridad;
    }

    public String getTitulo() {
        return titulo;
    }

    public Prioridad getPrioridad() {
        return prioridad;
    }

    public boolean estaHecha() {
        return hecha;
    }

    public void setHecha(boolean hecha) {
        this.hecha = hecha;
    }

    /** Una linea del archivo:  hecha;PRIORIDAD;titulo  (el titulo va al final). */
    public String aLinea() {
        return hecha + ";" + prioridad + ";" + titulo;
    }

    /** Lo contrario de aLinea(): reconstruye la tarea a partir de una linea. */
    public static Tarea desdeLinea(String linea) {
        String[] partes = linea.split(";", 3);   // 3 = como mucho 3 trozos
        Tarea tarea = new Tarea(partes[2], Prioridad.valueOf(partes[1]));
        tarea.setHecha(Boolean.parseBoolean(partes[0]));
        return tarea;
    }
}
  • El constructor rechaza un título vacío con IllegalArgumentException, igual que Partida rechaza dos jugadores con la misma ficha (capítulo 26). Así nunca existe una tarea inválida. isBlank() es true si el texto está vacío o solo tiene espacios; strip() quita los espacios de los extremos.
  • aLinea() y desdeLinea() son una pareja: una convierte el objeto en texto y la otra hace el camino inverso. A esto se le llama serializar y deserializar. desdeLinea es static porque se llama cuando todavía no hay ninguna tarea: es un método de fábrica, como BotonNeon.menu(...).
  • Prioridad.valueOf("ALTA") convierte el texto en el valor del enum, y Boolean.parseBoolean("true") el texto en boolean. Concatenar un enum ("" + prioridad) escribe su nombre: ALTA.

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

/**
 * La lista de tareas y su archivo. Hace con las tareas lo que Partida hace
 * con el Tablero: la interfaz le pide cosas y despues le pregunta como quedo.
 */
public class ListaTareas {

    private final List<Tarea> tareas = new ArrayList<>();
    private final Path archivo;

    public ListaTareas(Path archivo) {
        this.archivo = archivo;
    }

    /** Donde se guardan en Windows:  C:\Users\<tu-usuario>\TareasNeon\tareas.txt */
    public static Path archivoPorDefecto() {
        return Path.of(System.getProperty("user.home"), "TareasNeon", "tareas.txt");
    }

    public void agregar(Tarea tarea) {
        tareas.add(tarea);
    }

    public void eliminar(int indice) {
        tareas.remove(indice);
    }

    /** Vista de solo lectura: quien la pida no puede borrar a escondidas. */
    public List<Tarea> getTareas() {
        return Collections.unmodifiableList(tareas);
    }

    public int pendientes() {
        int total = 0;
        for (Tarea tarea : tareas) {
            if (!tarea.estaHecha()) {
                total++;
            }
        }
        return total;
    }

    /** Escribe todas las tareas, una por linea, en UTF-8 (para que las tildes no se rompan). */
    public void guardar() throws IOException {
        Files.createDirectories(archivo.getParent());
        List<String> lineas = new ArrayList<>();
        for (Tarea tarea : tareas) {
            lineas.add(tarea.aLinea());
        }
        Files.write(archivo, lineas, StandardCharsets.UTF_8);
    }

    /** Lee el archivo si existe. La primera vez que se usa el programa no existe: lista vacia. */
    public void cargar() throws IOException {
        tareas.clear();
        if (!Files.exists(archivo)) {
            return;
        }
        for (String linea : Files.readAllLines(archivo, StandardCharsets.UTF_8)) {
            if (!linea.isBlank()) {
                tareas.add(Tarea.desdeLinea(linea));
            }
        }
    }
}
  • List<Tarea> y ArrayList: una lista que crece sola, a diferencia del arreglo de tamaño fijo del capítulo 15. Lo que va entre < y > dice qué guarda.
  • Path representa una ruta de archivo. Path.of(a, b, c) la arma con el separador correcto del sistema (\ en Windows), sin que tengas que escribirlo.
  • Files.createDirectories crea la carpeta TareasNeon si no existe (y no se queja si ya existe). Files.write escribe todas las líneas de una vez y Files.readAllLines las lee.
  • throws IOException: escribir en disco puede fallar (disco lleno, sin permiso, archivo abierto por otro programa). Java te obliga a decidir qué hacer con ese posible error: o lo atrapas con try/catch o avisas con throws que lo resuelva quien llame (capítulo 26). Aquí lo resuelve la pantalla, mostrando un JOptionPane.showMessageDialog con el problema.
  • Collections.unmodifiableList entrega la lista «de solo lectura»: la pantalla puede recorrerla, pero si intentara borrar algo saltaría un error. Las tareas solo se cambian a través de los métodos de ListaTareas: eso es encapsulamiento (capítulo 19).

El reto principal: el estado de una calculadora y los decimales

Una calculadora parece simple hasta que la programas. Cuando pulsas 12 × 3 − 6 =, tiene que recordar en cada momento tres cosas: el número acumulado, la operación pendiente y si la próxima cifra empieza un número nuevo o continúa el que se ve. Eso es una pequeña máquina de estados, como el Estado de Partida. La traza de 12x3-6=:

El segundo reto son los decimales. Prueba esto en jshell (capítulo 11): 0.1 + 0.2. La respuesta es 0.30000000000000004. No es un error de Java: double guarda los números en binario, y 0,1 en binario tiene infinitas cifras (como 1/3 en decimal), así que se guarda redondeado. Para un juego da igual; para una calculadora o para dinero, no. La solución es java.math.BigDecimal, que guarda los números en decimal exacto. A cambio, no se usa con + y * sino con métodos: a.add(b), a.multiply(b). En la división hay que decir cuántas cifras quieres, porque 1/3 no termina nunca: MathContext.DECIMAL64 pide 16 cifras significativas.

Código de arranque

La lógica, src\Calculadora.java:

import java.math.BigDecimal;
import java.math.MathContext;

/**
 * La logica de la calculadora, sin nada de Swing (como Partida en el
 * Totito). Recibe "teclas" y dice que hay que mostrar en la pantalla.
 *
 * Usa BigDecimal en lugar de double para que 0.1 + 0.2 de 0.3 exacto.
 */
public class Calculadora {

    private String pantalla = "0";
    private BigDecimal acumulado = BigDecimal.ZERO;
    private char operacionPendiente = ' ';
    /** true justo despues de pulsar una operacion o "=": el proximo digito empieza un numero nuevo. */
    private boolean numeroNuevo = true;

    public String getPantalla() {
        return pantalla;
    }

    public void digito(char d) {
        if (numeroNuevo || pantalla.equals("0") || pantalla.equals("Error")) {
            pantalla = String.valueOf(d);
            numeroNuevo = false;
        } else if (pantalla.length() < 16) {
            pantalla = pantalla + d;
        }
    }

    public void punto() {
        if (numeroNuevo || pantalla.equals("Error")) {
            pantalla = "0.";
            numeroNuevo = false;
        } else if (!pantalla.contains(".")) {
            pantalla = pantalla + ".";
        }
    }

    /** + - x / : resuelve lo pendiente y recuerda la nueva operacion. */
    public void operacion(char op) {
        if (pantalla.equals("Error")) {
            return;
        }
        if (!numeroNuevo) {
            resolver();
        }
        operacionPendiente = op;
        numeroNuevo = true;
    }

    public void igual() {
        if (!pantalla.equals("Error")) {
            resolver();
        }
        operacionPendiente = ' ';
        numeroNuevo = true;
    }

    public void limpiar() {
        pantalla = "0";
        acumulado = BigDecimal.ZERO;
        operacionPendiente = ' ';
        numeroNuevo = true;
    }

    private void resolver() {
        BigDecimal actual = new BigDecimal(pantalla);
        switch (operacionPendiente) {
            case '+' -> acumulado = acumulado.add(actual);
            case '-' -> acumulado = acumulado.subtract(actual);
            case 'x' -> acumulado = acumulado.multiply(actual);
            case '/' -> {
                if (actual.signum() == 0) {
                    pantalla = "Error";      // dividir entre cero
                    acumulado = BigDecimal.ZERO;
                    return;
                }
                acumulado = acumulado.divide(actual, MathContext.DECIMAL64);
            }
            default -> acumulado = actual;   // primer numero: aun no hay operacion
        }
        pantalla = acumulado.stripTrailingZeros().toPlainString();
    }
}
  • Los cuatro campos private son el estado completo de la calculadora: con ellos se puede reconstruir qué está pasando en cualquier momento.
  • resolver() usa el switch con flechas del capítulo 13. El caso default cubre la primera vez: si aún no hay operación, el número de la pantalla simplemente pasa a ser el acumulado.
  • signum() devuelve −1, 0 o 1 según el signo; == 0 detecta la división entre cero, que con BigDecimal lanzaría una excepción.
  • stripTrailingZeros().toPlainString() quita los ceros sobrantes y escribe el número sin notación científica: 2.50 se ve como 2.5.

El reto principal: muchos datos en pantalla, y que sean correctos

Hasta ahora siempre había pocos datos a la vista: 9 casillas, un número. Un inventario puede tener 2000 productos. Dibujarlos a mano en un paintComponent sería absurdo; para eso Swing tiene JTable, una tabla con filas, columnas, selección, desplazamiento y orden. Funciona con la misma separación que el Totito:

  • El modelo (TableModel) dice cuántas filas hay, cuántas columnas, cómo se llama cada una y qué valor va en cada celda. No dibuja nada.
  • La vista (JTable) le pregunta al modelo y dibuja. Cuando los datos cambian, el modelo avisa con fireTableDataChanged() y la tabla se vuelve a dibujar.

Es exactamente el par Partida / PanelTablero, pero ya hecho por Swing: tú solo escribes el modelo.

La segunda mitad del reto es que los datos sean correctos. Dos reglas: el dinero va en BigDecimal (por lo visto en la calculadora: con double, sumar mil ventas de Q0.10 no da exactamente Q100.00), y una venta que no alcanza debe fallar sin cambiar nada. Para eso se crea una excepción propia, SinExistenciasException. Como hereda de Exception (y no de RuntimeException), es una excepción comprobada: Java obliga a quien llame a vender a escribir el try/catch. Es una forma de que el compilador te recuerde que ese caso existe.

import java.math.BigDecimal;

/** Un producto de la tienda. El precio es BigDecimal: con dinero no se usa double. */
public class Producto {

    private final String codigo;
    private final String nombre;
    private BigDecimal precio;
    private int existencias;
    private final int minimo;

    public Producto(String codigo, String nombre, BigDecimal precio, int existencias, int minimo) {
        if (precio.signum() < 0 || existencias < 0) {
            throw new IllegalArgumentException("Precio y existencias no pueden ser negativos");
        }
        this.codigo = codigo;
        this.nombre = nombre;
        this.precio = precio;
        this.existencias = existencias;
        this.minimo = minimo;
    }

    public String getCodigo() {
        return codigo;
    }

    public String getNombre() {
        return nombre;
    }

    public BigDecimal getPrecio() {
        return precio;
    }

    public int getExistencias() {
        return existencias;
    }

    public boolean bajoMinimo() {
        return existencias <= minimo;
    }

    /** Solo Inventario cambia las existencias (por eso no es public). */
    void cambiarExistencias(int diferencia) {
        existencias += diferencia;
    }
}

Fíjate en cambiarExistencias: no tiene public, private ni protected. Sin modificador, el método es visible solo para las clases del mismo paquete (capítulo 69). Como el proyecto no usa paquetes, en la práctica lo ven todas; el comentario deja clara la intención, y cuando el proyecto se organice en paquetes la regla se cumplirá sola.

src\Inventario.java:

import java.math.BigDecimal;
import java.util.ArrayList;
import java.util.Collection;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

/** Todos los productos, buscables por codigo, y las operaciones de la tienda. */
public class Inventario {

    /** LinkedHashMap: busca por codigo al instante y recuerda el orden en que se agregaron. */
    private final Map<String, Producto> productos = new LinkedHashMap<>();

    public void agregar(Producto producto) {
        if (productos.containsKey(producto.getCodigo())) {
            throw new IllegalArgumentException("Ya existe el codigo " + producto.getCodigo());
        }
        productos.put(producto.getCodigo(), producto);
    }

    public Producto buscar(String codigo) {
        return productos.get(codigo);   // null si no existe
    }

    /** Vende y devuelve el total a cobrar. Si no alcanza, no cambia nada y lanza la excepcion. */
    public BigDecimal vender(String codigo, int cantidad) throws SinExistenciasException {
        Producto producto = productos.get(codigo);
        if (producto == null) {
            throw new IllegalArgumentException("No existe el codigo " + codigo);
        }
        if (cantidad > producto.getExistencias()) {
            throw new SinExistenciasException(producto, cantidad);
        }
        producto.cambiarExistencias(-cantidad);
        return producto.getPrecio().multiply(BigDecimal.valueOf(cantidad));
    }

    public void reponer(String codigo, int cantidad) {
        productos.get(codigo).cambiarExistencias(cantidad);
    }

    public List<Producto> porReponer() {
        List<Producto> lista = new ArrayList<>();
        for (Producto p : productos.values()) {
            if (p.bajoMinimo()) {
                lista.add(p);
            }
        }
        return lista;
    }

    public Collection<Producto> todos() {
        return productos.values();
    }
}
  • Un Map guarda parejas clave → valor, como un diccionario: buscas la palabra (el código "A01") y obtienes la definición (el producto) al instante, sin recorrer la lista. LinkedHashMap además recuerda el orden en que se agregaron.
  • vender comprueba todo antes de cambiar nada: primero que el producto exista, luego que alcance, y solo entonces descuenta. Si lanzara la excepción a mitad de camino, el inventario quedaría a medias.
  • BigDecimal.valueOf(cantidad) convierte el int en BigDecimal para poder multiplicar.

    private static final String[] COLUMNAS = {"Código", "Producto", "Precio (Q)", "Existencias"};

    private List<Producto> filas;

    public ModeloTablaInventario(Inventario inventario) {

    }

    public int getRowCount() {

    public int getColumnCount() {

    public String getColumnName(int columna) {

        Producto p = filas.get(fila);
        return switch (columna) {
            case 0 -> p.getCodigo();
            case 1 -> p.getNombre();
            case 2 -> p.getPrecio();
            default -> p.getExistencias();
        };
    }

    /** Producto de una fila, para saber cual eligio el usuario. */
    public Producto getProducto(int fila) {
        return filas.get(fila);
    }
}

AbstractTableModel es una clase abstracta (capítulo 24): ya trae casi todo, y te obliga a escribir solo tres métodos, getRowCount, getColumnCount y getValueAt. getColumnName es opcional; sin él, las columnas se llamarían A, B, C. La tabla llama a getValueAt una vez por cada celda visible, cada vez que se dibuja. Es el mismo principio de paintComponent: Swing pregunta, tú respondes.

Por último, una tabla con el aspecto neón. Este componente, src\TablaNeon.java, no sabe nada de productos: sirve para cualquier tabla de cualquier programa, así que es candidato a sumarse a tu kit.

import java.awt.Color;
import java.awt.Component;
import java.awt.Font;
import java.util.regex.Pattern;
import javax.swing.BorderFactory;
import javax.swing.JLabel;
import javax.swing.JScrollPane;
import javax.swing.JTable;
import javax.swing.RowFilter;
import javax.swing.table.DefaultTableCellRenderer;
import javax.swing.table.TableModel;
import javax.swing.table.TableRowSorter;

/**
 * Un JTable con los colores del Tema y un filtro de busqueda. Sirve para
 * cualquier tabla (inventario, clientes, ventas...): solo cambia el modelo.
 */
public class TablaNeon extends JTable {

    private final TableRowSorter<TableModel> ordenador;

    public TablaNeon(TableModel modelo) {
        super(modelo);
        ordenador = new TableRowSorter<>(modelo);
        setRowSorter(ordenador);                  // clic en un titulo = ordenar por esa columna

        setRowHeight(34);
        setFont(Tema.fuente(Font.PLAIN, 15f));
        setForeground(Tema.TEXTO);
        setBackground(Tema.FONDO_ARRIBA);
        setGridColor(Tema.conAlfa(Tema.LAVANDA, 40));
        setSelectionBackground(Tema.conAlfa(Tema.ROSA, 110));
        setSelectionForeground(Tema.TEXTO);
        setFillsViewportHeight(true);

        getTableHeader().setFont(Tema.fuente(Font.BOLD, 14f));
        getTableHeader().setBackground(Tema.FONDO_ABAJO);
        getTableHeader().setForeground(Tema.LAVANDA);
        getTableHeader().setReorderingAllowed(false);

        // Filas alternas un poco mas claras, para que el ojo siga la linea.
        setDefaultRenderer(Object.class, new DefaultTableCellRenderer() {
            @Override
            public Component getTableCellRendererComponent(JTable tabla, Object valor, boolean elegida,
                                                           boolean foco, int fila, int columna) {
                JLabel celda = (JLabel) super.getTableCellRendererComponent(tabla, valor, elegida, foco, fila, columna);
                celda.setBorder(BorderFactory.createEmptyBorder(0, 10, 0, 10));
                if (!elegida) {
                    celda.setBackground(fila % 2 == 0 ? Tema.FONDO_ARRIBA : new Color(0x26, 0x1F, 0x52));
                }
                return celda;
            }
        });
    }

    /** Muestra solo las filas que contienen el texto (sin importar mayusculas). Vacio = todas. */
    public void filtrar(String texto) {
        if (texto == null || texto.isBlank()) {
            ordenador.setRowFilter(null);
        } else {
            ordenador.setRowFilter(RowFilter.regexFilter("(?i)" + Pattern.quote(texto.strip())));
        }
    }

    /** La tabla dentro de su barra de desplazamiento, sin el borde gris de Swing. */
    public JScrollPane conDesplazamiento() {
        JScrollPane panel = new JScrollPane(this);
        panel.setBorder(BorderFactory.createEmptyBorder());
        panel.getViewport().setBackground(Tema.FONDO_ARRIBA);
        return panel;
    }
}
  • TableRowSorter agrega dos cosas a la tabla: clic en el título de una columna para ordenar y la posibilidad de filtrar filas.
  • RowFilter.regexFilter("(?i)" + Pattern.quote(texto)) deja ver solo las filas que contienen el texto en alguna columna. (?i) significa «sin distinguir mayúsculas» y Pattern.quote hace que caracteres como el punto se busquen tal cual. Conéctalo a un CampoTexto con un DocumentListener y tendrás búsqueda mientras escribes.
  • El renderer es el objeto que dibuja cada celda. Se hereda de DefaultTableCellRenderer (que es un JLabel) y se sobrescribe un método para cambiar el fondo de las filas pares e impares: herencia y polimorfismo, capítulos 22 y 23.
  • conDesplazamiento() mete la tabla en un JScrollPane. Una tabla siempre va dentro de uno: es el que muestra los títulos de las columnas y la barra cuando hay muchas filas.

En la pantalla se usa así: TablaNeon tabla = new TablaNeon(new ModeloTablaInventario(inventario)); y se agrega tabla.conDesplazamiento() dentro de una Tarjeta. Se comprobó que con el filtro "a0" y cuatro productos (A01, F02, C03, A04) la tabla deja visibles solo las dos filas de código A0.

Resumen

  • Lo que aprendiste no es «un totito»: es separar lógica e interfaz, probar en consola, centralizar el estilo, crear componentes reutilizables, navegar entre pantallas y publicar.
  • El kit neón (Tema, Dibujo, Iconos, BotonNeon, Tarjeta, Rotulo, CampoTexto) compila solo y se copia tal cual a cualquier proyecto.
  • Conecta 4 enseña la gravedad (un ciclo de abajo hacia arriba) y los vectores de dirección; su IA necesita Minimax con profundidad limitada.
  • Buscaminas enseña la apertura recursiva, sus casos base, y cómo cambiarla por una cola cuando la recursión es demasiado profunda.
  • El gestor de tareas enseña a guardar datos: formato, UTF-8, la carpeta del usuario y cuándo guardar.
  • La calculadora demuestra que el kit sirve fuera de los juegos y enseña BigDecimal, GridLayout y los atajos de teclado.
  • El inventario enseña JTable con su modelo, Map, dinero exacto y excepciones propias.
  • La receta es siempre la misma: frase y bocetos → clases → lógica probada en consola → kit → pantallas → unir → empaquetar, con un commit por paso.
Aplícalo fuera del Totito Los cinco proyectos son plantillas de programas reales:
  • El Buscaminas es un «recorrido de vecinos»: el bote de pintura de Paint, que rellena un área del mismo color, usa exactamente la misma apertura en cascada.
  • El gestor de tareas es la base de cualquier programa que recuerda cosas: notas, recordatorios, la configuración de un juego (volumen, último nombre usado).
  • La calculadora es una máquina de estados con teclado, como un cajero automático o la pantalla de un microondas.
  • El inventario es, con otras columnas, un sistema de clientes, de alumnos y notas, de citas de una clínica o un punto de venta.
