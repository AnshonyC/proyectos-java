Capítulo 36Tipografía, espaciado, alineación y consistencia

El color atrae la mirada, pero son la letra y los espacios los que hacen que una interfaz se vea ordenada o improvisada. En este capítulo aprendes cómo elige el Totito su fuente, qué tamaños usa y por qué, cómo se centra un texto de verdad, cuánto espacio necesita un halo de neón y qué reglas mantienen todas las pantallas coherentes entre sí.

Vocabulario mínimo de tipografía

La tipografía es el arte de elegir y colocar letras. Antes de seguir, cuatro palabras que se confunden a menudo:

PalabraQué esEjemplo
Familia tipográficaUn diseño de letra completo, con todas sus variantes.Arial, Segoe UI, Nunito
Estilo (o peso)Una variante de la familia: normal, negrita, cursiva, fina, gruesa.Arial Bold (negrita)
TamañoLa altura de la letra, medida en puntos.25 puntos
FuenteEn Java, la combinación concreta de las tres cosas anteriores. Es un objeto de la clase java.awt.Font.new Font("Arial", Font.BOLD, 25)

Con remate, sin remate y de ancho fijo

Las familias se agrupan en grandes categorías. Las tres que importan para programar:

  • Con remate (serif): las letras tienen unos pequeños «pies» o terminaciones. Times New Roman es la más conocida. Se asocian a libros y periódicos.
  • Sin remate (sans serif, «sin remate» en francés): trazos limpios, sin terminaciones. Arial, Segoe UI. Son las más usadas en pantallas porque se leen bien en tamaños pequeños.
  • De ancho fijo (monospace): todas las letras ocupan lo mismo, la «i» igual que la «m». Se usan para código (como el de este libro) porque alinean las columnas.

El diseño del Totito usa una sin remate redondeada y geométrica: letras basadas en círculos, con terminaciones suaves. Ese estilo transmite algo amable y lúdico, perfecto para un juego. Familias de ese tipo son, por ejemplo, Nunito, Poppins o Montserrat.

El problema: Java solo usa las fuentes que hay en la computadora

Aquí aparece la primera diferencia entre una maqueta y un programa. El diseñador eligió una letra que tenía instalada; tu programa se ejecutará en computadoras que no la tienen. Java solo puede dibujar con las fuentes instaladas en el sistema operativo (o con archivos de fuente que el programa traiga y cargue él mismo).

Peor aún: si pides una familia que no existe, Java no da error. Usa en silencio una fuente genérica llamada Dialog y sigue adelante. Puedes escribir new Font("Nunito", Font.BOLD, 25) y no enterarte nunca de que se está viendo otra letra.

La lista de respaldo de Tema

El Totito resuelve el problema con una lista de preferencias: intenta la fuente ideal y, si no está, la siguiente, y así hasta llegar a una que exista. Es la misma idea que usan las páginas web con su propiedad font-family.

private static final List<String> FAMILIAS = Arrays.asList(
        "Nunito", "Poppins", "Montserrat", "Segoe UI", "Helvetica Neue",
        "Ubuntu", "Arial", "Liberation Sans", "DejaVu Sans");

Y si no hay ninguna, el método devuelve Font.SANS_SERIF, que existe siempre:

private static String elegirFamilia() {
    try {
        List<String> instaladas = Arrays.asList(
                GraphicsEnvironment.getLocalGraphicsEnvironment().getAvailableFontFamilyNames());
        for (String familia : FAMILIAS) {
            if (instaladas.contains(familia)) {
                return familia;
            }
        }
    } catch (RuntimeException e) {
        // Sin acceso a las fuentes del sistema: se usa la generica.
    }
    return Font.SANS_SERIF;
}

GraphicsEnvironment.getLocalGraphicsEnvironment() representa «el entorno gráfico de esta computadora», y su método getAvailableFontFamilyNames() devuelve un arreglo con los nombres de todas las familias instaladas. El for recorre las preferidas en orden y devuelve la primera que aparezca. El try/catch (capítulo 26) protege contra el caso raro de que el sistema no deje consultar sus fuentes.

Un detalle de eficiencia: el resultado se guarda en una constante, private static final String FAMILIA = elegirFamilia();. Una variable static se inicializa una sola vez, cuando Java carga la clase Tema por primera vez (capítulo 20). Consultar las fuentes del sistema es lento; hacerlo cada vez que se dibuja un texto (decenas de veces por segundo) sería un desperdicio.

Por qué las capturas del libro no son idénticas a lo que verás Las capturas de este libro se tomaron en Linux, donde la primera familia disponible de la lista es Liberation Sans. En tu Windows, el Totito usará Segoe UI (o Nunito, si la instalas). Los tamaños y posiciones son los mismos, pero la forma de las letras cambia un poco. Eso es justo lo que la lista de respaldo pretende: que el programa se vea bien en cualquier sistema, aunque no idéntico.

Tamaños: una escala, no números sueltos

Puntos y píxeles

El tamaño de una fuente se mide en puntos (una medida de imprenta: 72 puntos son una pulgada). Java2D considera que la pantalla tiene 72 puntos por pulgada, así que un punto equivale a un píxel en sus coordenadas: una letra de 25 puntos ocupa unos 25 píxeles de alto, contando el espacio para acentos y colas. Si Windows tiene la escala de pantalla al 125 % o al 150 %, Java (desde la versión 9) agranda todo en la misma proporción, letras y componentes por igual, y las proporciones se mantienen.

Cómo crea fuentes el Totito

public static Font fuente(int estilo, float tamano) {
    return new Font(FAMILIA, estilo, 12).deriveFont(tamano);
}

¿Por qué crear la fuente con tamaño 12 y luego cambiarlo? Porque el constructor de Font solo acepta tamaños enteros (int), y el Totito usa tamaños con decimales, como 10,5 para el lema. deriveFont(float) crea una copia de la fuente con el nuevo tamaño, que sí admite decimales. El 12 es un valor de paso que se descarta.

Fíjate en que los tamaños no están repartidos al azar: forman escalones. Del lema al texto secundario, de ahí al cuerpo, al subtítulo, al título y a la exhibición, cada nivel es aproximadamente un 20 %–25 % más grande que el anterior (13 → 17 → 21 → 25 → 36). Los diseñadores llaman a esto una escala tipográfica: un conjunto pequeño de tamaños con una proporción constante entre ellos. Con una escala, cada tamaño «significa» algo (este es un título, esto es una nota) y la jerarquía del capítulo 34 se lee sola.

Para tus proyectos: cinco o seis tamaños Elige un tamaño base para el cuerpo (16 es un buen número en pantalla) y multiplícalo y divídelo por 1,25: 10, 13, 16, 20, 25, 31, 39. Usa solo esos. Si te encuentras escribiendo un 15 o un 23 «porque se ve mejor aquí», probablemente estés rompiendo la jerarquía.

Cuando el texto no cabe, la letra se achica

Los títulos variables, como «¡Ganó …!», pueden ser más largos de lo previsto. Rotulo (capítulo 46) mide el texto y, mientras no quepa, le quita un punto a la letra (sin bajar de 12):

while (fm.stringWidth(texto) + extraIcono > getWidth() - 20 && f.getSize2D() > 12) {
    f = f.deriveFont(f.getSize2D() - 1);
    ...
}

Es una excepción controlada a la escala: preferimos un título un poco más pequeño a uno cortado.

Pesos: normal y negrita

Java define tres estilos básicos que se combinan con el operador |: Font.PLAIN (normal), Font.BOLD (negrita), Font.ITALIC (cursiva) y Font.BOLD | Font.ITALIC. El Totito solo usa los dos primeros, con una regla sencilla:

  • Negrita para lo que se pulsa (todos los botones) y para lo que nombra algo (títulos, nombres de jugadores, opciones).
  • Normal para lo que explica (los pasos, las descripciones, las etiquetas como «Nombre»).

Combinar el peso con el color es la manera más fina de crear jerarquía: en OpcionModo, «2 jugadores» va en negrita y blanco, y «Turnos en el mismo equipo» en normal y TEXTO_SUAVE. Sin cambiar casi el tamaño (16 frente a 12), el ojo entiende cuál es el título y cuál la explicación.

No abuses de la negrita Si todo está en negrita, nada destaca. Y evita la cursiva en pantallas con letra pequeña: con pocos píxeles las letras inclinadas se ven dentadas. Por eso el Totito no la usa.

El espacio entre letras (tracking)

Los títulos de sección del diseño («J U G A D O R E S») tienen las letras visiblemente separadas. Ese espacio adicional entre todas las letras se llama tracking (o interletraje). En Java se consigue con un atributo de la fuente:

public static Font fuenteEspaciada(int estilo, float tamano, float espaciado) {
    return fuente(estilo, tamano).deriveFont(Map.of(TextAttribute.TRACKING, espaciado));
}

deriveFont también acepta un mapa de atributos (Map.of(clave, valor) crea un mapa con una sola entrada). TextAttribute.TRACKING es la clave del espaciado y su valor es una fracción del tamaño de la letra: 0 es el espaciado normal y 0,3 agrega un 30 % del tamaño después de cada letra. Para «JUGADORES» a 17 puntos con espaciado 0,3:

  • Espacio extra por letra: 17 × 0,3 = 5,1 píxeles.
  • Ancho sin espaciado: 108 píxeles. Con espaciado: 154 píxeles (medido con Liberation Sans).
  • Diferencia: 46 píxeles = 9 letras × 5,1. Las cuentas cuadran.

Un detalle fino que pocos conocen: Java agrega el espacio extra también después de la última letra. Eso significa que stringWidth cuenta unos 5 píxeles de aire invisible a la derecha, y un texto espaciado centrado con (ancho - stringWidth) / 2 queda desplazado unos 2,5 píxeles a la izquierda. En el Totito no se nota; en un logotipo grande con mucho espaciado sí, y la solución es restar ese último espacio antes de centrar.

Mayúsculas espaciadas para títulos de sección

El Totito usa tres fuentes espaciadas: los títulos de sección (17 puntos, 0,3), el lema del encabezado (10,5 puntos, 0,28) y la etiqueta «EMPATES» del marcador (11 puntos, 0,2). Las tres tienen algo en común: son palabras cortas en mayúsculas. No es casualidad:

  • Las mayúsculas tienen todas la misma altura y forman un bloque compacto; pegadas, se ven apretadas. Separarlas les devuelve el aire.
  • Las mayúsculas espaciadas se leen como una etiqueta, no como una frase. Le dicen al usuario «esto es el nombre de una zona», no «esto es algo para leer».
  • Con letras pequeñas (10,5 puntos), el espaciado mejora la legibilidad: cada letra se distingue mejor.

Las mayúsculas se escriben así en el texto del código ("JUGADORES", "SÍMBOLOS"); no se transforman con toUpperCase(). Y en el lema, los separadores son puntos medios con dos espacios a cada lado: "ESTRATEGIA • DIVERSIÓN • SIEMPRE UN CLÁSICO".

Nunca para frases largas Un párrafo entero en mayúsculas espaciadas cuesta muchísimo leerlo: perdemos la forma de las palabras, que es en gran parte cómo leemos. Úsalas solo para etiquetas de una a cuatro palabras.

La línea base y el centrado vertical

Este es probablemente el detalle técnico más importante del capítulo, y el origen de muchísimos textos «mal centrados» en programas de principiantes.

drawString no empieza arriba

Cuando escribes g2.drawString("Jugar", x, y), la coordenada y no es la parte de arriba del texto, sino su línea base: la línea invisible sobre la que «se apoyan» las letras, como los renglones de un cuaderno. Las letras suben por encima de ella y algunas (la «g», la «j», la «p») bajan por debajo.

La fórmula del centrado vertical

Supón que quieres el texto centrado en vertical sobre una altura yCentro (por ejemplo, la mitad de un botón). El texto ocupa desde base − ascent (arriba) hasta base + descent (abajo). Su centro está en el punto medio:

centro del texto = base + (descent − ascent) ÷ 2

Queremos que ese centro sea yCentro. Despejando la base:

base = yCentro + (ascent − descent) ÷ 2

Es exactamente lo que hace Dibujo.lineaBaseCentrada, una de las líneas más usadas del Totito:

public static float lineaBaseCentrada(FontMetrics fm, float yCentro) {
    return yCentro + (fm.getAscent() - fm.getDescent()) / 2f;
}

Con números: en un botón del menú, la forma visible va de y = 9 a y = 79, así que su centro es 44. Con Liberation Sans negrita 25 (ascent 23, descent 6): base = 44 + (23 − 6) ÷ 2 = 44 + 8,5 = 52,5. El texto se dibuja con su línea base en 52,5 y queda centrado.

La gran ventaja es que la fórmula se adapta a la fuente: con Segoe UI los valores de ascent y descent serán otros, y el texto seguirá centrado. Si hubieras escrito «52» a mano, en Windows el texto quedaría torcido.

Centrado matemático y centrado óptico Como el ascent reserva sitio para acentos que la mayoría de las palabras no tienen, a veces un texto matemáticamente centrado parece un pelo bajo. Los diseñadores corrigen «a ojo» uno o dos píxeles. El Totito lo hace en Rotulo: cuando un título lleva subrayado, lo sube 6 píxeles (getHeight() / 2f - (conSubrayado ? 6 : 0)) para que el conjunto texto + línea quede equilibrado.

Y el centrado horizontal

Es más sencillo: si el espacio mide ancho y el texto mide fm.stringWidth(texto), el texto empieza en (ancho − stringWidth) ÷ 2. Cuando además hay un icono, se centra el bloque completo (icono + hueco + texto), como hace BotonNeon en sus píldoras:

double total = tamIcono + hueco + fm.stringWidth(texto);
double x = forma.getCenterX() - total / 2;

Ejemplo con «Regresar» (píldora de 330 × 70; forma visible de 312 × 52): icono de 52 × 0,44 ≈ 23 píxeles, hueco de 16 y texto de 82 píxeles (Liberation Sans negrita 19). Total: 23 + 16 + 82 = 121. El bloque empieza en 165 − 60,5 = 104,5 y el texto en 104,5 + 23 + 16 = 143,5. Si centraras solo el texto, el icono «colgaría» a la izquierda y el conjunto se vería desplazado.

Márgenes: el espacio que necesita el halo

En el capítulo 34 viste que un BotonNeon del menú mide 384 × 88, pero su forma visible mide 366 × 70: hay un margen de 9 píxeles por lado. ¿Por qué 9 y no 5 o 20? Se puede calcular.

Un componente no puede pintar fuera de sí mismo

Cada componente de Swing dibuja dentro de su propio rectángulo. Si intentas pintar fuera, lo que sobresale se recorta (en inglés, clipping): simplemente no aparece. Para un halo, que por definición se desborda alrededor del trazo, eso es un problema: si la forma toca el borde del componente, el halo queda cortado en seco.

(La línea punteada es el borde del componente.)

El cálculo

Un trazo de grosor g se dibuja centrado sobre la línea de la figura: la mitad cae hacia afuera y la mitad hacia adentro. En Dibujo.trazoNeon, la capa más ancha del halo mide g + 6 × 2,4 = g + 14,4. Por lo tanto sobresale de la figura:

lo que sobresale = (g + 14,4) ÷ 2 = g ÷ 2 + 7,2 píxeles

Cada margen es el mínimo necesario redondeado hacia arriba, con un píxel o dos de holgura. La intensidad del neón no cambia este cálculo: solo cambia la opacidad de las capas, no su grosor.

Margen exterior y relleno interior

Conviene distinguir dos espacios:

  • Margen (exterior): entre el borde del componente y la forma visible. En el Totito sirve para el halo y se descuenta al dibujar (new RoundRectangle2D.Double(MARGEN, MARGEN, getWidth() - 2 * MARGEN, …)).
  • Relleno (interior, en inglés padding): entre el borde de una caja y su contenido. En Swing se pone con un borde vacío: tarjeta.setBorder(BorderFactory.createEmptyBorder(34, 28, 34, 28)) deja 34 píxeles arriba y abajo y 28 a los lados (en ese orden: arriba, izquierda, abajo, derecha) antes de colocar los botones.

Una consecuencia importante: el espacio que ves entre dos formas es la suma de los márgenes de ambos componentes más la separación que pongas entre ellos. Entre dos botones del menú hay 9 (margen de abajo del primero) + 14 (el espacio fijo) + 9 (margen de arriba del segundo) = 32 píxeles visibles. Por eso en el Totito las separaciones del código parecen pequeñas: el halo ya aporta casi 20 píxeles de aire.

Alineación y rejilla

Una rejilla (en inglés, grid) es un conjunto de líneas invisibles a las que se alinean los elementos. Las páginas web suelen usar rejillas de 12 columnas; un juego como el Totito usa la rejilla más simple que existe: una sola columna centrada. Todo se alinea a la línea vertical que pasa por la mitad de la ventana (x = 320).

En el código, eso se consigue con una sola línea repetida en todos los componentes: setAlignmentX(CENTER_ALIGNMENT). PantallaBase.agregar se la aplica a todo lo que se agrega:

protected void agregar(JComponent componente) {
    componente.setAlignmentX(CENTER_ALIGNMENT);
    contenido.add(componente);
}
La trampa de la alineación en BoxLayout En un panel con BoxLayout vertical (capítulo 37), si unos componentes tienen alineación centrada y otros a la izquierda (el valor por defecto de muchos componentes), Swing hace cosas extrañas: alinea los bordes izquierdos de unos con el centro de los otros y todo queda torcido. Regla: todos los hijos de un mismo BoxLayout con la misma alineación. Por eso el Totito se la pone a todo, sin excepción.

Los anchos también forman una rejilla

Aunque cada componente tiene su propio ancho, se agrupan en dos medidas que se repiten:

Ancho del componenteQuién lo usa
≈ 590 (columna ancha)Marcador (590), letrero de turno (590), fila de tarjetas de jugador (290 + 8 + 290 = 588), fila de opciones de modo (290 + 6 + 290 = 586), títulos de sección (560)
≈ 440–480 (columna de tarjeta)Tarjeta del menú (440), tarjeta de instrucciones (460), tarjeta de resultado (480)

La columna ancha deja unos 25 píxeles de aire a cada lado de la ventana de 640; la columna de tarjeta, entre 80 y 100. Ese «casi igual» en todas las pantallas hace que, al pasar de una a otra, las cosas no salten de sitio.

Centrar lo corto, alinear a la izquierda lo largo

Que la columna esté centrada no significa que todo el texto deba estarlo. Los títulos y botones (una línea, pocas palabras) se centran. Pero los pasos de las instrucciones, que tienen dos líneas cada uno, van alineados a la izquierda dentro de su bloque, con los números formando una columna. Un texto de varias líneas centrado obliga al ojo a buscar el principio de cada línea en un lugar distinto; alineado a la izquierda, siempre empieza en el mismo sitio.

Ritmo vertical: los espacios entre bloques

El ritmo vertical es la regularidad de los espacios de arriba abajo. Un buen ritmo aplica la ley de proximidad del capítulo 34: poco espacio dentro de un grupo, más espacio entre grupos. En la pantalla de configuración:

  • Entre el título «JUGADORES» y sus tarjetas: 0 píxeles de separación en el código (solo los márgenes de halo). El título está pegado a lo que nombra.
  • Entre las tarjetas y el título siguiente: espacio(2) más los márgenes. Un poco más de aire marca el cambio de sección.

Las pantallas usan dos herramientas de PantallaBase (verás cómo funcionan por dentro en el capítulo 37):

  • espacio(n): una separación fija de n píxeles.
  • relleno(): un espacio elástico que se estira para ocupar lo que sobre. Poniendo uno al principio y otro al final, el contenido queda centrado en vertical.

Las cuentas de la pantalla más llena

¿Por qué en la configuración los espacios son tan pequeños (2 y 4) mientras que en el menú la tarjeta flota con mucho aire? Hagamos la suma de los altos de la pantalla de configuración, de arriba abajo:

El espacio disponible debajo del encabezado es 690 − 96 (encabezado) − 10 (borde inferior del contenido) = 584 píxeles. Sobran solo 10, que los dos relleno() reparten: 5 arriba y 5 abajo. ¡La pantalla está al límite! Cualquier espacio mayor habría empujado el botón «Volver» fuera de la ventana. El menú, en cambio, solo tiene una tarjeta de 360 píxeles de alto (34 + 88 + 14 + 88 + 14 + 88 + 34): los rellenos se reparten 584 − 360 = 224 píxeles, 112 arriba y 112 abajo, y la tarjeta queda flotando en el centro. Las mismas dos herramientas producen resultados muy distintos según el contenido, y por eso son tan útiles.

Una unidad base de espaciado En proyectos nuevos, elige una unidad (4 u 8 píxeles) y haz que todos los espacios, márgenes y rellenos sean múltiplos de ella: 4, 8, 12, 16, 24, 32. El Totito usa valores ajustados a ojo (2, 6, 14, 34…) porque se calcaron del diseño, pero una unidad base hace que el ritmo salga regular sin pensarlo y facilita ponerse de acuerdo con un diseñador.

El tamaño de la ventana: 640 × 690

La ventana del Totito mide 640 píxeles de ancho y 690 de alto. Está escrito en PanelPrincipal, con un comentario que da la razón:

/** Tamano de la ventana. Cabe en pantallas de 1366x768. */
public static final int ANCHO = 640;
public static final int ALTO = 690;

La resolución de 1366 × 768 sigue siendo muy común en portátiles económicos. Hagamos la cuenta vertical en Windows: la barra de tareas ocupa unos 40 píxeles, así que quedan 728 libres; la barra de título de la ventana ocupa unos 30. Con 690 de contenido, la ventana completa mide unos 720: cabe, con 8 píxeles de sobra. 700 de alto ya habría sido demasiado justo. El ancho no es problema (640 de 1366).

Otras decisiones relacionadas, todas en TotitoApp y PanelPrincipal:

  • El tamaño se fija en el contenido, no en la ventana: PanelPrincipal llama a setPreferredSize(new Dimension(ANCHO, ALTO)) y la ventana usa pack(), que la ajusta para que el contenido mida exactamente eso. Si en cambio hicieras setSize(640, 690) en la ventana, la barra de título y los bordes se comerían parte de ese espacio y el contenido sería más pequeño de lo planeado.
  • No se puede cambiar el tamaño (setResizable(false)): los componentes tienen tamaños fijos en píxeles, así que agrandar la ventana solo añadiría espacio vacío alrededor.
  • Se abre centrada: setLocationRelativeTo(null).
La escala de pantalla de Windows Si Windows tiene la escala al 125 %, Java agranda la ventana a 800 × 862 píxeles físicos. En una pantalla de 1920 × 1080 (la combinación típica de 125 %) cabe sin problema. En una de 1366 × 768 con escala de 125 % no cabría, pero es un caso raro: Windows recomienda el 100 % para esa resolución.

Consistencia: las mismas reglas en todas partes

La consistencia es lo que hace que cinco pantallas distintas parezcan un solo programa. No es algo que se consiga al final «repasando»: se construye desde el principio repitiendo los mismos valores. Estos son los del Totito.

El resto de las reglas

  • Colores: solo de Tema (capítulo 35).
  • Fuentes: solo con Tema.fuente o Tema.fuenteEspaciada, con los tamaños de la escala.
  • Halos: siempre con Dibujo.trazoNeon, nunca dibujados a mano.
  • Iconos: todos de línea, con puntas redondeadas (Dibujo.redondo) y medidas en fracciones del tamaño (capítulo 42).
  • Alineación: todo centrado en la columna.
  • Estados: los mismos efectos (más brillo, oscurecer, 40 % de opacidad) en todos los controles.

Fíjate en que casi todas estas reglas están en el código, no en la memoria del programador: si para crear un botón tienes que llamar a BotonNeon.pildora(…), el botón saldrá con el radio, el grosor, el halo y la fuente correctos sin que tengas que acordarte de nada. La mejor consistencia es la que no se puede romper por descuido.

Resumen

  • Una fuente en Java es familia + estilo + tamaño. Java solo usa fuentes instaladas y, si pides una que no existe, cambia a otra en silencio.
  • Tema recorre una lista de respaldo (Nunito… Segoe UI… Arial… DejaVu Sans) y usa la primera instalada; si no hay ninguna, SansSerif. En Windows será casi siempre Segoe UI.
  • Los tamaños forman una escala (de 10,5 a 40) con niveles que significan algo; negrita para lo que se pulsa o nombra, normal para lo que explica.
  • El tracking (TextAttribute.TRACKING) separa las letras de las etiquetas cortas en mayúsculas; es una fracción del tamaño.
  • drawString usa la línea base; para centrar en vertical: base = yCentro + (ascent − descent) ÷ 2.
  • El margen para el halo se calcula: grosor ÷ 2 + 7,2; por eso 9 y 10 píxeles. El espacio visible entre dos formas incluye los márgenes de ambas.
  • Todo se alinea a una columna centrada; el ritmo vertical usa espacios fijos y rellenos elásticos.
  • La ventana mide 640 × 690 para caber en 1366 × 768; la consistencia (radios, grosores, colores, fuentes) se garantiza con constantes y métodos de fábrica.
Aplícalo fuera del Totito
  • Cualquier programa de escritorio: copia el patrón de la lista de respaldo de fuentes. Un programa de facturación que pide «Calibri» a secas se verá distinto en cada oficina; con una lista y un respaldo genérico, se verá bien en todas.
  • Páginas web: las mismas ideas tienen nombre propio en CSS: font-family con lista de respaldo, letter-spacing para el tracking, line-height para el alto de línea, padding y margin para relleno y margen, y border-radius para los radios.
  • Botones, etiquetas y celdas de tabla en cualquier interfaz dibujada a mano (un juego, un gráfico, un visor): usa siempre FontMetrics y la fórmula de la línea base para centrar texto. Es lo que diferencia un programa pulido de uno amateur.
  • Documentos y presentaciones: una escala de cinco tamaños, mayúsculas espaciadas solo para etiquetas, poco espacio dentro de los grupos y más entre grupos. Funciona igual en un informe de Word que en un afiche.
