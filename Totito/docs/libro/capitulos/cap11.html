Capítulo 11Cómo funciona Java

Antes de escribir el Totito necesitas saber qué pasa entre el momento en que tecleas una línea de Java y el momento en que la computadora la obedece. En este capítulo escribes, compilas y ejecutas tu primer programa, entiendes cada palabra y cada símbolo que lleva, y aprendes a leer la «anatomía» de cualquier archivo del Totito.

Qué es un programa y qué es un lenguaje de programación

Un programa es una lista de instrucciones que la computadora sigue al pie de la letra, una tras otra. El Totito es un programa: «dibuja el tablero», «cuando hagan clic en una casilla, pon una X», «revisa si hay tres en línea»…

El problema es que el procesador de tu computadora (la CPU, el chip que hace los cálculos) solo entiende código máquina: números binarios del tipo 10110000 01100001. Nadie escribe programas así. Por eso existen los lenguajes de programación: idiomas a medio camino entre el español y el código máquina, con palabras en inglés (if, for, class) y reglas muy estrictas. Java es uno de ellos.

Lo que tú escribes en Java se llama código fuente: es texto normal, que podrías abrir con el Bloc de notas. Se guarda en archivos que terminan en .java. Todo el Totito son archivos así: Tablero.java, Jugador.java, PanelTablero.java…

Analogía: la receta y el cocinero. El código fuente es como una receta escrita: describe qué hacer, pero por sí sola no cocina nada. Hace falta alguien que la lea y la ejecute. En Java ese «cocinero» tiene dos ayudantes: el compilador, que revisa y traduce la receta, y la máquina virtual, que la cocina.

El viaje de tu código: fuente → javac → bytecode → JVM

En Java, el camino desde tu texto hasta el programa funcionando tiene dos etapas:

  1. Compilar. Un programa llamado javac (el compilador de Java; la «c» final es de compiler) lee tu archivo .java, comprueba que respete todas las reglas del lenguaje y, si está bien, lo traduce a un archivo .class. Si encuentra un error, se detiene y te dice en qué línea está.
  2. Ejecutar. Otro programa, java, arranca la máquina virtual de Java o JVM (Java Virtual Machine), que carga los .class y los ejecuta.

El contenido de un .class se llama bytecode: instrucciones sencillas, pensadas no para tu procesador concreto sino para una computadora «imaginaria», la JVM. La JVM, que sí está hecha para tu sistema (hay una versión para Windows, otra para macOS, otra para Linux…), traduce ese bytecode al código máquina real mientras el programa corre. Las partes que se repiten mucho las traduce una sola vez y las guarda ya traducidas (eso se llama compilación JIT, just in time, «justo a tiempo»), por eso Java es rápido.

Por qué «escribe una vez, ejecuta en todas partes»

Ese fue el lema con el que nació Java en 1995 (write once, run anywhere). Como el .class no está atado a ningún procesador ni sistema, el mismo archivo funciona en cualquier computadora que tenga una JVM. El Totito que compilas en tu Windows corre igual en la Mac de un amigo, sin cambiar una letra ni volver a compilar. En lenguajes como C, en cambio, el compilador genera directamente código máquina para un sistema concreto, y para Mac habría que compilar otra vez, en una Mac.

Analogía: la partitura. El bytecode es como una partitura musical. El compositor la escribe una vez y cualquier músico del mundo la puede tocar con su instrumento. La JVM es el músico: cada sistema operativo tiene el suyo, pero todos leen la misma partitura.

Si tienes curiosidad, puedes «abrir» un .class con una herramienta del JDK llamada javap. Este es el bytecode real del programa que escribirás en un momento (no hace falta entenderlo; solo para que veas que existe):

Tu primer programa: HolaTotito

Vamos a hacerlo «a mano», sin NetBeans, para que veas cada paso que el IDE normalmente hace por ti. Los ejercicios sueltos de esta Parte III los guardarás en una carpeta aparte, $HOME\Proyectos\Practicas, para no mezclar pruebas con el proyecto Totito.

# Crear la carpeta de prácticas (si ya existe no pasa nada) y entrar en ella
New-Item -ItemType Directory -Force $HOME\Proyectos\Practicas | Out-Null
cd $HOME\Proyectos\Practicas
# Abrir el Bloc de notas con un archivo nuevo llamado HolaTotito.java
notepad HolaTotito.java

Si el Bloc de notas pregunta si quieres crear el archivo, responde Sí. Escribe exactamente esto (respeta mayúsculas y minúsculas) y guarda con Ctrl+S:

public class HolaTotito {
    public static void main(String[] args) {
        System.out.println("¡Hola, Totito!");
        System.out.println("Hoy empiezo a programar en Java.");
    }
}

Ahora compila y ejecuta desde PowerShell, en la misma carpeta:

javac HolaTotito.java
Get-ChildItem
java HolaTotito

javac no muestra nada si todo salió bien (en programación, el silencio suele ser buena noticia). Get-ChildItem te muestra que ahora hay un archivo nuevo, HolaTotito.class, junto a tu HolaTotito.java. Y java HolaTotito imprime:

¡Hola, Totito!
Hoy empiezo a programar en Java.
Fíjate en la diferencia: a javac le das el nombre del archivo con su extensión (HolaTotito.java); a java le das el nombre de la clase, sin extensión (HolaTotito, no HolaTotito.class). Si escribes java HolaTotito.class, Java busca una clase llamada «class» dentro de algo llamado «HolaTotito» y falla.
Hito Acabas de recorrer el viaje completo: escribiste código fuente, lo compilaste a bytecode y la JVM lo ejecutó. Todo lo que harás en este libro, incluido el Totito neón, sigue exactamente este camino; NetBeans solo lo automatiza con un botón.
Atajo para programas de un solo archivo: java HolaTotito.java (con la extensión) compila en memoria y ejecuta de una vez, sin dejar ningún .class. Es lo que hace el libro con herramientas\PruebaConsola.java en el capítulo 32. Para el proyecto entero, con muchos archivos, se sigue usando javac (o NetBeans).

Cada palabra y cada símbolo, uno por uno

Seis líneas y ya hay más de quince cosas que entender. Vamos con todas, porque son las mismas que verás en cada archivo del Totito.

Línea 1: public class HolaTotito {

  • class: anuncia que empieza una clase. En Java todo el código vive dentro de alguna clase; no puedes escribir una instrucción suelta en un archivo. Por ahora piensa en una clase como una «caja con nombre» que agrupa datos e instrucciones relacionados. Tablero es la caja de todo lo que tiene que ver con las casillas; Jugador, la de nombre y ficha. En el capítulo 18 verás que una clase es, sobre todo, un molde para fabricar objetos.
  • HolaTotito: el nombre de la clase. Lo eliges tú, con dos condiciones: no puede tener espacios ni empezar con número, y por convención empieza con mayúscula y junta las palabras con mayúscula inicial (PascalCase): PanelTablero, BotonNeon, IA_Minimax.
  • public: un modificador de acceso; dice que esta clase la puede usar cualquiera, incluida la JVM. Lo opuesto es private («solo yo»), que verás en el capítulo 19. Regla importante: una clase public debe guardarse en un archivo que se llame exactamente igual, con .java al final. public class Tablero vive en Tablero.java; si no coinciden, javac se niega a compilar.
  • {: la llave de apertura. Marca dónde empieza el contenido de la clase. Toda llave que se abre tiene que cerrarse con su }; lo que queda entre las dos es un bloque. En este programa, la llave de la línea 1 se cierra en la línea 6.

Línea 2: public static void main(String[] args) {

Esta línea declara un método. Un método es un bloque de instrucciones con nombre, que se puede ejecutar cuando se le llama (el capítulo 16 está dedicado a ellos). Este en particular es especial: es el punto de entrada. Cuando escribes java HolaTotito, la JVM busca dentro de la clase un método con exactamente esta forma y empieza a ejecutar por su primera línea. En el Totito, el punto de entrada es el main de TotitoApp.

  • public: la JVM está «fuera» de tu clase y necesita poder llamar a main; por eso tiene que ser público.
  • static: significa que el método pertenece a la clase misma y no a un objeto fabricado con ella. Cuando el programa arranca todavía no existe ningún objeto, así que la JVM necesita un método que se pueda llamar «en frío», sin crear nada antes. Eso es lo que garantiza static. (Lo verás a fondo en el capítulo 20.)
  • void: «vacío». Indica que el método no devuelve ningún resultado a quien lo llamó. Otros métodos sí devuelven algo: tableroLleno() del Totito devuelve true o false, y por eso en su lugar dice boolean.
  • main: el nombre, «principal». No es un nombre libre: la JVM busca exactamente main. Si escribes mian, compila sin errores, pero al ejecutar verás Error: Main method not found in class HolaTotito.
  • ( ): los paréntesis después del nombre de un método encierran sus parámetros: los datos que el método recibe para trabajar. Siempre van, aunque estén vacíos (reiniciar()).
  • String[] args: el único parámetro de main. String es el tipo «texto»; los corchetes [] significan «una lista (arreglo) de» (capítulo 15); y args (de arguments) es el nombre que le damos. Es decir: main recibe una lista de textos. ¿Cuáles? Las palabras que escribas después del nombre de la clase al ejecutarla. Lo verás en un momento.
  • {: abre el bloque del método, que se cierra en la línea 5.

Línea 3: System.out.println("¡Hola, Totito!");

  • System: una clase que viene con Java y representa al sistema donde corre el programa.
  • El punto .: significa «de dentro de». System.out se lee «el out que está dentro de System»; out.println, «el println de out». Es la misma idea que una ruta de carpetas: Proyectos\Totito\src. Verás puntos por todas partes: tablero.marcarCasilla(…), Tema.ROSA, Math.max(…).
  • out: la salida estándar, que normalmente es la ventana de la terminal.
  • println: «print line», imprime el texto y después salta a la línea siguiente. Su hermano print imprime sin saltar.
  • ( … ): aquí los paréntesis son una llamada: «ejecuta println con este dato». Lo que va dentro es el argumento.
  • Las comillas dobles "…": delimitan un texto literal (un String). Todo lo que está entre ellas se toma tal cual, letra por letra, con sus espacios y tildes. Sin comillas, Java pensaría que Hola es el nombre de algo y daría error.
  • El punto y coma ;: termina la instrucción (en Java se dice sentencia). Es como el punto final de una oración: le dice al compilador «aquí acaba esta orden». Las líneas que abren o cierran bloques ({ }) no lo llevan; las órdenes, sí.

Líneas 5 y 6: } y }

Cierran el método main y la clase, en ese orden: lo último que se abrió es lo primero que se cierra, como unas muñecas rusas. La sangría (los cuatro espacios al principio de las líneas interiores) no la exige Java, pero ayuda muchísimo a ver qué está dentro de qué. NetBeans la pone sola con Alt+Shift+F.

Los argumentos de main: para qué sirve String[] args

Para comprobar que args recibe de verdad lo que escribes al ejecutar, crea HolaJugador.java en la carpeta de prácticas. Usa un if («si…»), que verás a fondo en el capítulo 13: aquí solo evita leer un nombre cuando no te dieron ninguno.

public class HolaJugador {
    public static void main(String[] args) {
        System.out.println("Recibí " + args.length + " argumento(s).");
        if (args.length > 0) {
            System.out.println("¡Hola, " + args[0] + "! Te toca la X.");
        }
    }
}
javac HolaJugador.java
java HolaJugador
java HolaJugador Ana
java HolaJugador "Ana Lucía" Pedro
Recibí 0 argumento(s).
Recibí 1 argumento(s).
¡Hola, Ana! Te toca la X.
Recibí 2 argumento(s).
¡Hola, Ana Lucía! Te toca la X.

args.length es cuántos textos llegaron; args[0] es el primero (se cuenta desde cero, capítulo 15). Las comillas en PowerShell juntan «Ana Lucía» en un solo argumento. El signo + entre textos los pega (concatena): "Recibí " + 2 + " argumento(s)." da "Recibí 2 argumento(s).". El Totito no usa argumentos (se abre con doble clic), pero muchas herramientas sí: cuando escribes git commit -m "mensaje", commit, -m y "mensaje" llegan al programa git exactamente así.

Crear un archivo, compilar y ejecutar solo para probar «¿cuánto da 7 dividido entre 2 en Java?» es lento. Para eso el JDK trae jshell, una consola donde escribes una línea de Java y ves el resultado al instante (un REPL: read–eval–print loop, «lee, evalúa, imprime, repite»). Anatomía de un archivo del Totito

Ya tienes el vocabulario para leer un archivo real. Este es Jugador.java completo, la clase más pequeña del juego (la escribirás en el capítulo 30):

/**
 * Representa al jugador humano: su nombre y la ficha que utiliza.
 * Es una clase simple de datos, sin logica de juego.
 */
public class Jugador {

    private final String nombre;
    private final char ficha;

    public Jugador(String nombre, char ficha) {
        this.nombre = nombre;
        this.ficha = ficha;
    }

    public String getNombre() {
        return nombre;
    }

    public char getFicha() {
        return ficha;
    }
}

Todo archivo de Java del Totito tiene, de arriba hacia abajo, las mismas partes:

  1. Imports (opcionales). Jugador no los necesita, pero PanelTablero.java empieza así: 
    import java.awt.Color;
import java.awt.Graphics2D;
import javax.swing.JComponent;
    Java trae miles de clases ya hechas, ordenadas en paquetes (carpetas con nombre, como java.awt, para gráficos, o javax.swing, para ventanas). Un import dice «cuando escriba Color, me refiero a java.awt.Color». Sin él tendrías que escribir el nombre completo cada vez; de hecho, PanelTablero lo hace una vez a propósito: java.util.Arrays.fill(fila, Tablero.VACIA). Las clases de java.lang (como String, System o Math) se importan solas, por eso HolaTotito no tuvo ningún import. Y las clases del propio Totito tampoco necesitan import entre ellas porque viven todas en el mismo «paquete por defecto». Es como en una oficina: a un compañero de tu mismo equipo lo llamas por su nombre; a alguien de otro departamento, por nombre y departamento.
  2. Comentario Javadoc de la clase: qué representa y qué no hace. El de Tablero dice expresamente «No conoce nada de la interfaz grafica».
  3. Declaración de la clase: public class Jugador {. Más adelante verás añadidos como extends JComponent (capítulo 22).
  4. Campos (o atributos): las variables que guarda cada objeto de la clase; sus datos. Aquí, nombre y ficha. En Tablero, la matriz casillas.
  5. Constructor: el bloque con el mismo nombre de la clase y sin tipo de retorno (public Jugador(String nombre, char ficha)), que prepara un objeto nuevo (capítulo 20).
  6. Métodos: lo que la clase sabe hacer. getNombre() y getFicha() aquí; marcarCasilla, verificarGanador… en Tablero.
  7. La llave final que cierra la clase.
Analogía: la ficha de un empleado. Una clase se parece a un formulario de recursos humanos. Los campos son las casillas del formulario (nombre, puesto); el constructor es el momento en que se llena al contratar a alguien; los métodos son las preguntas que se le pueden hacer después («¿cómo te llamas?» = getNombre()). Cada persona contratada es un objeto: mismo formulario, datos distintos.

Reglas de escritura que se cumplen en todos los archivos

  • Los espacios y saltos de línea no importan al compilador (salvo dentro de comillas). int x=5 ; y int x = 5; son lo mismo. Se formatea bien por las personas. Por eso las condiciones largas del Totito se parten en varias líneas sin problema.
  • Convenciones de nombres: clases en PascalCase (PanelTablero); métodos y variables en camelCase, empezando en minúscula (marcarCasilla, filaEncima); constantes en MAYUSCULAS_CON_GUIONES (VACIA, PAUSA_IA_MS). Java no lo obliga, pero todo programador de Java lo espera, y al verlo sabes de un vistazo qué es cada cosa.
  • Palabras reservadas: class, public, if, for, int, return… tienen un significado fijo y no puedes usarlas como nombres.
  • Un archivo, una clase pública, y el archivo se llama como ella.

Errores de compilación y errores de ejecución

Vas a ver muchos errores; todos los programadores los ven a diario. Lo importante es saber de qué tipo son, porque se buscan distinto.

Errores de compilación: javac se niega

Ocurren cuando el código no respeta las reglas del lenguaje. javac no genera el .class y te dice archivo, línea y qué esperaba. Los mensajes salen en inglés. Quita el punto y coma de la línea 3 de HolaTotito y compila:

HolaTotito.java:3: error: ';' expected
        System.out.println("¡Hola, Totito!")
                                            ^
1 error

Se lee: «en HolaTotito.java, línea 3, esperaba un ;», y el ^ apunta al lugar exacto. Ahora pon el ; pero escribe mal el método (printn):

HolaTotito.java:3: error: cannot find symbol
        System.out.printn("¡Hola, Totito!");
                  ^
  symbol:   method printn(String)
  location: variable out of type PrintStream
1 error

«No encuentro el símbolo»: no existe ningún método printn en out. Es el error más común de todos y casi siempre significa una letra mal escrita, una mayúscula equivocada o un import que falta. Errores de ejecución: compila, pero falla al correr

El código es correcto para el compilador, pero al ejecutarse ocurre algo imposible: leer una posición que no existe, dividir entre cero, usar un objeto que no existe. La JVM lanza una excepción (capítulo 26) y, si nadie la atiende, el programa se detiene. Por ejemplo, una fila del totito tiene tres casillas (posiciones 0, 1 y 2); pedir la posición 3:

public class CasillaFuera {
    public static void main(String[] args) {
        char[] fila = {'X', 'O', ' '};
        System.out.println("Primera casilla: " + fila[0]);
        System.out.println("Cuarta casilla: " + fila[3]);
    }
}
Primera casilla: X
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at CasillaFuera.main(CasillaFuera.java:5)

Fíjate: la primera línea sí se imprimió; el programa corrió hasta la línea 5 y ahí murió. El mensaje dice qué pasó (índice 3 fuera de rango para longitud 3) y la última línea, llamada traza de la pila (stack trace), dice dónde: CasillaFuera.java:5. Este es exactamente el error que el Totito evita en marcarCasilla al comprobar fila < 0 || fila > 2 antes de tocar la matriz.

Hay un tercer tipo, el más traicionero: el error de lógica. El programa compila y corre sin quejarse, pero hace otra cosa de la que querías; por ejemplo, que la IA juegue en una casilla ocupada porque olvidaste comprobarla. Nadie te avisa: lo descubres probando. Para eso existen el capítulo 32 (probar la lógica en consola) y el 62 (el depurador).

Cómo leer un error sin asustarte. 1) Mira solo el primer error: muchas veces los siguientes son consecuencia de él. 2) Ve a la línea indicada y a la anterior (un ; que falta en la línea 3 a veces se reporta en la 4). 3) Copia la frase clave en inglés (cannot find symbol) en un buscador: alguien la tuvo antes. El apéndice D recoge los más frecuentes.

Lo mismo, en NetBeans

Lo que hiciste a mano es lo que NetBeans hace al pulsar Clean and Build (Shift+F11): llama a javac para cada archivo de src\ y deja los .class en target\classes. Run Project (F6) llama a java con la clase principal. Y el subrayado rojo que aparece mientras escribes es NetBeans ejecutando el compilador continuamente por debajo, para avisarte antes. Si alguna vez NetBeans «se vuelve loco», saber hacerlo a mano te permite comprobar dónde está el problema: javac -encoding UTF-8 -d out src\*.java y java -cp out TotitoApp desde la carpeta del proyecto, como en el capítulo 5.

En JDK 21 los archivos fuente se leen como UTF-8 por defecto, así que las tildes y la «ñ» funcionan. Si alguna vez ves letras raras (Ã¡ en lugar de á), añade -encoding UTF-8 a javac y asegúrate de que tu editor guardó el archivo en UTF-8 (en el Bloc de notas, abajo a la derecha de la ventana).

Resumen

  • Escribes código fuente (.java), javac lo revisa y lo traduce a bytecode (.class), y la JVM lo ejecuta. El mismo .class sirve en cualquier sistema con JVM.
  • El JDK (para programar) incluye el JRE (para ejecutar), que incluye la JVM.
  • Un programa empieza en public static void main(String[] args): público para que la JVM lo vea, estático para llamarlo sin crear objetos, void porque no devuelve nada, y args con lo que escribas tras el nombre de la clase.
  • Llaves = bloques; paréntesis = parámetros, llamadas y condiciones; corchetes = arreglos; ; = fin de sentencia; punto = «de dentro de»; comillas dobles = texto, simples = un carácter.
  • jshell ejecuta Java línea a línea y con /open carga clases del Totito para probarlas.
  • Comentarios: // de una línea, /* */ de varias, /** */ Javadoc para documentar.
  • Todo archivo del Totito sigue la misma anatomía: imports, Javadoc, clase, campos, constructor, métodos.
  • Errores de compilación los da javac antes de correr; errores de ejecución (excepciones) los da la JVM al correr; los de lógica, solo probando.
Aplícalo fuera del Totito
  • Herramientas de línea de comandos. Con main y args puedes hacer un programa que reciba un nombre de archivo (java ContarLineas notas.txt) o un número (java Tabla 7, que imprima la tabla del 7). Es la base de utilidades como git o javac mismos.
  • Probar una idea en jshell antes de escribirla. En cualquier proyecto (una calculadora de cuotas, un sistema de inventario) prueba la fórmula en jshell y, cuando funcione, pásala al archivo.
  • Leer código ajeno. La anatomía imports → clase → campos → constructor → métodos es la de cualquier proyecto Java profesional, desde una app de Android hasta un servidor con Spring Boot. Empieza siempre por el Javadoc de la clase.
  • Diagnosticar fallos en otros programas. Una traza de pila (Exception in thread "main" … at Clase.metodo(Archivo.java:N)) aparece igual en cualquier aplicación Java, incluido Minecraft Java Edition; ya sabes leerla.
