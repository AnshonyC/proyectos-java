Capítulo 12Variables, tipos y operadores

Un programa que no recuerda nada no puede jugar al totito: necesita saber qué hay en cada casilla, de quién es el turno y cuántas partidas lleva ganadas cada uno. En este capítulo aprendes a guardar datos en variables, a elegir el tipo correcto para cada dato (y por qué la ficha del Totito es un char y no un texto) y a hacer cuentas con ellos, incluidas las cuentas con decimales que dibujan el tablero.

Qué es una variable

Una variable es un espacio con nombre en la memoria de la computadora donde se guarda un dato que puede cambiar mientras el programa corre. Piensa en una caja con una etiqueta: la etiqueta es el nombre (victorias), lo que hay dentro es el valor (3) y la forma de la caja es el tipo: una caja para números enteros no admite un texto, igual que en un monedero no cabe una sandía.

En el Totito hay variables por todas partes. En Partida.java:

private int empates;
/** Indice (0 o 1) del jugador al que le toca. */
private int turno;

Cada partida empatada, empates aumenta en uno; cada jugada válida, turno cambia de 0 a 1 o de 1 a 0. Ese «cambiar» es lo que hace que sean variables.

Declarar, asignar, inicializar

public class Variable {
    public static void main(String[] args) {
        int victorias;             // 1) declarar: reservar la caja
        victorias = 0;             // 2) asignar: guardar un valor
        System.out.println("Al empezar: " + victorias);
        victorias = victorias + 1; // leer, sumar y volver a guardar
        System.out.println("Tras ganar una: " + victorias);
        int empates = 2;           // declarar e inicializar a la vez
        int partidas = victorias + empates;
        System.out.println("Partidas jugadas: " + partidas);
        empates = 5;
        System.out.println("partidas sigue valiendo " + partidas);
    }
}
Al empezar: 0
Tras ganar una: 1
Partidas jugadas: 3
partidas sigue valiendo 3
  • Declarar (int victorias;) es decirle a Java «necesito una caja de tipo int llamada victorias». Primero va el tipo, después el nombre, y termina en ;.
  • Asignar (victorias = 0;) es guardar un valor. El signo = en Java no significa «es igual a» como en matemáticas; significa «guarda lo de la derecha en la caja de la izquierda». Por eso victorias = victorias + 1; tiene sentido: primero se calcula la derecha con el valor viejo (0 + 1) y el resultado (1) se guarda en la caja, reemplazando lo que había.
  • Inicializar es asignar el primer valor. Se puede hacer en la misma línea que la declaración: int empates = 2;.
  • La última línea demuestra algo importante: partidas guardó el resultado de la suma (3) en el momento de calcularla, no la fórmula. Cambiar empates después no la recalcula. Una variable no es una celda de Excel con fórmula: es una caja con un valor.
Java no te deja leer una variable local que nunca recibió valor. Si escribes int victorias; y enseguida System.out.println(victorias);, el compilador protesta: error: variable victorias might not have been initialized. Es una protección: en otros lenguajes leerías «basura» que quedó en esa memoria. (Los campos de una clase, como empates en Partida, son distintos: Java los pone automáticamente en 0, false o null; lo verás en el capítulo 18.)

Los tipos: qué forma tiene cada caja

Java es un lenguaje de tipado estático: cada variable tiene un tipo fijo desde que se declara y el compilador comprueba que nunca le metas algo de otro tipo. Puede parecer rígido, pero atrapa montones de errores antes de ejecutar. Java tiene ocho tipos primitivos (los «átomos» del lenguaje, en minúscula) y, encima de ellos, todas las clases, como String.

int: el caballo de batalla

Casi todos los números del Totito son int: filas y columnas (0, 1, 2), el turno (0 o 1), las victorias, los milisegundos de pausa, los tamaños en píxeles de los botones (384, 88). Un int no puede tener decimales y tiene límites. ¿Qué pasa si te pasas?

public class Limites {
    public static void main(String[] args) {
        System.out.println("int va de " + Integer.MIN_VALUE + " a " + Integer.MAX_VALUE);
        System.out.println("long va de " + Long.MIN_VALUE + " a " + Long.MAX_VALUE);
        int maximo = Integer.MAX_VALUE;
        System.out.println("MAX_VALUE + 1 = " + (maximo + 1));
        long grande = Integer.MAX_VALUE;
        System.out.println("como long: " + (grande + 1));
        System.out.println("0.1 + 0.2 = " + (0.1 + 0.2));
    }
}

long va de -9223372036854775808 a 9223372036854775807

como long: 2147483648

Al sumar 1 al máximo, el int «da la vuelta» al mínimo, como el cuentakilómetros de un carro viejo que pasa de 99999 a 00000. Se llama desbordamiento (overflow) y Java no avisa. Con un long la cuenta sale bien. En el Totito nunca se llega ni cerca, pero si programas un sistema de ventas que suma centavos de todo un año, usa long.

Integer.MIN_VALUE y Integer.MAX_VALUE sí aparecen en el Totito, y con mucha intención. En IA_Minimax:

int mejorValor = Integer.MIN_VALUE;

La IA busca la jugada de puntaje más alto. Para empezar a comparar necesita un «récord» inicial que cualquier jugada real supere; el número más pequeño que existe es perfecto: hace de «menos infinito». Es como empezar a buscar al más alto de la clase anotando «estatura récord: 0 cm». Lo verás funcionar en el capítulo 31.

Para escribir un long grande a mano se le pone una L al final: long poblacion = 8_000_000_000L;. Los guiones bajos dentro de un número están permitidos y solo sirven para leerlo mejor, como los separadores de miles.

double y float: números con decimales

Para dibujar, los enteros no bastan: el centro de una casilla puede caer en el píxel 268.5. Por eso PanelTablero calcula sus medidas con double:

private double tamCasilla() {
    return (getWidth() - 2.0 * (MARGEN + RELLENO)) / 3.0;
}

En Java un número escrito con punto decimal, como 3.0, es double por defecto (el separador decimal siempre es el punto, nunca la coma). Si quieres un float, tienes que añadir una f: 1.5f. ¿Por qué existe float si double es más preciso? Porque gasta la mitad de memoria y muchas bibliotecas gráficas lo prefieren. Java2D, la parte de Java que dibuja, pide float para el grosor de las líneas; por eso en el Totito verás llamadas como:

Dibujo.trazoNeon(g2, marco, Tema.MORADO, 1.5f, 0.8f);

Si olvidas la f, el compilador no te deja seguir, porque meter un double en una caja float podría perder precisión:

FloatMal.java:3: error: incompatible types: possible lossy conversion from double to float
        float grosor = 1.5;
                       ^
Los decimales no son exactos. Como viste arriba, 0.1 + 0.2 da 0.30000000000000004. La computadora guarda los decimales en binario, y 0.1 en binario tiene infinitas cifras (como 1/3 en decimal: 0.3333…), así que se redondea. Para dibujar da igual (nadie ve una milmillonésima de píxel), pero nunca uses double para dinero: en un sistema de facturación se usan centavos en un long, o la clase BigDecimal. Y nunca compares decimales con ==: 0.1 + 0.2 == 0.3 da false.

boolean: sí o no

Un boolean (en honor al matemático George Boole) solo puede valer true (verdadero) o false (falso). Es el tipo de las preguntas de sí o no: «¿el tablero se puede pulsar?» (interactivo), «¿está lleno?», «¿fue válida la jugada?». En Tablero, marcarCasilla devuelve un boolean que dice si se pudo colocar la ficha, y tableroLleno() otro que dice si quedan casillas. Toda comparación produce un boolean, como verás en un momento, y todas las decisiones del capítulo 13 se toman con ellos.

Nombra los boolean como preguntas o estados: juegoTerminado, esComputadora, resaltado, sePuedeJugar. Así, al leer if (sePuedeJugar), el código suena a español.

char: por qué la ficha es un carácter

Un char guarda un solo carácter y se escribe entre comillas simples: 'X', 'O', ' '. En el Totito, toda ficha es un char: el campo ficha de Jugador, cada casilla de la matriz char[][] casillas y la constante VACIA = ' ' (un espacio). ¿Por qué no un String como "X"?

  1. Es exactamente lo que el dato es. Una casilla contiene una X, una O o nada: un símbolo, nunca una palabra. El tipo documenta la intención: quien lea char ficha sabe que ahí no cabe "Equis".
  2. Se compara con == sin trampas. casillas[0][0] == casillas[1][1] compara dos caracteres directamente. Con String, == no compara el contenido sino otra cosa (lo verás en el capítulo 17) y habría que usar equals en cada una de las muchas comparaciones de verificarGanador.
  3. Es ligero. Un char ocupa 2 bytes. Minimax crea cientos de miles de copias del tablero mientras piensa (capítulo 31); con caracteres eso es rapidísimo.
  4. Tiene un valor «vacío» claro. ' ' se dibuja bien en consola (capítulo 32) y no da problemas, a diferencia de un String que podría ser null.

Por dentro, un char es un número: el código del carácter en la tabla Unicode (el catálogo mundial que da un número a cada letra de cada idioma). Eso tiene consecuencias curiosas:

public class LaFicha {
    public static void main(String[] args) {
        char ficha = 'X';
        char vacia = ' ';
        System.out.println("ficha: " + ficha + "  su codigo: " + (int) ficha);
        System.out.println("'O' tiene el codigo " + (int) 'O');
        System.out.println("la casilla vacia ' ' tiene el codigo " + (int) vacia);
        System.out.println("ficha == 'X'? " + (ficha == 'X'));
        System.out.println("ficha == 'x'? " + (ficha == 'x'));
        char siguiente = (char) (ficha + 1);
        System.out.println("la letra que sigue a X es " + siguiente);
        System.out.println("'X' + 'O' = " + ('X' + 'O'));
        System.out.println("\"\" + 'X' + 'O' = " + ("" + 'X' + 'O'));
    }
}

Fíjate en las dos últimas: sumar dos char suma sus códigos (88 + 79 = 167), no los pega. Para pegarlos hace falta que en la suma haya un texto, aunque sea vacío (""). Y la X mayúscula no es la x minúscula: códigos distintos. El \" dentro del texto es una secuencia de escape: como las comillas terminan el texto, para escribir unas comillas dentro se les pone una barra invertida delante. Otras útiles: \n (salto de línea) y \\ (una barra invertida, como en las rutas de Windows).

Comillas simples o dobles. 'X' es un char; "X" es un String de longitud 1. Son tipos distintos y no se pueden mezclar libremente: char ficha = "X"; no compila. Es como la diferencia entre una ficha física del totito y una tarjeta que dice «X».

String: el texto

String se escribe con mayúscula porque no es primitivo: es una clase que viene con Java, y cada texto es un objeto. Por eso tiene métodos (nombre.length(), nombre.trim()…). Su capítulo es el 17; por ahora te basta saber que se escribe entre comillas dobles y que el + lo pega con lo que sea: "Turno de " + enTurno.getNombre() es como PantallaJuego arma el letrero «Turno de Ana».

Nombres de variables

Reglas que obliga Java: el nombre empieza por letra (o _ o $), luego letras, dígitos o _; sin espacios ni guiones; no puede ser una palabra reservada (int, class…); y distingue mayúsculas (fila y Fila son dos variables distintas). Java admite tildes y eñes en los nombres, pero la costumbre (y la del Totito) es no usarlas en el código: tamano, no tamaño.

Convenciones que esperan los demás programadores: variables y métodos en camelCase (filaEncima, columnaEncima, mejorValor), constantes en mayúsculas (PAUSA_RESULTADO_MS).

Operadores aritméticos

public class Aritmetica {
    public static void main(String[] args) {
        System.out.println("7 + 2 = " + (7 + 2));
        System.out.println("7 - 2 = " + (7 - 2));
        System.out.println("7 * 2 = " + (7 * 2));
        System.out.println("7 / 2 = " + (7 / 2));
        System.out.println("7.0 / 2 = " + (7.0 / 2));
        System.out.println("7 % 2 = " + (7 % 2));
        System.out.println("8 % 3 = " + (8 % 3));

        // El turno del Totito: 0 -> 1 -> 0 -> 1 ...
        int turno = 0;
        turno = 1 - turno;
        System.out.println("turno despues de una jugada: " + turno);
        turno = 1 - turno;
        System.out.println("turno despues de otra: " + turno);

        // Casilla numero 0..8 convertida a fila y columna
        int casilla = 7;
        System.out.println("casilla 7 -> fila " + (casilla / 3) + ", columna " + (casilla % 3));

        // Contadores
        int empates = 0;
        empates++;
        empates++;
        System.out.println("empates = " + empates);
        int puntos = 10;
        puntos += 5;
        puntos -= 3;
        puntos *= 2;
        System.out.println("puntos = " + puntos);
    }
}

  • + - *: suma, resta, multiplicación (el asterisco, no la x).
  • / entre dos enteros es división entera: corta los decimales. 7 / 2 da 3, no 3.5. Basta con que uno de los dos sea decimal (7.0 / 2) para obtener 3.5. Por eso tamCasilla() escribe 2.0 y 3.0 en lugar de 2 y 3: si el tablero mide 337 píxeles, cada casilla debe medir 100.33…, no 100.
  • % es el resto (módulo) de la división entera: 7 % 2 es 1 porque 7 = 2×3 + 1. Sirve para tres cosas que verás en todos lados: saber si un número es par (n % 2 == 0; Iconos lo usa para alternar las puntas largas y cortas de la estrella), «dar la vuelta» (las horas del reloj: (hora + 1) % 12) y repartir en filas y columnas: la casilla número 7 de un tablero numerado del 0 al 8 está en la fila 7 / 3 = 2, columna 7 % 3 = 1.
  • turno = 1 - turno: el truco que usa Partida.jugar para pasar el turno. Si vale 0 queda en 1; si vale 1 queda en 0. Una sola cuenta, sin preguntar nada.
Dividir un entero entre cero detiene el programa (ArithmeticException: / by zero). Dividir un decimal entre cero no falla, pero da Infinity, que luego contamina todas las cuentas. Si un divisor puede ser cero, compruébalo antes.

Atajos: ++, --, += y compañía

Sumar uno es tan frecuente que tiene su propio operador: empates++ equivale a empates = empates + 1. El Totito lo usa en Partida.jugar para el marcador: empates++; y victorias[turno]++; (suma una victoria al jugador en turno). Su opuesto es --: el bucle del halo en Dibujo.trazoNeon cuenta hacia atrás con i--.

Los operadores compuestos +=, -=, *=, /=, %= aplican la operación y guardan: puntos += 5 es puntos = puntos + 5. Dibujo.textoNeon recorre los ángulos de 45 en 45 grados con angulo += 45.

a++ o ++a. Escritos solos en su línea dan igual. Dentro de otra expresión no: int b = a++; guarda en b el valor antiguo y luego suma; int d = ++c; suma primero y guarda el nuevo. Con a = 5 y c = 5, el resultado es a = 6, b = 5 y c = 6, d = 6. Para no confundirte, usa ++ siempre en una línea propia, como hace el Totito.

La línea boolean fuera = fila < 0 || fila > 2; es casi la primera comprobación de Tablero.marcarCasilla. El || significa «o» (capítulo 13): la fila 3 está fuera del tablero, y por eso marcarCasilla(3, 0, 'X') devuelve false sin tocar la matriz. Las dos últimas líneas muestran que el + se evalúa de izquierda a derecha: mientras ve números, suma; en cuanto aparece un texto, pega. Por eso en este libro las cuentas dentro de un println siempre van entre paréntesis.

= asigna, == compara. if (turno = 1) es un error; lo correcto es if (turno == 1). Por suerte, en Java el compilador casi siempre te avisa (incompatible types: int cannot be converted to boolean).

Precedencia: quién va primero

Igual que en matemáticas, en 2 + 3 * 4 se multiplica antes de sumar: da 14, no 20. Java sigue un orden de precedencia; los más comunes, de mayor a menor:

OrdenOperadores
1Paréntesis ( ), acceso con punto ., corchetes [ ], llamadas a métodos
2++ -- !, signo menos -x, casting (int)
3* / %
4+ -
5< > <= >=
6== !=
7&&, después ||
8? : (ternario, capítulo 13)
9= += -= … (la asignación, siempre al final)

Los del mismo nivel se hacen de izquierda a derecha: 10 - 4 - 3 es (10 - 4) - 3 = 3. Veámoslo con las cuentas reales de PanelTablero, que calcula el tamaño del tablero y el centro de cada columna:

public class Medidas {
    public static void main(String[] args) {
        final int MARGEN = 10;    // como en PanelTablero
        final int RELLENO = 8;
        int tamCasilla = 100;

        // Lado del tablero: lo mismo que calcula el constructor de PanelTablero
        int lado = 2 * (MARGEN + RELLENO) + 3 * tamCasilla;
        System.out.println("lado del tablero = " + lado);
        int sinParentesis = 2 * MARGEN + RELLENO + 3 * tamCasilla;
        System.out.println("sin parentesis   = " + sinParentesis);

        // Centro de la columna 2, como centroX(2)
        double tam = (lado - 2.0 * (MARGEN + RELLENO)) / 3.0;
        double centroX = MARGEN + RELLENO + (2 + 0.5) * tam;
        System.out.println("tam = " + tam + ", centro de la columna 2 = " + centroX);
    }
}
lado del tablero = 336
sin parentesis   = 328
tam = 100.0, centro de la columna 2 = 268.0

Paso a paso: 2 * (MARGEN + RELLENO) + 3 * tamCasilla → primero el paréntesis, 10 + 8 = 18 → luego las multiplicaciones, 2 * 18 = 36 y 3 * 100 = 300 → al final la suma, 336. Es lógico: el tablero lleva margen y relleno a los dos lados (por eso ×2) más tres casillas. Sin el paréntesis, el 2 solo multiplica al margen y el resultado es 328: un tablero 8 píxeles más estrecho de lo debido, con la última columna recortada. Un error así no lo detecta el compilador; lo ves en la pantalla.

Otro ejemplo, el halo de trazoNeon: int alfa = Math.round((6 + (capas - i) * 5) * intensidad); Con capas = 6, intensidad = 1 y la capa i = 1: (6 - 1) = 5 → 5 * 5 = 25 → 6 + 25 = 31 → 31 * 1 = 31. Para i = 6 sale 6. Así, la capa más ancha es casi invisible (alfa 6 de 255) y la más fina, más opaca (31): eso es el resplandor.

Ante la duda, pon paréntesis. No cuestan nada, no hacen el programa más lento y dejan clara tu intención a quien lea. El código del Totito los usa incluso cuando no hacen falta, como en (capas - i) * 5.

Conversiones y casting

A veces tienes un dato de un tipo y lo necesitas en otro. Hay dos casos:

Ampliar: automático

Pasar de un tipo «pequeño» a uno «grande» (int → long, int → double, float → double) nunca pierde información, así que Java lo hace solo: double ancho = 3; guarda 3.0. También ocurre dentro de las cuentas: en MARGEN + RELLENO + (columna + 0.5) * tamCasilla() los enteros se convierten a double en cuanto se encuentran con uno.

Reducir: casting explícito

Pasar de grande a pequeño (double → int, double → float) puede perder información, así que Java exige que lo pidas por escrito, poniendo el tipo destino entre paréntesis delante: (int) 2.99. A eso se le llama casting (o «conversión de tipo»). Es tu firma diciendo «sé que puedo perder algo, y está bien».

public class Casting {
    public static void main(String[] args) {
        // Ampliar: automatico, no se pierde nada
        int entero = 3;
        double ancho = entero;
        System.out.println("int 3 como double: " + ancho);

        // Reducir: hay que pedirlo con (tipo) y se pueden perder decimales
        double tam = 100.0;
        float grosor = (float) Math.max(3, tam * 0.085);
        System.out.println("grosor de las fichas: " + grosor);
        System.out.println("(int) 2.99 = " + (int) 2.99);
        System.out.println("(int) -0.08 = " + (int) -0.08);
        System.out.println("Math.floor(-0.08) = " + Math.floor(-0.08));
        System.out.println("Math.round(2.5f) = " + Math.round(2.5f));

        // Que columna hay bajo el raton? (actualizarCasillaEncima de PanelTablero)
        int x = 250;
        System.out.println("x = 250 -> columna " + (int) Math.floor((x - 18) / tam));
        x = 10;
        System.out.println("x = 10  -> con floor: " + (int) Math.floor((x - 18) / tam)
                + ", solo con (int): " + (int) ((x - 18) / tam));
    }
}

grosor de las fichas: 8.5
(int) 2.99 = 2
(int) -0.08 = 0
Math.floor(-0.08) = -1.0
Math.round(2.5f) = 3
x = 250 -> columna 2
x = 10  -> con floor: -1, solo con (int): 0

Lo que enseña este programa:

  • (float) Math.max(3, tam * 0.085) es la línea exacta de PanelTablero.paintComponent que calcula el grosor de las fichas: 8.5 % del tamaño de la casilla, pero nunca menos de 3 píxeles (Math.max devuelve el mayor de los dos). Math.max devuelve double y los trazos piden float: de ahí el casting.
  • (int) corta, no redondea: (int) 2.99 es 2. Y corta hacia el cero: (int) -0.08 es 0.
  • Math.floor redondea hacia abajo (hacia menos infinito): Math.floor(-0.08) es -1.0.
  • Math.round redondea al más cercano, y con un float devuelve directamente un int (por eso trazoNeon lo usa para el alfa).

La última parte explica una línea que parece rebuscada en PanelTablero.actualizarCasillaEncima:

int columna = (int) Math.floor((x - MARGEN - RELLENO) / tam);

Para saber sobre qué columna está el ratón se resta el borde (18 píxeles) y se divide entre el tamaño de la casilla: en x = 250, (250 − 18) / 100 = 2.32 → columna 2. Pero si el ratón está en el borde izquierdo, en x = 10, sale −0.08. Con solo (int) daría 0, y el juego resaltaría la columna 0 aunque el ratón esté fuera de la rejilla. Con Math.floor da −1, que el código siguiente reconoce como «fuera» (columna >= 0 es falso). Un detalle de una palabra que evita un error visible.

Casting de objetos. Los paréntesis también convierten entre clases: en Dibujo.preparar, (Graphics2D) g.create() le dice a Java «este objeto Graphics es en realidad un Graphics2D, más completo». Es otro tipo de conversión, que entenderás con la herencia (capítulos 22 y 23).

Números en hexadecimal

En Tema.java los colores se escriben así: new Color(0x1C, 0x17, 0x40). El prefijo 0x indica un número en hexadecimal (base 16, con dígitos 0–9 y A–F): 0x1C es 28 y 0xFF es 255. Se usa porque los diseñadores escriben los colores como #1C1740, y así el código se parece al diseño. Para Java, 0x1C y 28 son exactamente el mismo int. El capítulo 35 explica los colores a fondo.

Constantes con final

Un valor que no debe cambiar nunca se declara con final: se le da valor una vez y el compilador impide cualquier otra asignación. En el Totito:

public static final char VACIA = ' ';                 // Tablero
private static final int MARGEN = 10;   // espacio para el halo del borde (PanelTablero)
private static final int PAUSA_IA_MS = 450;           // PantallaJuego

(static significa que la constante pertenece a la clase y hay una sola para todos, capítulo 20.) Si alguien intenta cambiarla:

ConstanteMal.java:5: error: cannot assign a value to static final variable VACIA
        VACIA = '-';
        ^

¿Para qué sirven, si podrías escribir ' ' o 450 directamente?

  • Dan nombre al número. esperar(PAUSA_IA_MS, …) se entiende; esperar(450, …) obliga a adivinar qué es 450. A los números sueltos sin explicación se les llama «números mágicos» (capítulo 27).
  • Un solo lugar para cambiarlo. Si la IA te parece lenta, cambias 450 por 300 en una línea y afecta a todo el juego. Si cambiaras la casilla vacía de ' ' a '-', con la constante lo haces en un sitio; sin ella tendrías que encontrar cada ' ' (y no confundirlo con los espacios de los textos).
  • Protegen. Nadie puede cambiar el valor por accidente a mitad del programa.

final también se usa en variables que no son constantes «globales»: en Jugador, private final char ficha; significa que, una vez creado el jugador, su ficha no cambia nunca. Y en trazoNeon, final int capas = 6; es una variable local que no se va a modificar.

var: que Java deduzca el tipo

Desde Java 10 puedes escribir var en lugar del tipo cuando el valor inicial ya lo deja claro:

public class Constantes {
    static final char VACIA = ' ';
    static final int PAUSA_IA_MS = 450;

    public static void main(String[] args) {
        System.out.println("La IA espera " + PAUSA_IA_MS + " ms");
        System.out.println("Casilla vacia: [" + VACIA + "]");
        var nombre = "Totito";      // Java deduce: String
        var victorias = 3;          // Java deduce: int
        System.out.println(nombre + " lleva " + victorias + " victorias");
    }
}
La IA espera 450 ms
Casilla vacia: [ ]
Totito lleva 3 victorias

var no hace que la variable acepte cualquier cosa: victorias sigue siendo un int para siempre, solo que no lo escribiste. Solo vale para variables locales (dentro de un método) y que se inicializan en la misma línea. Es cómodo con tipos largos: var raton = new MouseAdapter() { … }. El Totito no lo usa a propósito: para alguien que aprende, ver Tablero copia = tablero.obtenerCopia(); con el tipo escrito ayuda a entender qué es cada cosa. Úsalo cuando el tipo sea obvio por la derecha de la línea.

Resumen

  • Una variable es una caja con nombre y tipo. Se declara (int turno;), se asigna (turno = 0;) y el = significa «guarda», no «es igual».
  • Tipos que usa el Totito: int para filas, turnos y contadores; double y float para medidas de dibujo; boolean para sí/no; char para las fichas; String para nombres.
  • La ficha es char porque es un único símbolo, se compara con == sin trampas y es ligera para Minimax.
  • / entre enteros corta los decimales; % da el resto (pares, vueltas, fila/columna). turno = 1 - turno alterna 0 y 1.
  • ++, --, +=… son atajos; las comparaciones dan boolean; = asigna y == compara.
  • La precedencia decide el orden de las cuentas; un paréntesis olvidado cambia el resultado sin que el compilador lo note.
  • Ampliar tipos es automático; reducir exige casting ((int), (float)), que corta hacia el cero; Math.floor y Math.round redondean de otras formas.
  • final crea constantes con nombre; var deja que Java deduzca el tipo de una variable local.
Aplícalo fuera del Totito
  • Un punto de venta. Precios en centavos con long (nunca double), cantidad de productos con int, «¿pagó con tarjeta?» con boolean, y el impuesto como constante: static final int IVA_PORCENTAJE = 12;.
  • Convertir tiempos. Con / y % pasas segundos a minutos y segundos: int minutos = total / 60; int segundos = total % 60;. Es lo mismo que convertir la casilla 7 a fila 2, columna 1.
  • Cualquier cuadrícula en pantalla (un calendario, un Buscaminas, una galería de fotos): el cálculo «posición del ratón → celda» con Math.floor de PanelTablero sirve tal cual.
  • Configuración con nombre. En un juego de plataformas, GRAVEDAD, VELOCIDAD_SALTO y VIDAS_INICIALES como constantes final permiten ajustar la dificultad en un solo lugar.
