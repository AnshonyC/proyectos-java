Capítulo 14Repeticiones

El tablero tiene nueve casillas, hay ocho líneas posibles de victoria y la IA prueba cientos de miles de jugadas antes de mover. Nadie escribe eso instrucción por instrucción: se escribe una vez y se repite. En este capítulo aprendes los bucles de Java (for, while, do-while y for-each), a recorrer el tablero 3×3 con dos bucles anidados siguiendo cada paso, y a controlar cuándo parar.

Por qué repetir

Para dejar el tablero vacío hay que poner un espacio en las nueve casillas. Sin bucles serían nueve líneas casi iguales:

casillas[0][0] = VACIA;
casillas[0][1] = VACIA;
casillas[0][2] = VACIA;
casillas[1][0] = VACIA;
// ... y cinco mas

Funciona, pero es aburrido, fácil de equivocarse (¿te saltaste alguna?) y no escala: un tablero de Conecta 4 tiene 42 casillas y uno de ajedrez, 64. Un bucle (en inglés loop) es una estructura que repite un bloque de código mientras se cumpla una condición. Cada repetición se llama iteración o «vuelta».

Analogía: lavar los platos. No piensas «lavo el plato 1, lavo el plato 2…». Piensas: «mientras quede un plato sucio, toma uno y lávalo». Hay una condición (quedan platos), un cuerpo (lavar uno) y algo que avanza hacia el final (cada vez queda uno menos). Si lo que avanza no avanzara (por ejemplo, si alguien te trae un plato sucio cada vez que lavas uno), no terminarías nunca. Todos los bucles tienen estas tres piezas.

El bucle for

Es el más usado cuando sabes cuántas vueltas quieres dar. Su forma:

for (inicializacion; condicion; actualizacion) {
    // cuerpo: lo que se repite
}

Un ejemplo mínimo que recorre las tres filas del tablero:

public class ForBasico {
    public static void main(String[] args) {
        for (int fila = 0; fila < 3; fila++) {
            System.out.println("Revisando la fila " + fila);
        }
        System.out.println("Listo");
    }
}

Revisando la fila 1

Listo

Las tres partes, una por una

  • int fila = 0 (inicialización): se ejecuta una sola vez, antes de la primera vuelta. Crea la variable de control, el «contador», y le da su valor inicial. Empieza en 0 porque las filas del tablero se numeran 0, 1 y 2 (capítulo 15 explica por qué Java cuenta desde cero).
  • fila < 3 (condición): se evalúa antes de cada vuelta. Si es true, se ejecuta el cuerpo; si es false, el bucle termina y el programa sigue después de la llave de cierre. Con < 3 las vueltas son para 0, 1 y 2: exactamente tres.
  • fila++ (actualización): se ejecuta después de cada vuelta, justo antes de volver a evaluar la condición. Es lo que hace avanzar al bucle hacia su final.

Los ; dentro del paréntesis separan las tres partes. Fíjate en que no hay ; después del paréntesis: igual que con el if, un ; ahí dejaría el bucle vacío.

Observa dos cosas. La condición se evaluó cuatro veces (tres true y una false), el cuerpo tres. El error «uno de más» o «uno de menos». for (int fila = 0; fila <= 3; fila++) da cuatro vueltas (0, 1, 2, 3), y la cuarta intentará leer la fila 3, que no existe. for (int fila = 1; fila < 3; fila++) da solo dos y se salta la fila 0. La forma segura y estándar para recorrer N elementos es siempre for (int i = 0; i < N; i++): empieza en 0 y usa <, no <=.

Contar de otras formas

Ni el inicio tiene que ser 0, ni el paso 1, ni el sentido hacia arriba. Dos bucles reales de Dibujo:

public class Pasos {
    public static void main(String[] args) {
        // Como Dibujo.textoNeon: de 45 en 45 grados
        for (int angulo = 0; angulo < 360; angulo += 45) {
            System.out.print(angulo + " ");
        }
        System.out.println();

        // Como Dibujo.trazoNeon: de la capa 6 a la 1, hacia atras

        for (int i = capas; i >= 1; i--) {
            float grosor = 2f + i * 2.4f;
            int alfa = 6 + (capas - i) * 5;
            System.out.println("capa " + i + ": grosor " + grosor + ", alfa " + alfa);
        }
    }
}

El segundo es el corazón del efecto neón. Cuenta hacia atrás (i--, condición i >= 1) por una razón de pintura: en una pantalla, lo que se dibuja después queda encima. Hay que pintar primero la capa más ancha y transparente (grosor 16.4, alfa 6) y terminar con la más fina y opaca (4.4, alfa 31), igual que un pintor pone primero el fondo y al final los detalles. (Y sí: 16.400002 es la imprecisión de los decimales del capítulo 12, que en un dibujo no importa.)

Bucles anidados: recorrer el tablero 3×3

El tablero tiene filas y columnas. Para visitar las nueve casillas se pone un for dentro de otro: el de fuera recorre las filas y, por cada fila, el de dentro recorre sus tres columnas. Es la estructura que más se repite en todo el Totito: está en reiniciar, tableroLleno, obtenerCopia, calcularMejorJugada, minimax (dos veces), PanelTablero.mostrar y paintComponent.

public class RecorrerTablero {
    public static void main(String[] args) {
        int vueltas = 0;
        for (int fila = 0; fila < 3; fila++) {
            for (int columna = 0; columna < 3; columna++) {
                vueltas++;
                System.out.println("vuelta " + vueltas + ": fila " + fila + ", columna " + columna);
            }
            System.out.println("-- termino la fila " + fila);
        }
    }
}

vuelta 2: fila 0, columna 1
vuelta 3: fila 0, columna 2
-- termino la fila 0
vuelta 4: fila 1, columna 0
vuelta 5: fila 1, columna 1
vuelta 6: fila 1, columna 2

vuelta 7: fila 2, columna 0

Traza paso a paso

  1. El bucle de fuera arranca: fila = 0; 0 < 3, entra.
  2. El bucle de dentro arranca desde cero: columna = 0. Da sus tres vueltas completas: (0,0), (0,1), (0,2). Cuando columna llega a 3, el bucle interior termina.
  3. Se ejecuta lo que hay después del bucle interior, dentro del exterior: «-- termino la fila 0».
  4. El de fuera actualiza: fila = 1; 1 < 3, entra otra vez.
  5. El de dentro vuelve a empezar con columna = 0 (su inicialización se ejecuta de nuevo cada vez que se llega a él): (1,0), (1,1), (1,2).
  6. Lo mismo para fila = 2. Después, fila = 3, la condición exterior es false y todo termina.

En total: 3 vueltas de fuera × 3 de dentro = 9 ejecuciones del cuerpo interior, una por casilla, en el orden en que lees un libro: de izquierda a derecha y de arriba abajo.

Analogía: el reloj. Los bucles anidados funcionan como las manecillas de un reloj: el minutero (bucle de dentro) da la vuelta completa de 60 por cada paso del horario (bucle de fuera). O como un cine: el acomodador recorre la fila A butaca por butaca, luego la fila B desde la butaca 1, y así.

Lo que el Totito hace con esos dos bucles

Un tablero de verdad se guarda en una matriz de caracteres, char[][] casillas: una tabla de 3×3 donde casillas[fila][columna] es la casilla de esa fila y columna. Los arreglos y matrices son el tema del capítulo 15; para este capítulo te basta esa idea. Este programa reproduce tres métodos del Totito: Tablero.reiniciar, PruebaConsola.imprimir y un conteo parecido a tableroLleno.

public class TableroConBucles {
    public static void main(String[] args) {
        final char VACIA = ' ';
        char[][] casillas = new char[3][3];

        // Tablero.reiniciar(): poner VACIA en las 9 casillas
        for (int fila = 0; fila < 3; fila++) {
            for (int columna = 0; columna < 3; columna++) {
                casillas[fila][columna] = VACIA;
            }
        }

        casillas[0][0] = 'X';
        casillas[1][1] = 'O';
        casillas[2][1] = 'X';

        // PruebaConsola.imprimir(): dibujar el tablero con caracteres
        for (int fila = 0; fila < 3; fila++) {
            System.out.println(" " + casillas[fila][0] + " | " + casillas[fila][1] + " | " + casillas[fila][2]);
            if (fila < 2) {
                System.out.println("---+---+---");
            }
        }

        // Contar casillas vacias
        int vacias = 0;
        for (int fila = 0; fila < 3; fila++) {
            for (int columna = 0; columna < 3; columna++) {
                if (casillas[fila][columna] == VACIA) {
                    vacias++;
                }
            }
        }
        System.out.println("Quedan " + vacias + " casillas vacias");
    }
}

Quedan 6 casillas vacias
  • Reiniciar: el cuerpo interior, casillas[fila][columna] = VACIA;, se ejecuta nueve veces, cada vez con una pareja (fila, columna) distinta. Las nueve líneas del principio del capítulo, en tres.
  • Imprimir: aquí basta un solo bucle, porque cada vuelta escribe una fila entera nombrando sus tres columnas a mano. El if (fila < 2) pone la raya separadora después de las filas 0 y 1, pero no después de la última. Es un patrón muy común: «separador entre elementos, pero no al final».
  • Contar: un acumulador (vacias) empieza en 0 fuera de los bucles y crece dentro. Si lo declararas dentro, se reiniciaría a 0 en cada vuelta y nunca contaría más de 1.

Tablero.tableroLleno es casi igual que el conteo, pero más listo: en cuanto encuentra una casilla vacía, ya sabe la respuesta y sale con return false;, sin mirar el resto. Solo si los dos bucles terminan sin encontrar ninguna llega al return true; del final.

public boolean tableroLleno() {
    for (int fila = 0; fila < 3; fila++) {
        for (int columna = 0; columna < 3; columna++) {
            if (casillas[fila][columna] == VACIA) {
                return false;
            }
        }
    }
    return true;
}

Un solo bucle que revisa dos cosas: verificarGanador

Tablero.verificarGanador usa un truco elegante: un solo for de i = 0 a 2 revisa, en cada vuelta, la fila i (casillas[i][0], [i][1], [i][2]) y la columna i (casillas[0][i], [1][i], [2][i]). Tres vueltas cubren las seis líneas rectas; las dos diagonales se revisan después, fuera del bucle, porque son solo dos y no siguen ese patrón. Este programa lo reproduce imprimiendo qué mira en cada vuelta (usa break, que verás enseguida, donde el método real usa return):

public class BuscarGanador {
    public static void main(String[] args) {
        final char VACIA = ' ';
        char[][] casillas = {
            {'X', 'O', ' '},
            {'X', 'O', ' '},
            {' ', 'O', 'X'}
        };
        char ganador = VACIA;
        // Como Tablero.verificarGanador: en la vuelta i se revisan la fila i y la columna i
        for (int i = 0; i < 3; i++) {
            System.out.println("vuelta " + i + ": fila " + i + " = [" + casillas[i][0] + casillas[i][1] + casillas[i][2]
                    + "], columna " + i + " = [" + casillas[0][i] + casillas[1][i] + casillas[2][i] + "]");
            if (casillas[i][0] != VACIA && casillas[i][0] == casillas[i][1] && casillas[i][1] == casillas[i][2]) {
                ganador = casillas[i][0];
                break;
            }
            if (casillas[0][i] != VACIA && casillas[0][i] == casillas[1][i] && casillas[1][i] == casillas[2][i]) {
                ganador = casillas[0][i];
                break;
            }
        }
        System.out.println("Ganador: [" + ganador + "]");
    }
}
vuelta 0: fila 0 = [XO ], columna 0 = [XX ]
vuelta 1: fila 1 = [XO ], columna 1 = [OOO]
Ganador: [O]

En la vuelta 0 ni la fila ni la columna 0 están completas. En la vuelta 1, la columna central tiene tres O: se encontró al ganador y el bucle se corta; la vuelta 2 nunca ocurre. (Nota: al sumar char después de un texto, se pegan; por eso "[" + 'O' + 'O' + 'O' + "]" da [OOO].)

Tres niveles: cuántas vueltas da la IA

En IA_Minimax, dentro de los dos bucles que recorren el tablero, se llama a minimax, que a su vez tiene otros dos bucles que vuelven a llamar a minimax… Cada nivel multiplica: con el tablero vacío hay 9 primeras jugadas, por cada una 8 respuestas, por cada una 7… Por eso la IA revisa cientos de miles de posiciones antes de su primera jugada. Ese «bucle que se llama a sí mismo» es la recursión del capítulo 16, y el algoritmo completo está en el capítulo 31.

Cuando anides bucles, multiplica las vueltas mentalmente antes de ejecutar. Dos bucles de 3 son 9 vueltas, pero dos bucles de 10 000 son cien millones. Es la primera pregunta que se hace un programador cuando un programa «va lento».

El bucle while

for es ideal cuando conoces el número de vueltas. Cuando no lo conoces («sigue mientras…»), se usa while («mientras»):

while (condicion) {
    // cuerpo
}

Solo tiene la condición: la inicialización va antes y la actualización dentro del cuerpo, a tu cargo. Un for es, de hecho, un while con las tres partes ordenadas en una línea; for (int i = 0; i < 3; i++) { … } equivale a int i = 0; while (i < 3) { …; i++; }.

Ejemplo real: Dibujo.recortar, que acorta un nombre demasiado largo para su tarjeta y le pone «…». No sabe de antemano cuántas letras sobran, así que quita una por una mientras no quepa. El original mide en píxeles con la fuente; esta versión mide en caracteres para poder probarla en consola:

public class Recortar {
    public static void main(String[] args) {
        String texto = "Maria Fernanda";
        int maximo = 10;   // caben 10 caracteres

        // Como Dibujo.recortar: quitar letras del final hasta que quepa con "…"
        String recortado = texto;
        while (recortado.length() > 1 && (recortado + "…").length() > maximo) {
            recortado = recortado.substring(0, recortado.length() - 1);
            System.out.println("  probando: " + recortado + "…");
        }
        System.out.println("Resultado: " + recortado + "…");
    }
}
  probando: Maria Fernand…
  probando: Maria Fernan…
  probando: Maria Ferna…
  probando: Maria Fern…
  probando: Maria Fer…
Resultado: Maria Fer…

substring(0, largo - 1) devuelve el texto sin su última letra (capítulo 17). Cada vuelta quita una; cuando «Maria Fer…» ya mide 10, la condición es false y el bucle para. La primera parte de la condición, recortado.length() > 1, es un seguro: si el espacio fuera ridículamente pequeño, el bucle se detiene con una letra en vez de seguir hasta dejar el texto vacío y fallar.

while (true): el bucle de un juego

Un juego en consola no sabe cuántas jugadas habrá: se repite «pide jugada, juega, revisa» hasta que alguien gane. PruebaConsola (capítulo 32) lo escribe así:

while (true) {
    System.out.print("Tu jugada: ");
    // ... leer fila y columna, jugar, imprimir ...
    if (terminoLaPartida(tablero)) {
        return;
    }
    // ... juega la IA ...
}

while (true) es un bucle cuya condición nunca se vuelve falsa: un bucle infinito a propósito. La salida está dentro: el return termina el método main (y con él el programa) cuando la partida acaba. Es un patrón legítimo cuando la condición de salida se conoce a mitad del cuerpo y no al principio. La ventana del Totito no necesita este bucle: Swing tiene el suyo propio, que espera clics (capítulo 37).

El bucle do-while

do-while es un while con la condición al final. La diferencia: el cuerpo se ejecuta al menos una vez, porque se pregunta después de hacerlo.

do {
    // cuerpo: se ejecuta una vez seguro
} while (condicion);

Encaja cuando necesitas hacer algo para saber si tienes que repetirlo. Por ejemplo, una IA «tonta» que, en lugar de pensar como Minimax, elige casillas al azar hasta dar con una libre: primero hay que elegir, y solo después se puede comprobar si la casilla estaba vacía.

import java.util.Random;

public class IaAlAzar {
    public static void main(String[] args) {
        char[][] casillas = {
            {'X', 'O', 'X'},
            {'O', 'X', ' '},
            {' ', ' ', 'O'}
        };
        Random azar = new Random(11);   // semilla fija: siempre los mismos numeros
        int fila, columna;
        int intentos = 0;

        // Una IA "tonta": elige casillas al azar HASTA dar con una vacia
        do {
            fila = azar.nextInt(3);      // 0, 1 o 2
            columna = azar.nextInt(3);
            intentos++;
            System.out.println("intento " + intentos + ": (" + fila + ", " + columna + ") tiene '" + casillas[fila][columna] + "'");
        } while (casillas[fila][columna] != ' ');

        System.out.println("La IA tonta juega en (" + fila + ", " + columna + ")");
    }
}
intento 1: (0, 2) tiene 'X'
intento 2: (0, 0) tiene 'X'
intento 3: (0, 0) tiene 'X'
intento 4: (1, 2) tiene ' '
La IA tonta juega en (1, 2)
  • Random es una clase de Java que genera números al azar; nextInt(3) devuelve 0, 1 o 2. Viene en el paquete java.util, de ahí el import. La «semilla» 11 hace que salgan siempre los mismos números, para que tu salida coincida con la del libro; sin ella (new Random()) cada ejecución sería distinta.
  • fila y columna se declaran antes del do, no dentro: la condición del while está fuera de las llaves y necesita verlas.
  • Fíjate en el ; después de while (…): en do-while es obligatorio, al revés que en el while normal.
  • Repetir la (0, 0) dos veces es lo que hace el azar: no tiene memoria. Por eso esta IA es mala y el Totito usa Minimax.
Esta IA tiene un peligro: si el tablero estuviera lleno, ninguna casilla sería ' ' y el bucle no terminaría nunca. Antes de un bucle de «buscar hasta encontrar», asegúrate de que lo buscado existe (aquí, comprobando primero que el tablero no está lleno, como hace Partida antes de dejar jugar a la IA).

break y continue

Dos palabras para alterar el curso normal de un bucle desde dentro:

  • break («romper») sale del bucle inmediatamente, sin terminar la vuelta actual ni hacer las siguientes. Es el mismo break del switch clásico.
  • continue («continuar») abandona solo la vuelta actual y salta a la siguiente (en un for, pasa por la actualización).
public class BreakContinue {
    public static void main(String[] args) {
        char[] fila = {'X', 'O', ' ', 'X', ' '};

        // break: buscar la PRIMERA casilla vacia y dejar de buscar
        int primeraVacia = -1;
        for (int i = 0; i < fila.length; i++) {
            System.out.println("miro la posicion " + i);
            if (fila[i] == ' ') {
                primeraVacia = i;
                break;
            }
        }
        System.out.println("Primera vacia: " + primeraVacia);

        // continue: saltar las ocupadas y procesar solo las vacias
        for (int i = 0; i < fila.length; i++) {
            if (fila[i] != ' ') {
                continue;
            }
            System.out.println("La posicion " + i + " esta libre");
        }
    }
}
miro la posicion 0
miro la posicion 1
miro la posicion 2
Primera vacia: 2
La posicion 2 esta libre
La posicion 4 esta libre

Con break el bucle miró solo tres posiciones: en cuanto encontró lo que buscaba, dejó de trabajar. -1 como valor inicial es una convención para «no encontrado» (ninguna posición real es negativa); el Totito la usa en filaEncima = -1 para decir «el ratón no está sobre ninguna casilla». fila.length es el tamaño del arreglo (capítulo 15).

En el Totito, PruebaConsola usa continue cuando escribes una casilla inválida: imprime «Esa casilla no se puede usar. Prueba otra.» y salta al principio del while (true), para volver a pedir la jugada sin dejar jugar a la IA. Y en lugar de break, los métodos del Totito suelen salir con return, que es aún más drástico: no solo sale del bucle, sale del método entero (así lo hacen tableroLleno, verificarGanador y buscarLineaGanadora).

break sale solo del bucle más interno. Si estás en dos for anidados y haces break en el de dentro, el de fuera sigue con la siguiente fila. Para salir de los dos a la vez, lo más claro es poner los bucles en un método y usar return, como hace tableroLleno.

El for-each: «para cada elemento»

Muchas veces no te interesa la posición, solo cada elemento de una colección. Para eso existe el for mejorado o for-each:

for (Tipo elemento : coleccion) {
    // usa elemento
}

Los dos puntos se leen «en»: «para cada familia en FAMILIAS». No hay contador, ni condición, ni actualización: Java te va dando los elementos de uno en uno, del primero al último. El Totito lo usa tres veces:

  • Tema.elegirFamilia: for (String familia : FAMILIAS) prueba las fuentes preferidas en orden y se queda con la primera instalada.
  • Partida.buscarLineaGanadora: for (int[] l : lineas) revisa las 8 líneas posibles del tablero, cada una descrita por seis números.
  • PanelTablero: for (char[] fila : fichas) recorre las filas de la matriz para llenarlas de casillas vacías.
public class ParaCada {
    public static void main(String[] args) {
        String[] familias = {"Nunito", "Poppins", "Segoe UI", "Arial"};
        String instalada = "Segoe UI";

        // Como Tema.elegirFamilia: usar la primera fuente que exista
        for (String familia : familias) {
            System.out.println("¿Esta instalada " + familia + "?");
            if (familia.equals(instalada)) {
                System.out.println("Si: se usa " + familia);
                break;
            }
        }

        // Como Partida.buscarLineaGanadora: recorrer las lineas del tablero
        int[][] lineas = {
            {0, 0, 0, 1, 0, 2},
            {0, 0, 1, 1, 2, 2}
        };
        for (int[] l : lineas) {
            System.out.println("linea de (" + l[0] + "," + l[1] + ") a (" + l[4] + "," + l[5] + ")");
        }
    }
}

Bucles infinitos: cómo se producen y cómo evitarlos

Un bucle infinito es uno cuya condición nunca llega a ser falsa. El programa no da error: simplemente no termina, o se queda congelado. Las causas típicas:

  1. Olvidar avanzar. Un while sin la actualización: 
    public class BucleInfinito {
    public static void main(String[] args) {
        int fila = 0;
        while (fila < 3) {
            System.out.println("fila " + fila);
            // falta fila++: fila vale 0 para siempre
        }
    }
}
    fila 0
fila 0
fila 0
fila 0
...
    Imprime «fila 0» miles de veces por segundo hasta que lo detengas.
  2. Avanzar en el sentido equivocado. for (int i = 6; i >= 1; i++): i crece y siempre es mayor o igual que 1 (hasta que desborda, capítulo 12).
  3. Una condición que nunca cambia. Buscar al azar una casilla vacía en un tablero lleno, como viste arriba.
  4. Modificar el contador dentro del cuerpo de un for, de forma que nunca alcanza el límite. Regla: en un for, el contador solo lo toca la actualización.

Cómo detenerlo: en PowerShell, pulsa Ctrl+C. En NetBeans, el botón cuadrado rojo de la ventana Output (o Run → Stop Build/Run). Si el bucle está en una ventana de Swing, la ventana se congela (no responde a clics) porque el hilo que la dibuja está atrapado en el bucle; ciérrala desde NetBeans o con el Administrador de tareas.

Lista de comprobación de cualquier bucle: 1) ¿Dónde empieza? 2) ¿Qué condición lo detiene? 3) ¿Qué cambia en cada vuelta que lo acerca a esa condición? Si no puedes señalar una línea concreta para la pregunta 3, tienes un bucle infinito (o un while (true) que debe tener su return o break bien visible).

Resumen

  • Un bucle repite un bloque mientras se cumpla una condición; necesita inicio, condición y algo que avance.
  • for (inicio; condición; actualización): el inicio se ejecuta una vez, la condición antes de cada vuelta y la actualización después de cada vuelta. Para N elementos: for (int i = 0; i < N; i++).
  • Puede contar con pasos distintos (angulo += 45) o hacia atrás (i--, el halo neón se pinta de la capa ancha a la fina).
  • Dos for anidados recorren el tablero 3×3: el de dentro da sus 3 vueltas completas por cada vuelta del de fuera; 9 en total, de izquierda a derecha y de arriba abajo.
  • while repite sin número fijo de vueltas; while (true) con un return dentro es el bucle de un juego en consola; do-while ejecuta el cuerpo al menos una vez.
  • break sale del bucle (el más interno), continue salta a la siguiente vuelta y return sale del método entero.
  • El for-each (for (String familia : FAMILIAS)) recorre cada elemento sin índice.
  • Un bucle infinito se detiene con Ctrl+C; se evita comprobando que algo avance hacia la condición de salida.
Aplícalo fuera del Totito
  • Cualquier cuadrícula se recorre con dos for anidados: las 42 casillas de Conecta 4 (6 filas × 7 columnas), las minas de un Buscaminas, los píxeles de una foto para aplicarle un filtro, las celdas de una hoja de cálculo.
  • Acumuladores en informes: sumar las ventas del día, contar cuántos alumnos aprobaron o encontrar el producto más caro son bucles con una variable que empieza fuera y se actualiza dentro, como vacias.
  • Menús de consola: un while (true) que muestra opciones, lee la elegida y sale con return cuando el usuario escribe «salir»; la base de un gestor de tareas en consola.
  • Reintentos: un do-while que intenta conectarse a Internet o pedir una contraseña, y repite mientras falle (con un máximo de intentos para no hacer un bucle infinito).
Ejercicios
  1. Con un for, imprime la tabla del 7 (de 7×1 a 7×10). Luego, con dos for anidados, imprime todas las tablas del 1 al 10 en forma de cuadrícula.
  2. Modifica RecorrerTablero para que imprima, en cada vuelta, el número de casilla del 0 al 8 calculado con fila * 3 + columna. Luego cambia el orden de los bucles (columnas fuera, filas dentro) y describe en qué orden se visitan ahora.
  3. Escribe un bucle que revise solo las dos diagonales de un char[][] de 3×3 usando una sola variable i. Pista: la diagonal principal es [i][i]; la otra es [i][2 - i].
  4. Con break, encuentra la primera casilla vacía de un tablero 3×3 recorriéndolo por filas, e imprime su fila y columna. Si no hay ninguna, imprime «Tablero lleno». Pista: necesitarás una variable boolean encontrada para salir también del bucle exterior.
  5. Reto: usando Random con semilla, simula una partida completa entre dos IA «tontas» que juegan al azar en un tablero de consola, alternando X y O con turno = 1 - turno, hasta que se llene el tablero. Imprime el tablero tras cada jugada. (No hace falta detectar al ganador todavía.)
