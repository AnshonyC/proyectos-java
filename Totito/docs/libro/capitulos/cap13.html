Capítulo 13Decisiones

Un juego está hecho de preguntas: ¿esta casilla está libre?, ¿alguien hizo tres en línea?, ¿le toca a la computadora? En este capítulo aprendes a que tu programa tome caminos distintos según la respuesta, con if, else, los operadores lógicos, switch y el operador ternario, todos tal como aparecen en el Totito.

Por qué un programa necesita decidir

Hasta ahora tus programas eran una lista que se ejecutaba de arriba abajo, siempre igual. Pero el Totito no hace siempre lo mismo: si haces clic en una casilla vacía pone tu ficha; si está ocupada, no hace nada; si tu jugada completa una línea, anuncia la victoria; si no, pasa el turno. Esas bifurcaciones se llaman estructuras de control o de decisión: le dicen a la computadora «ejecuta esto solo si se cumple tal condición».

Analogía: el semáforo. Cuando llegas a una esquina decides: si está en verde, avanzas; si está en amarillo, frenas con cuidado; si no (rojo), te detienes. Nunca haces las tres cosas, siempre exactamente una, y la elección depende de una condición que miras en ese momento. Un if … else if … else es eso mismo, escrito en Java.

El if: ejecutar algo solo si…

La forma más simple:

if (condicion) {
    // instrucciones que se ejecutan solo si la condicion es true
}
  • if («si» en inglés) es una palabra reservada.
  • Los paréntesis encierran la condición: cualquier expresión cuyo resultado sea un boolean (capítulo 12). No puede ser un número ni un texto: if (turno) no compila si turno es un int; hay que preguntar algo, como if (turno == 1).
  • Las llaves encierran el bloque que depende de la condición. Si la condición es false, Java salta el bloque entero y sigue con lo que haya después de la llave de cierre.

Un ejemplo real, de BotonNeon.paintComponent:

if (!isEnabled()) {
    g2.setComposite(AlphaComposite.getInstance(AlphaComposite.SRC_OVER, 0.4f));
}

«Si el botón no está habilitado, dibuja todo al 40 % de opacidad». Un botón desactivado se ve apagado; uno activo se dibuja normal porque el bloque simplemente no se ejecuta. El ! significa «no» y lo verás en un momento.

else y else if: elegir entre varios caminos

else («si no») añade el camino alternativo: lo que se hace cuando la condición es falsa. Y else if encadena más preguntas. Este programa decide qué pasó en una partida a partir de lo que devolverían verificarGanador() y tableroLleno() del Tablero:

public class EstadoPartida {
    public static void main(String[] args) {
        char ganador = 'O';          // lo que devolveria verificarGanador()
        boolean lleno = false;       // lo que devolveria tableroLleno()

        if (ganador != ' ') {
            System.out.println("Gano " + ganador);
        } else if (lleno) {
            System.out.println("Empate");
        } else {
            System.out.println("La partida sigue");
        }
        System.out.println("(fin de la revision)");
    }
}
Gano O
(fin de la revision)

Cómo lo recorre Java, paso a paso:

  1. Evalúa ganador != ' ': 'O' es distinto de espacio, así que es true. Ejecuta el primer bloque e imprime «Gano O».
  2. Salta todos los demás else if y else sin mirarlos. En una cadena así se ejecuta como máximo un bloque: el primero cuya condición sea verdadera.
  3. Continúa después de la última llave: «(fin de la revision)».

Cambia ganador a ' ' y lleno a true: la primera condición es falsa, la segunda verdadera → «Empate». Con ' ' y false, ninguna lo es y se ejecuta el else → «La partida sigue». El else final no lleva condición: es el «en cualquier otro caso».

El Totito hace exactamente esto en Partida.jugar, después de colocar la ficha:

if (tablero.verificarGanador() != Tablero.VACIA) {
    estado = Estado.VICTORIA;
    ganador = jugadores[turno];
    victorias[turno]++;
} else if (tablero.tableroLleno()) {
    estado = Estado.EMPATE;
    empates++;
} else {
    turno = 1 - turno;
}

Tres caminos y solo uno se recorre: o alguien ganó (se anota la victoria), o se llenó el tablero (se anota el empate), o la partida sigue (se pasa el turno). Fíjate en por qué el orden importa: si la última jugada llena el tablero y forma una línea, hay que anunciar victoria, no empate. Como la victoria se pregunta primero, gana ella. Si invirtieras los dos primeros bloques, el jugador que gana con la novena ficha vería «¡Empate!». Un error de lógica sin ningún mensaje de error.

Varias comprobaciones seguidas: las cláusulas de guarda

Otra forma muy común de usar if es para salir en cuanto algo no está bien. Así empieza Tablero.marcarCasilla:

if (fila < 0 || fila > 2 || columna < 0 || columna > 2) {
    return false;
}
if (casillas[fila][columna] != VACIA) {
    return false;
}
casillas[fila][columna] = ficha;
return true;

return termina el método en ese instante y devuelve un valor a quien lo llamó (capítulo 16). Así que se lee: «si la posición está fuera del tablero, rechaza; si la casilla está ocupada, rechaza; si llegaste hasta aquí, todo está bien: coloca la ficha y acepta». A estos if que filtran los casos malos al principio se les llama cláusulas de guarda, como el guardia de la entrada de un edificio que revisa credenciales antes de dejarte pasar. Evitan amontonar if dentro de if y dejan el «camino feliz» al final, limpio. Este programa simula esa validación con else if:

public class ValidarJugada {
    public static void main(String[] args) {
        int fila = 1;
        int columna = 3;
        char ocupante = ' ';

        if (fila < 0 || fila > 2 || columna < 0 || columna > 2) {
            System.out.println("(" + fila + ", " + columna + ") esta fuera del tablero");
        } else if (ocupante != ' ') {
            System.out.println("La casilla ya tiene una " + ocupante);
        } else {
            System.out.println("Jugada valida en (" + fila + ", " + columna + ")");
        }
    }
}
(1, 3) esta fuera del tablero

¿Por qué importa que la comprobación de rango vaya antes que la de «ocupada»? Porque en el Tablero real la segunda lee casillas[fila][columna], y con columna 3 eso sería el ArrayIndexOutOfBoundsException del capítulo 11. La primera guarda protege a la segunda.

Ifs anidados

Un if puede ir dentro de otro. IA_Minimax.calcularMejorJugada lo hace dentro de dos bucles: «si la casilla está vacía, simula la jugada; y si el valor obtenido es mejor que el récord, guárdala»:

if (tablero.obtenerCasilla(fila, columna) == Tablero.VACIA) {
    Tablero copia = tablero.obtenerCopia();
    copia.marcarCasilla(fila, columna, fichaIA);
    int valor = minimax(copia, 0, false);
    if (valor > mejorValor) {
        mejorValor = valor;
        mejorJugada[0] = fila;
        mejorJugada[1] = columna;
    }
}

El if interior solo se evalúa si el exterior fue verdadero. Es como «si tengo hambre, abro la refri; y si hay pollo, lo caliento». Con más de dos o tres niveles el código se vuelve difícil de seguir; entonces conviene usar guardas o los operadores lógicos que vienen ahora.

public class TablaVerdad {
    public static void main(String[] args) {
        System.out.println("a      b      a && b  a || b  !a");
        boolean a = true, b = true;
        System.out.println(a + "   " + b + "   " + (a && b) + "    " + (a || b) + "    " + !a);
        b = false;
        System.out.println(a + "   " + b + "  " + (a && b) + "   " + (a || b) + "    " + !a);

        System.out.println(a + "  " + b + "   " + (a && b) + "   " + (a || b) + "    " + !a);
        b = false;
        System.out.println(a + "  " + b + "  " + (a && b) + "   " + (a || b) + "   " + !a);
    }
}

Cómo lee el Totito sus condiciones compuestas

Partida.esTurnoDeIA():

return ia != null && turno == 1 && estado == Estado.EN_CURSO;

«Le toca a la IA si: existe una IA (estamos en modo contra la computadora) y el turno es del jugador 2 y la partida no ha terminado». Las tres a la vez. Si falta una, no es su turno.

La condición de victoria en una fila, de Tablero.verificarGanador:

if (casillas[i][0] != VACIA && casillas[i][0] == casillas[i][1] && casillas[i][1] == casillas[i][2]) {

«La primera casilla no está vacía y la primera es igual a la segunda y la segunda igual a la tercera». ¿Por qué hace falta la primera parte? Porque una fila completamente vacía también tiene tres casillas iguales (tres espacios) y, sin esa comprobación, ¡el juego diría que ganó el espacio en blanco al empezar!

Y en PanelTablero.actualizarCursor, una condición partida en dos líneas para leerla mejor:

boolean sePuedeJugar = interactivo && filaEncima >= 0
        && fichas[filaEncima][columnaEncima] == Tablero.VACIA;

La manita del ratón aparece solo si el tablero acepta clics, el ratón está sobre alguna casilla y esa casilla está vacía. Guardar el resultado en un boolean con buen nombre hace que la línea siguiente se lea sola: sePuedeJugar ? Cursor.HAND_CURSOR : Cursor.DEFAULT_CURSOR.

Precedencia lógica. ! se aplica primero, luego && y por último ||; y todos van después de las comparaciones (<, ==…). Por eso fila < 0 || fila > 2 funciona sin paréntesis. Si mezclas && y || en la misma condición, pon paréntesis aunque no hagan falta: (a && b) || c.

El cortocircuito: por qué el orden importa

&& y || son perezosos, y eso es una virtud. Evalúan de izquierda a derecha y se detienen en cuanto saben la respuesta:

  • En a && b, si a es false, el resultado ya es false: b no se evalúa.
  • En a || b, si a es true, el resultado ya es true: b no se evalúa.

A eso se le llama evaluación en cortocircuito, y el Totito depende de ella. En BotonNeon.pintarContenidoCentrado:

if (texto == null || texto.isEmpty()) {

null significa «no hay ningún objeto» (capítulo 18). Si texto es null, la primera parte ya es true y Java no llama a texto.isEmpty(), lo cual es una suerte: pedirle algo a un objeto que no existe detiene el programa. Mira qué pasa si inviertes el orden:

public class Cortocircuito {
    public static void main(String[] args) {
        String texto = null;   // un boton sin texto

        // Como BotonNeon: si es null, ni siquiera mira isEmpty()
        if (texto == null || texto.isEmpty()) {
            System.out.println("Boton solo con icono");
        }

        // Al reves, el orden importa: aqui se llama isEmpty() sobre null
        if (texto.isEmpty() || texto == null) {
            System.out.println("Nunca llega aqui");
        }
    }
}
Boton solo con icono

	at Cortocircuito.main(Cortocircuito.java:11)

La famosa NullPointerException: «no puedo llamar a isEmpty() porque la variable es null». (<local1> es como llama Java a texto cuando se compila sin información de depuración; desde NetBeans verás el nombre real.) Lo mismo protege ia != null && … en esTurnoDeIA() y interactivo && oyente != null && filaEncima >= 0 en PanelTablero: primero se comprueba que la cosa existe, y solo después se usa.

Analogía. «¿Tienes carro y está lleno el tanque?» Si la respuesta a la primera parte es «no tengo carro», nadie va a revisar el tanque. El cortocircuito es ese sentido común: no preguntes por el tanque de un carro que no existe.
Existen también & y | (con un solo símbolo). Con boolean calculan lo mismo, pero sin cortocircuito: evalúan siempre las dos partes. Con texto == null | texto.isEmpty() el programa fallaría igual. En condiciones usa siempre los dobles.

El «no» y cómo negar condiciones compuestas

! invierte un boolean. En Partida.jugar:

if (!tablero.marcarCasilla(fila, columna, jugadores[turno].getFicha())) {
    return false;
}

Ojo con lo que hace esta línea: llama a marcarCasilla, que intenta colocar la ficha y devuelve true si pudo; el ! invierte ese resultado. Se lee «si no se pudo marcar la casilla, la jugada no vale». Cuando sí se pudo, la ficha ya quedó puesta y el método sigue.

Para negar una condición con && o || se usan las leyes de De Morgan: !(a && b) es lo mismo que !a || !b, y !(a || b) es !a && !b. Ejemplo: «fuera del tablero» es fila < 0 || fila > 2; «dentro» es lo contrario, fila >= 0 && fila <= 2. Es la condición que verás en PanelTablero: fila >= 0 && fila < 3.

Errores clásicos con if

El punto y coma fantasma

public class PuntoYComa {
    public static void main(String[] args) {
        int fila = 5;
        if (fila > 2); {
            System.out.println("Fila fuera de rango");
        }
        fila = 1;
        if (fila > 2); {
            System.out.println("Fila fuera de rango (y fila vale " + fila + ")");
        }
    }
}
Fila fuera de rango
Fila fuera de rango (y fila vale 1)

Con fila 1 no debería imprimir nada, y lo imprime. El ; después del paréntesis termina el if ahí mismo, con una instrucción vacía; el bloque de llaves queda suelto y se ejecuta siempre. Compila sin quejarse. Nunca pongas ; entre la condición y la llave.

Olvidar las llaves

Java permite un if sin llaves cuando el bloque es una sola instrucción: if (fila > 2) return false;. Pero si después añades una segunda línea, creyendo que también depende del if, te equivocas: solo la primera depende de él, la segunda se ejecuta siempre, por mucho que la sangría diga lo contrario. Por eso el Totito usa llaves en todos sus if, aunque tengan una sola línea. Es una de las buenas prácticas más aceptadas.

Comparar textos con ==

Con int, char y boolean, == compara valores. Con String no: compara si son el mismo objeto en memoria, y dos textos iguales pueden ser objetos distintos. Para textos se usa nombre.equals("Ana"). Lo verás con detalle en el capítulo 17. (Otra razón por la que la ficha es char.)

switch: elegir según un valor

Cuando la pregunta es «¿cuál de estos valores tiene esta variable?», una cadena de else if se vuelve repetitiva. Para eso existe switch («conmutador», como el selector de canales de una radio). Java tiene dos formas: la clásica, heredada del lenguaje C, y la moderna con flechas.

El switch clásico

public class SwitchClasico {
    public static void main(String[] args) {
        int casilla = 4;   // casillas numeradas de 0 a 8
        String nombre;
        switch (casilla) {
            case 0:
            case 2:
            case 6:
            case 8:
                nombre = "esquina";
                break;
            case 4:
                nombre = "centro";
                break;
            default:
                nombre = "borde";
                break;
        }
        System.out.println("La casilla " + casilla + " es " + nombre);
    }
}
La casilla 4 es centro
  • switch (casilla): el valor que se examina. Puede ser int, char, String o un enum (más abajo).
  • case 4:: una etiqueta. Java salta directamente a la etiqueta que coincide con el valor y empieza a ejecutar desde ahí.
  • break;: «rompe», sale del switch. Sin él, la ejecución sigue hacia abajo por los casos siguientes.
  • default:: lo que se hace si ningún case coincide; es el else del switch.
  • Varias etiquetas seguidas (case 0: case 2: …) comparten el mismo código: las cuatro esquinas.

Ese «seguir hacia abajo» (en inglés fall-through) es la mayor trampa del switch clásico. Olvida los break:

public class SinBreak {
    public static void main(String[] args) {
        char ficha = 'X';
        switch (ficha) {
            case 'X':
                System.out.println("rosa");
            case 'O':
                System.out.println("azul");
            default:
                System.out.println("sin color");
        }
    }
}

azul

Entró en 'X' y, como nada lo detuvo, ejecutó también los casos de 'O' y el default. Compila sin advertencias. Es un error tan frecuente que Java creó una forma nueva.

El switch con flechas ->

Desde Java 14, cada caso puede escribirse con una flecha. Con flechas no hay fall-through: se ejecuta solo lo que está a la derecha de la flecha del caso que coincide, y se acabó. Además, el switch puede devolver un valor, como una expresión. Así decide BotonNeon cuánto redondear las esquinas según su estilo:

double arco = switch (estilo) {
    case MENU -> 30;
    case ICONO -> 16;
    default -> alto;        // pildora: extremos totalmente redondos
};

Se lee: «el arco vale 30 si el estilo es MENU, 16 si es ICONO, y en cualquier otro caso (las dos píldoras) vale lo mismo que la altura del botón». Un arco igual a la altura hace los extremos completamente redondos: por eso los botones «Comenzar partida» o «Volver» parecen cápsulas. Fíjate en el ; después de la llave de cierre: todo el switch es el valor de una asignación, y la asignación termina con punto y coma.

estilo es de tipo Estilo, un enum: una lista cerrada de valores con nombre que define el propio programador (MENU, PILDORA, CONTORNO, ICONO). Los enums se estudian en el capítulo 26; por ahora basta saber que son perfectos para un switch, porque el compilador conoce todos los valores posibles. Este programa reproduce el switch de BotonNeon y añade otra novedad: varias etiquetas separadas por comas en un mismo caso.

public class SwitchFlecha {
    enum Estilo { MENU, PILDORA, CONTORNO, ICONO }

    public static void main(String[] args) {
        double alto = 48;
        Estilo estilo = Estilo.ICONO;

        // Como en BotonNeon.paintComponent: un switch que DEVUELVE un valor
        double arco = switch (estilo) {
            case MENU -> 30;
            case ICONO -> 16;
            default -> alto;        // pildora: extremos totalmente redondos
        };
        System.out.println(estilo + " -> arco " + arco);

        estilo = Estilo.CONTORNO;
        arco = switch (estilo) {
            case MENU -> 30;
            case ICONO -> 16;
            default -> alto;
        };
        System.out.println(estilo + " -> arco " + arco);

        // Varias etiquetas en un mismo caso
        int casilla = 6;
        String tipo = switch (casilla) {
            case 0, 2, 6, 8 -> "esquina";
            case 4 -> "centro";
            default -> "borde";
        };
        System.out.println("La casilla " + casilla + " es " + tipo);
    }
}

Switch que ejecuta acciones

No todo switch devuelve un valor; también puede ejecutar instrucciones distintas en cada caso. Si un caso necesita varias líneas, se envuelven en llaves. Así actualiza PantallaJuego el letrero de arriba del tablero según el estado de la partida:

public class SwitchEstado {
    enum Estado { EN_CURSO, VICTORIA, EMPATE }

    public static void main(String[] args) {
        Estado estado = Estado.VICTORIA;
        String nombreEnTurno = "Ana";
        boolean turnoDeIA = false;

        // Como PantallaJuego.actualizar(): un switch que HACE algo en cada caso
        switch (estado) {
            case EN_CURSO -> {
                String texto = turnoDeIA
                        ? "La computadora esta pensando..."
                        : "Turno de " + nombreEnTurno;
                System.out.println(texto);
            }
            case VICTORIA -> System.out.println("¡Tres en linea!");
            case EMPATE -> System.out.println("¡Empate!");
        }
    }
}
¡Tres en linea!

En el Totito real, en lugar de println, cada caso llama a turno.setTexto(…) con el texto y los colores adecuados: rosa o azul según la ficha en curso, lavanda y morado para el empate. Al usar un enum, dentro de los case se escribe solo VICTORIA, no Estado.VICTORIA: Java ya sabe de qué enum se trata.

El compilador te cuida. Cuando un switch con flechas devuelve un valor, debe cubrir todos los casos posibles. Si olvidas uno y no hay default, no compila:

Esto es una gran ventaja: si algún día añades un estado nuevo al enum (por ejemplo PAUSA), el compilador te señala cada switch que se quedó sin tratarlo.

¿Switch o if? Usa switch cuando compares una variable contra valores fijos (un estado, un estilo, una opción de menú). Usa if cuando las condiciones sean rangos (fila > 2), mezclen varias variables o lleven &&/||.

El operador ternario ? :

Muchas decisiones del Totito no ejecutan acciones distintas, sino que eligen entre dos valores. Para eso hay un atajo, el único operador de Java con tres partes:

condicion ? valorSiTrue : valorSiFalse

Se lee «¿se cumple la condición? entonces esto; si no, aquello». El resultado es un valor que se puede guardar, devolver o pasar a un método. Ejemplos reales:

El ternario lo dice en una y, además, permite declarar la variable ya con su valor (incluso como final).

Cuándo no usarlo. El ternario es para elegir entre dos valores sencillos. Si hay que ejecutar acciones, o si te ves anidando un ternario dentro de otro (a ? b : c ? d : e), vuelve al if o al switch: el código se lee más veces de las que se escribe. Cuando la condición o los valores son largos, pártelo en líneas como PantallaJuego, con el ? y el : al principio de cada línea.

Resumen

  • if (condición) { … } ejecuta un bloque solo si la condición (un boolean) es true; else if encadena alternativas y else recoge el resto. Se ejecuta como mucho un bloque de la cadena, y el orden de las preguntas importa.
  • Las cláusulas de guarda (if (malo) { return …; } al principio) filtran los casos inválidos, como hace marcarCasilla.
  • && (y), || (o) y ! (no) combinan condiciones. Evalúan en cortocircuito: pon primero la comprobación que protege (texto == null || texto.isEmpty()).
  • Errores típicos: ; después del if, omitir llaves, comparar textos con ==.
  • El switch clásico sigue de largo sin break; el switch con -> no, puede devolver un valor y el compilador exige cubrir todos los casos.
  • El ternario cond ? a : b elige entre dos valores en una línea: la ficha del rival, el color, quién empieza.
Aplícalo fuera del Totito
  • Validar formularios. En un registro de clientes, cláusulas de guarda: si el nombre está vacío, rechaza; si el correo no tiene @, rechaza; si la edad es menor de 18, rechaza; si todo pasó, guarda. Es marcarCasilla con otros datos.
  • Precios por rangos. Una tienda que da 5 % de descuento desde Q100 y 10 % desde Q500 usa if / else if / else preguntando primero por el rango más alto, igual que el Totito pregunta por la victoria antes que por el empate.
  • Menús y estados. Una calculadora (switch sobre el operador '+', '-', '*', '/'), un semáforo o un reproductor de música (REPRODUCIENDO, PAUSA, DETENIDO) se resuelven con un enum y un switch con flechas.
  • Textos según el caso. cantidad == 1 ? "1 producto" : cantidad + " productos" evita el feo «1 productos» en cualquier aplicación.
Ejercicios
  1. Escribe un programa con una variable int victorias que imprima «Principiante» si tiene menos de 3, «Intermedio» de 3 a 9 y «Experto» con 10 o más. Prueba con 0, 3, 9 y 10.
  2. Reescribe la condición «la casilla (fila, columna) está dentro del tablero» usando && en lugar de ||, y comprueba con varios valores que da lo contrario de la de marcarCasilla. Pista: leyes de De Morgan.
  3. Con un switch con flechas sobre un char, convierte la ficha en su color como texto: 'X' → «rosa», 'O' → «azul», cualquier otra → «vacía». Luego hazlo con un ternario anidado y decide cuál se lee mejor.
  4. Las tres variables char a, b, c representan una fila del tablero. Escribe la condición que diga si esa fila es ganadora, sin olvidar el caso de la fila vacía. Pruébala con 'X','X','X', ' ',' ',' ' y 'X','O','X'.
