Capítulo 15Arreglos y matrices

El tablero del Totito son nueve casillas, el marcador son dos contadores y hay ocho líneas que dan la victoria. Guardar cada cosa en su propia variable sería un caos. En este capítulo aprendes a guardar muchos datos del mismo tipo bajo un solo nombre, con arreglos (int[]) y matrices (char[][]), a recorrerlos sin salirte de sus límites y a entender la diferencia, sutil pero crucial, entre copiar un tablero y compartirlo.

El problema: muchos datos del mismo tipo

Imagina el marcador sin arreglos:

int victoriasJugador1;
int victoriasJugador2;
// y al terminar una partida:
if (turno == 0) {
    victoriasJugador1++;
} else {
    victoriasJugador2++;
}

Ahora con un arreglo, como lo hace de verdad Partida:

private final int[] victorias = new int[2];
// y al terminar una partida:
victorias[turno]++;

Una línea en lugar de cinco, y sin if: el número del turno (0 o 1) elige directamente qué contador aumentar. Esa es la gracia de los arreglos: puedes calcular a qué dato quieres acceder. Con el tablero es aún más claro: nueve variables casilla00, casilla01… no se podrían recorrer con un bucle; una matriz casillas[fila][columna] sí.

Analogía: los casilleros. Un arreglo es como una fila de casilleros numerados en un gimnasio: todos del mismo tamaño, uno junto al otro, con un solo nombre para el conjunto («los casilleros del pasillo B») y un número para cada uno. No preguntas por «el casillero de Ana», sino por «el casillero 7 del pasillo B». Y el número puede salir de una cuenta: «el casillero que corresponde a tu número de socio».

Declarar y crear un arreglo

Un arreglo (en inglés array) es una colección de tamaño fijo de elementos del mismo tipo, numerados desde 0. Analicemos la línea de Partida pieza por pieza:

int[] victorias = new int[2];
  • int[]: el tipo «arreglo de int». Los corchetes vacíos convierten cualquier tipo en «arreglo de ese tipo»: char[], String[], Jugador[].
  • victorias: el nombre. Por convención, en plural: es una colección.
  • new: «crea uno nuevo». Reserva la memoria para el arreglo. Es la misma palabra que crea objetos (new Tablero(), capítulo 18): en Java los arreglos son objetos.
  • int[2]: de enteros, con 2 posiciones. El tamaño se fija al crearlo y no puede cambiar después.

Al crearse, cada posición recibe un valor por defecto: 0 para números, false para boolean, el carácter de código 0 para char y null para objetos (como String). Por eso el marcador empieza en cero sin que nadie lo escriba.

import java.util.Arrays;

public class Marcador {
    public static void main(String[] args) {
        int[] victorias = new int[2];   // como en Partida: una caja por jugador
        System.out.println("Al crear: " + Arrays.toString(victorias));
        System.out.println("Hay " + victorias.length + " posiciones");

        int turno = 0;
        victorias[turno]++;             // gana el jugador 0
        turno = 1;
        victorias[turno]++;             // gana el jugador 1
        victorias[turno]++;             // y otra vez
        System.out.println("Despues: " + Arrays.toString(victorias));
        System.out.println("Jugador 1 (indice 0): " + victorias[0]);
        System.out.println("Jugador 2 (indice 1): " + victorias[1]);

        System.out.println("Imprimir el arreglo directamente: " + victorias);
    }
}

Hay 2 posiciones

  • victorias[turno]: los corchetes con un número (o una variable, o una cuenta) acceden a una posición. Ese número se llama índice. victorias[turno]++ lee la posición turno, le suma 1 y la guarda.
  • victorias.length: el tamaño del arreglo. Ojo: sin paréntesis, porque es un dato que el arreglo guarda, no un método (al revés que texto.length() de los String; es una incoherencia histórica de Java que confunde a todo el mundo).
  • Arrays.toString(…): una utilidad de la clase java.util.Arrays (de ahí el import) que convierte el arreglo en un texto legible. Si imprimes el arreglo directamente obtienes [I@29453f44: [I significa «arreglo de int» y lo demás es un código interno. No es un error; es que un arreglo no sabe describirse solo.

Los índices empiezan en 0

Un arreglo de tamaño 3 tiene los índices 0, 1 y 2. El primero es [0] y el último es [length - 1]. ¿Por qué no del 1 al 3, como contaría cualquier persona? Porque el índice no es «el número de orden» sino la distancia desde el principio. El primer elemento está a 0 pasos del inicio; el segundo, a 1 paso. Para encontrar casillas[2], la computadora toma la dirección donde empieza el arreglo y avanza 2 casillas: una sola cuenta, rapidísima.

Analogía: la regla. En una regla, el primer centímetro no empieza en la marca «1», empieza en la «0». La marca indica cuánto te has alejado del borde. Lo mismo con la edad: durante su primer año de vida, un bebé tiene «0 años».

En el Totito esto encaja perfecto: las filas y columnas son 0, 1 y 2, el turno es 0 o 1 (índice del arreglo jugadores), y las cuentas como turno = 1 - turno o fila * 3 + columna funcionan precisamente porque se empieza en cero.

Arreglos literales: crear y llenar a la vez

Si ya sabes qué valores van dentro, los escribes entre llaves y Java cuenta el tamaño por ti:

import java.util.Arrays;

public class Literales {
    public static void main(String[] args) {
        char[] fila = {'X', 'O', ' '};
        String[] familias = {"Nunito", "Poppins", "Segoe UI"};
        int[] mejorJugada = new int[]{-1, -1};   // como en IA_Minimax

        System.out.println(Arrays.toString(fila) + " tiene " + fila.length + " casillas");
        System.out.println("La primera fuente es " + familias[0]);
        System.out.println("La ultima fuente es " + familias[familias.length - 1]);
        System.out.println("Mejor jugada inicial: " + Arrays.toString(mejorJugada));

        mejorJugada[0] = 2;
        mejorJugada[1] = 1;
        System.out.println("Mejor jugada final: fila " + mejorJugada[0] + ", columna " + mejorJugada[1]);
    }
}

Las dos formas, {…} y new int[]{…}, crean lo mismo. La corta solo se permite al declarar la variable; en cualquier otro sitio hay que escribir la larga. Por eso Partida.buscarLineaGanadora devuelve su resultado con return new int[]{l[0], l[1], l[4], l[5]}; y el constructor de Partida asigna this.jugadores = new Jugador[]{jugador1, jugador2};.

Fíjate en para qué usa IA_Minimax el arreglo mejorJugada: un método solo puede devolver un valor, y la IA necesita devolver dos (fila y columna). Solución: los mete en un arreglo de 2 y devuelve el arreglo. Empieza en {-1, -1}, que significa «todavía ninguna», y se va actualizando cada vez que encuentra una jugada mejor. Quien lo recibe lo desarma: jugar(jugada[0], jugada[1]).

Salirse del arreglo: ArrayIndexOutOfBoundsException

Pedir una posición que no existe (negativa, o mayor o igual que length) detiene el programa. Ya lo viste en el capítulo 11 con el índice 3. Con índices negativos pasa lo mismo, y esto importa en el Totito, que usa -1 como «el ratón no está sobre ninguna casilla»:

public class IndiceNegativo {
    public static void main(String[] args) {
        char[][] fichas = new char[3][3];
        int filaEncima = -1;      // "el raton no esta sobre ninguna casilla"
        int columnaEncima = -1;
        if (filaEncima >= 0) {    // la guarda de PanelTablero
            System.out.println("Hay una ficha: " + fichas[filaEncima][columnaEncima]);
        }
        System.out.println("Sin la guarda:");
        System.out.println(fichas[filaEncima][columnaEncima]);
    }
}
Sin la guarda:
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index -1 out of bounds for length 3
	at IndiceNegativo.main(IndiceNegativo.java:10)

Por eso en PanelTablero toda lectura de fichas[filaEncima][columnaEncima] va precedida de filaEncima >= 0 &&: gracias al cortocircuito (capítulo 13), si el ratón está fuera, la matriz ni se toca. Y por eso Tablero.marcarCasilla comprueba fila < 0 || fila > 2 || … antes de nada. Regla: si un índice viene de fuera (un clic, lo que escribe el usuario, un cálculo con coordenadas), compruébalo antes de usarlo.

Recorrer un arreglo

Las dos formas del capítulo 14:

// Con indice: cuando necesitas saber la posicion o modificar
for (int i = 0; i < victorias.length; i++) {
    System.out.println("Jugador " + (i + 1) + ": " + victorias[i]);
}

// For-each: cuando solo necesitas cada valor
int total = 0;
for (int v : victorias) {
    total += v;
}

Usa siempre i < arreglo.length en lugar de escribir el número a mano (i < 2): si algún día el arreglo crece, el bucle se adapta solo. El Totito escribe 3 directamente en sus bucles del tablero porque el tablero del totito es 3×3 por definición; en un juego con tablero de tamaño variable usarías casillas.length.

Matrices: arreglos de dos dimensiones

El tablero es una tabla de filas y columnas. En Java eso es una matriz, que se declara con dos pares de corchetes. Así lo declara y crea Tablero:

private char[][] casillas;

public Tablero() {
    casillas = new char[3][3];
    reiniciar();
}

new char[3][3] crea 3 filas de 3 caracteres. Para acceder a una casilla das dos índices: primero la fila, luego la columna. casillas[0][2] es la esquina superior derecha; casillas[2][0], la inferior izquierda; casillas[1][1], el centro.

columna 0columna 1columna 2
fila 0[0][0][0][1][0][2]
fila 1[1][0][1][1] centro[1][2]
fila 2[2][0][2][1][2][2]
Fila primero, columna después, siempre. En pantalla, en cambio, las coordenadas son (x, y): primero la horizontal (que corresponde a la columna) y luego la vertical (la fila). Por eso PanelTablero llama a centroX(columna) y centroY(fila), y en paintComponent la raya ganadora usa centroX(lineaGanadora[1]) (el índice 1 es la columna) y centroY(lineaGanadora[0]) (el 0 es la fila). Confundir el orden dibuja la ficha en la casilla simétrica respecto a la diagonal: un error muy típico.

Por qué el constructor llama a reiniciar()

Una pregunta razonable: si new char[3][3] ya crea las casillas, ¿para qué reiniciar() justo después? Porque el valor por defecto de un char no es el espacio:

public class MatrizNueva {
    public static void main(String[] args) {
        char[][] casillas = new char[3][3];
        System.out.println("filas: " + casillas.length + ", columnas de la fila 0: " + casillas[0].length);
        System.out.println("codigo de casillas[1][1] recien creada: " + (int) casillas[1][1]);
        System.out.println("¿es igual a ' '? " + (casillas[1][1] == ' '));

        // Por eso el constructor de Tablero llama a reiniciar()
        for (int fila = 0; fila < 3; fila++) {
            for (int columna = 0; columna < 3; columna++) {
                casillas[fila][columna] = ' ';
            }
        }
        System.out.println("tras reiniciar, ¿es igual a ' '? " + (casillas[1][1] == ' '));

        int[] numeros = new int[3];
        boolean[] marcas = new boolean[3];
        String[] nombres = new String[3];
        System.out.println("int: " + numeros[0] + ", boolean: " + marcas[0] + ", String: " + nombres[0]);
    }
}
filas: 3, columnas de la fila 0: 3
codigo de casillas[1][1] recien creada: 0
¿es igual a ' '? false
tras reiniciar, ¿es igual a ' '? true
int: 0, boolean: false, String: null

Una casilla recién creada contiene el carácter de código 0 (se escribe '\u0000'), un carácter invisible que no es el espacio (código 32). Todo el Totito pregunta == VACIA, es decir, == ' '. Sin reiniciar(), un tablero nuevo tendría nueve casillas que no están «vacías» según las reglas: no podrías jugar en ninguna y tableroLleno() diría que está lleno antes de empezar. Una sola línea en el constructor evita ese desastre, y además reutiliza el mismo método que sirve para «jugar otra vez».

PanelTablero resuelve lo mismo de otra forma, con java.util.Arrays.fill, que llena un arreglo entero con un valor:

for (char[] fila : fichas) {
    java.util.Arrays.fill(fila, Tablero.VACIA);
}

Una matriz es un arreglo de arreglos

Lo anterior también revela cómo está hecha una matriz por dentro: casillas.length es 3 (hay 3 filas) y casillas[0].length también es 3 (la fila 0 tiene 3 casillas). En Java, char[][] es literalmente un «arreglo de char[]»: un arreglo exterior cuyas 3 posiciones guardan, cada una, una fila. Por eso casillas[1] sola es válida (es la fila 1 entera, un char[]), y por eso el for-each de PanelTablero recorre fichas de fila en fila con char[] fila. También puedes escribir una matriz literal, fila por fila, con llaves dentro de llaves:

char[][] casillas = {
    {'X', 'O', 'X'},
    {' ', 'X', 'O'},
    {' ', ' ', 'O'}
};

Esta forma es muy útil para preparar situaciones de prueba («¿qué hace la IA con este tablero?»), como harás en el capítulo 32.

Copiar o compartir: la referencia

Esta es la idea más importante del capítulo, y la causa de muchísimos errores. Una variable de tipo arreglo no contiene el arreglo: contiene una referencia, es decir, la dirección de memoria donde vive. Cuando escribes otra = casillas; no copias el tablero: copias la dirección. Ahora hay dos nombres para el mismo tablero.

Analogía: la dirección de una casa. Si le das a un amigo la dirección de tu casa anotada en un papel, no le diste una casa; le diste otra forma de llegar a la misma. Si él entra y pinta la sala de verde, tú encontrarás la sala verde. Copiar un arreglo de verdad es construir otra casa idéntica.

¿Por qué importa en el Totito? Porque la IA necesita imaginar jugadas: «si juego aquí, ¿qué pasa?». Si simulara sobre el tablero real, las fichas imaginarias aparecerían en la partida de verdad. Este programa muestra las tres maneras de «copiar» y qué pasa con cada una:

import java.util.Arrays;

public class CompartirVsCopiar {
    public static void main(String[] args) {
        char[][] partida = {
            {'X', ' ', ' '},
            {' ', 'O', ' '},
            {' ', ' ', ' '}
        };

        // 1) "Copiar" con = : solo se copia la referencia (la direccion)
        char[][] simulacion = partida;
        simulacion[2][2] = 'X';
        System.out.println("1) partida[2][2] = '" + partida[2][2] + "'  <- ¡la partida real cambio!");
        partida[2][2] = ' ';

        // 2) clone(): copia el arreglo de filas, pero las filas se comparten
        char[][] superficial = partida.clone();
        superficial[2][2] = 'X';
        System.out.println("2) partida[2][2] = '" + partida[2][2] + "'  <- ¡tambien cambio!");
        System.out.println("   ¿misma matriz? " + (superficial == partida) + ", ¿misma fila 2? " + (superficial[2] == partida[2]));
        partida[2][2] = ' ';

        // 3) Copia profunda, casilla por casilla (lo que hace Tablero.obtenerCopia)
        char[][] copia = new char[3][3];
        for (int fila = 0; fila < 3; fila++) {
            for (int columna = 0; columna < 3; columna++) {
                copia[fila][columna] = partida[fila][columna];
            }
        }
        copia[2][2] = 'X';
        System.out.println("3) partida[2][2] = '" + partida[2][2] + "'  <- intacta");
        System.out.println("   copia:   " + Arrays.deepToString(copia));
        System.out.println("   partida: " + Arrays.deepToString(partida));
    }
}
1) partida[2][2] = 'X'  <- ¡la partida real cambio!
2) partida[2][2] = 'X'  <- ¡tambien cambio!
   ¿misma matriz? false, ¿misma fila 2? true
3) partida[2][2] = ' '  <- intacta
   copia:   [[X,  ,  ], [ , O,  ], [ ,  , X]]
   partida: [[X,  ,  ], [ , O,  ], [ ,  ,  ]]
  1. Con =: simulacion y partida son dos nombres para la misma matriz. Escribir en una es escribir en la otra.
  2. Con clone(): todo arreglo tiene un método clone() que crea un arreglo nuevo con los mismos elementos. Con un char[] de una dimensión basta. Pero en una matriz, los elementos del arreglo exterior son referencias a filas, así que el clon es una lista nueva que apunta a las mismas filas. La comprobación lo confirma: las matrices son distintas (false) pero la fila 2 es la misma (true). Esto se llama copia superficial.
  3. Casilla por casilla: se crea una matriz nueva con su propio new y se copia cada char. Como los char son valores primitivos (no referencias), lo que se copia es la letra misma. Es una copia profunda: dos tableros totalmente independientes.

(Arrays.deepToString es el hermano de toString para matrices. Y aquí == entre arreglos pregunta «¿es la misma dirección?», no «¿tienen el mismo contenido?».)

Tablero.obtenerCopia(), explicado

Ahora entiendes por qué el Totito tiene este método, y por qué está hecho así:

/** Crea una copia independiente del tablero, usada por el algoritmo Minimax
 *  para simular jugadas sin afectar la partida real. */
public Tablero obtenerCopia() {
    Tablero copia = new Tablero();
    for (int fila = 0; fila < 3; fila++) {
        for (int columna = 0; columna < 3; columna++) {
            copia.casillas[fila][columna] = this.casillas[fila][columna];
        }
    }
    return copia;
}

new Tablero() crea un tablero nuevo, con su propia matriz casillas recién fabricada. Los dos bucles copian, letra por letra, de this.casillas (las casillas del tablero original; this significa «yo mismo», capítulo 20) a copia.casillas. Es la copia profunda del caso 3. Un return casillas.clone() habría sido más corto… y habría hecho que la IA moviera fichas en tu partida mientras «pensaba». Puedes comprobarlo con el Tablero real del proyecto. Guarda este programa en tu carpeta de prácticas:

public class CopiaTablero {
    public static void main(String[] args) {
        Tablero real = new Tablero();
        real.marcarCasilla(0, 0, 'X');
        real.marcarCasilla(1, 1, 'O');

        Tablero copia = real.obtenerCopia();       // lo que hace IA_Minimax
        copia.marcarCasilla(2, 2, 'X');            // simula una jugada

        System.out.println("copia[2][2] = '" + copia.obtenerCasilla(2, 2) + "'");
        System.out.println("real[2][2]  = '" + real.obtenerCasilla(2, 2) + "'");

        Tablero mismo = real;                      // NO es una copia
        mismo.marcarCasilla(0, 2, 'O');
        System.out.println("real[0][2]  = '" + real.obtenerCasilla(0, 2) + "'");
    }
}

Y ejecútalo diciéndole a Java dónde están las clases compiladas del Totito con -cp (classpath, «ruta de clases»), cuando ya hayas compilado el proyecto (capítulo 29 en adelante):

cd $HOME\Proyectos\Practicas
java -cp $HOME\Proyectos\Totito\target\classes CopiaTablero.java
copia[2][2] = 'X'
real[2][2]  = ' '
real[0][2]  = 'O'

La jugada simulada en la copia no tocó el tablero real. En cambio, Tablero mismo = real; no copió nada: es la misma regla de las referencias, ahora con un objeto Tablero en lugar de un arreglo. Lo retomarás en el capítulo 18.

Pista de que compartes sin querer: «cambié algo aquí y apareció un cambio allá». Si te pasa, busca un = entre dos variables de arreglo (u objeto) y pregúntate si querías un segundo nombre o una copia independiente. PanelTablero.mostrar también copia casilla por casilla el tablero que recibe, en lugar de guardar la referencia: así lo que dibuja no cambia por sorpresa mientras la partida avanza.

Datos en lugar de código: int[][] lineas

Tablero.verificarGanador comprueba las ocho líneas con if escritos a mano. Partida.buscarLineaGanadora hace casi lo mismo de otra forma: describe las ocho líneas como datos, en una matriz literal, y las recorre con un solo bucle:

int[][] lineas = {
    {0, 0, 0, 1, 0, 2}, {1, 0, 1, 1, 1, 2}, {2, 0, 2, 1, 2, 2},   // filas
    {0, 0, 1, 0, 2, 0}, {0, 1, 1, 1, 2, 1}, {0, 2, 1, 2, 2, 2},   // columnas
    {0, 0, 1, 1, 2, 2}, {0, 2, 1, 1, 2, 0}                        // diagonales
};

Cada fila de lineas tiene seis números: tres parejas (fila, columna), una por cada casilla de la línea. {0, 2, 1, 1, 2, 0} se lee «(0,2), (1,1), (2,0)»: la diagonal que baja de la esquina superior derecha a la inferior izquierda. Este programa usa la misma tabla sobre un tablero concreto:

import java.util.Arrays;

public class LineaGanadora {
    public static void main(String[] args) {
        char[][] casillas = {
            {'O', 'X', 'X'},
            {' ', 'X', 'O'},
            {'X', 'O', ' '}
        };
        // Igual que Partida.buscarLineaGanadora: 8 lineas, 3 casillas cada una
        int[][] lineas = {
            {0, 0, 0, 1, 0, 2}, {1, 0, 1, 1, 1, 2}, {2, 0, 2, 1, 2, 2},   // filas
            {0, 0, 1, 0, 2, 0}, {0, 1, 1, 1, 2, 1}, {0, 2, 1, 2, 2, 2},   // columnas
            {0, 0, 1, 1, 2, 2}, {0, 2, 1, 1, 2, 0}                        // diagonales
        };
        System.out.println("Hay " + lineas.length + " lineas de " + lineas[0].length + " numeros");

        int numero = 0;
        for (int[] l : lineas) {
            char a = casillas[l[0]][l[1]];
            char b = casillas[l[2]][l[3]];
            char c = casillas[l[4]][l[5]];
            System.out.println("linea " + numero + ": [" + a + b + c + "]");
            if (a != ' ' && a == b && a == c) {
                int[] raya = new int[]{l[0], l[1], l[4], l[5]};
                System.out.println("¡Ganadora! La raya va de (" + raya[0] + "," + raya[1]
                        + ") a (" + raya[2] + "," + raya[3] + "): " + Arrays.toString(raya));
                break;
            }
            numero++;
        }
    }
}

¡Ganadora! La raya va de (0,2) a (2,0): [0, 2, 2, 0]

Traza de la línea 7: l es {0, 2, 1, 1, 2, 0}. a = casillas[l[0]][l[1]] = casillas[0][2] = 'X'; b = casillas[1][1] = 'X'; c = casillas[2][0] = 'X'. Las tres iguales y no vacías: ganadora. Fíjate en el doble salto de los índices: l[0] es un número que se usa, a su vez, como índice de casillas. Un arreglo que guarda posiciones de otro arreglo.

El método devuelve solo los extremos de la línea, {filaInicio, columnaInicio, filaFin, columnaFin} (las posiciones 0, 1, 4 y 5 de l; la casilla del medio no hace falta), porque para dibujar la raya neón basta con saber de dónde a dónde va. Si ninguna línea gana, devuelve null: «no hay arreglo». PanelTablero lo guarda en lineaGanadora y solo dibuja la raya if (lineaGanadora != null).

Datos frente a código. Convertir una lista de casos en una tabla de datos más un bucle (en lugar de muchos if casi iguales) hace el código más corto y fácil de ampliar: para un tablero de 4×4 bastaría con añadir filas a la tabla. Es una técnica que usarás mucho: tablas de precios, de niveles de un juego, de traducciones.

Arreglos de objetos

Un arreglo puede guardar objetos, no solo números o caracteres. Partida guarda a sus dos jugadores en un Jugador[] y los elige con el turno: jugadores[turno].getFicha(), getJugadorEnTurno() devuelve jugadores[turno]. Lo que el arreglo guarda en realidad son referencias a los objetos; al crearlo vacío, cada posición vale null:

public class Jugadores {
    public static void main(String[] args) {
        String[] nombres = new String[2];
        System.out.println("Recien creado: " + nombres[0] + ", " + nombres[1]);
        nombres[0] = "Ana";
        nombres[1] = "Computadora";
        int turno = 1;
        System.out.println("Le toca a " + nombres[turno]);
        turno = 1 - turno;
        System.out.println("Ahora le toca a " + nombres[turno]);
    }
}
Recien creado: null, null
Le toca a Computadora
Ahora le toca a Ana

Si llamaras a un método sobre una posición que aún es null (nombres[0].length() antes de asignarla) obtendrías una NullPointerException. Por eso Partida crea el arreglo ya lleno: new Jugador[]{jugador1, jugador2}.

El límite de los arreglos: tamaño fijo

Un arreglo no crece. Para el Totito es perfecto: siempre hay 9 casillas, 2 jugadores, 8 líneas. Pero si quisieras guardar el historial de todas las partidas jugadas, no sabrías de qué tamaño crearlo. Para eso Java tiene las colecciones, como ArrayList y List, que crecen solas. El Totito usa una en Tema (List<String> FAMILIAS = Arrays.asList(…)), solo para poder preguntar instaladas.contains(familia). Las verás en tus siguientes proyectos (capítulos 68 y 69).

Resumen

  • Un arreglo guarda varios valores del mismo tipo bajo un nombre: int[] victorias = new int[2];. El tamaño es fijo y cada posición empieza con su valor por defecto (0, false, '\u0000' o null).
  • Los índices van de 0 a length - 1 (distancia desde el principio). Salirse lanza ArrayIndexOutOfBoundsException: comprueba los índices que vienen de fuera.
  • Un índice puede ser una variable o una cuenta: victorias[turno]++ sustituye a un if.
  • char[][] casillas = new char[3][3] es una matriz: un arreglo de filas. Se accede con [fila][columna]; fila primero.
  • El char por defecto no es el espacio: por eso Tablero llama a reiniciar() en su constructor.
  • Una variable de arreglo guarda una referencia: = comparte, clone() de una matriz copia solo el exterior, y obtenerCopia copia casilla por casilla para que Minimax simule sin tocar la partida.
  • Arreglos literales como int[][] lineas convierten una lista de casos en datos que se recorren con un bucle; un int[] permite devolver varios valores a la vez.
  • Arrays.toString, Arrays.deepToString y Arrays.fill ayudan a imprimir y llenar arreglos.
Aplícalo fuera del Totito
  • Calificaciones de un curso: un double[] notas para calcular promedio, nota máxima y cuántos aprobaron; una matriz double[][] con una fila por alumno y una columna por examen.
  • Ventas por día de la semana: int[] ventas = new int[7] y ventas[dia]++ en cada venta, igual que victorias[turno]++. Un histograma, sin un solo if.
  • Juegos de cuadrícula: Conecta 4 (char[6][7]), Buscaminas (boolean[][] minas y int[][] vecinas) o un editor de píxeles. Y en todos ellos, si hay «deshacer» o una IA que simula, copia profunda como obtenerCopia.
  • Tablas de configuración: los precios por talla, las recompensas por nivel o los días de cada mes (int[] diasPorMes = {31, 28, 31, …}) como datos literales en lugar de cadenas de if.
Ejercicios
  1. Crea un int[] puntos = {3, 7, 2, 9, 4} e imprime, con bucles, la suma, el mayor y la posición del mayor. Pista: para el mayor, empieza con Integer.MIN_VALUE, como mejorValor en la IA.
  2. Declara una matriz literal de 3×3 con una partida a medias e imprime, con dos bucles, cuántas X, cuántas O y cuántas casillas vacías tiene.
  3. Escribe la copia profunda de un char[][] de cualquier tamaño, usando origen.length y origen[fila].length en lugar de 3. Comprueba que modificar la copia no altera el original.
  4. Usando la tabla lineas, cuenta en cuántas líneas una ficha tiene dos casillas propias y la tercera vacía (una «amenaza» de victoria). Prueba con un tablero donde la X amenace en dos líneas a la vez.
