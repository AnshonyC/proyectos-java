Capítulo 63El archivo .jar

Hasta ahora el Totito vive repartido en 42 archivos .class dentro de target\classes. En este capítulo descubres cómo NetBeans los empaqueta en un único archivo, Totito-1.0-SNAPSHOT.jar, qué lleva dentro, cómo sabe Java por dónde arrancarlo y por qué, aun así, no basta para compartir el juego con cualquier persona.

El problema: un programa hecho de muchas piezas

En el capítulo 11 viste el camino de un programa Java: escribes código fuente (.java), el compilador javac lo traduce a bytecode (.class) y la máquina virtual de Java (JVM) ejecuta ese bytecode. Cada clase produce su propio .class, y algunas producen varios: el Totito tiene 29 archivos .java pero genera 42 archivos .class. Más abajo verás por qué.

Imagina que quieres pasarle el juego a un amigo. ¿Le mandas 42 archivos sueltos y le explicas que tiene que escribir java -cp carpeta TotitoApp sabiendo de memoria que la clase de arranque se llama TotitoApp? Es como regalar un rompecabezas sin la caja y sin la foto de cómo queda. Hace falta una sola pieza que contenga todo y que diga por dónde se empieza. Esa pieza es el .jar.

Qué es un .jar

Un .jar es un .zip con otro nombre. JAR significa Java ARchive, «archivo de Java». Por dentro es exactamente un archivo comprimido ZIP, el mismo formato que usas para mandar fotos por correo. Lleva tus .class (y, si los tuviera, imágenes, sonidos o textos) más una carpeta especial, META-INF, con un archivo de instrucciones llamado manifiesto.

Que sea un ZIP tiene ventajas muy prácticas: ocupa menos (está comprimido), viaja como un solo archivo y cualquier programa que abra ZIP puede mirar su contenido. Java, además, sabe leer clases directamente desde dentro del .jar, sin descomprimirlo en el disco.

Una analogía: el .jar es una lonchera. Dentro van todos los alimentos (las clases) y pegada en la tapa va una nota (el manifiesto) que dice «empieza por el sándwich». Quien abre la lonchera no tiene que adivinar.

Sin NetBeans. Si tienes Maven instalado aparte, el mismo resultado se obtiene con mvn clean package desde la carpeta del proyecto. NetBeans, en el fondo, ejecuta exactamente eso con el Maven que trae dentro.

¿De dónde sale el nombre?

Maven arma el nombre con dos datos del pom.xml (capítulo 5): <artifactId>Totito</artifactId> y <version>1.0-SNAPSHOT</version>, unidos por un guion. SNAPSHOT («instantánea») es la forma en que Maven dice «versión en desarrollo, todavía puede cambiar». No te preocupes por ese nombre feo: quien use tu programa nunca lo verá. En los capítulos 65 y 66 jpackage le pondrá al programa la versión pública, 1.0.0, con la opción --app-version, y en el capítulo 67 verás qué significa cada número.

Mirar dentro del .jar

Como es un ZIP, hay dos formas de abrirlo.

Forma 1: con el Explorador de Windows

Haz una copia con extensión .zip y ábrela con doble clic. La copia va a dist\, una carpeta que el .gitignore ya ignora (capítulo 5), así no ensucias el proyecto:

New-Item -ItemType Directory -Force dist | Out-Null
Copy-Item target\Totito-1.0-SNAPSHOT.jar dist\mirar.zip
explorer dist\mirar.zip

Se abre como cualquier ZIP. Verás la carpeta META-INF y todos los .class.

Forma 2: con la herramienta jar del JDK

El JDK trae un programa llamado jar que crea y lista estos archivos. La opción tf significa «tabla de contenido del fichero que te indico»:

Son 49 entradas en total: 42 clases y 7 de la carpeta META-INF. Fíjate en tres cosas:

  • Las clases con $. Partida$Modo.class es el enum Modo que vive dentro de Partida (capítulo 26); Iconos$Icono.class es la interfaz interna Icono; PanelTablero$1.class es una clase anónima, el MouseAdapter que se creó con new MouseAdapter() { ... } (capítulo 25). Java guarda cada clase interna en su propio archivo con el nombre Externa$Interna, y a las anónimas les pone números. Por eso 29 archivos fuente se convierten en 42 .class (29 + 13 con $).
  • Está también JuegoMain.class, la ventana sencilla del capítulo 33. El .jar lleva todo lo que hay en src.
  • No están las carpetas herramientas ni recursos: Maven solo empaqueta lo que hay en src (lo dice <sourceDirectory>src</sourceDirectory> del pom.xml). Las herramientas son para ti, no para quien juega.

La carpeta META-INF/maven/ la añade Maven con una copia del pom.xml y un pom.properties con el grupo, el nombre y la versión. Sirve para que otras herramientas sepan de qué proyecto salió ese .jar. Al juego no le afecta.

El manifiesto: la nota en la tapa

El archivo más importante del .jar es META-INF/MANIFEST.MF. Para leerlo, extráelo a una carpeta de usar y tirar dentro de dist. La opción xf del programa jar significa «extraer del fichero» y extrae en la carpeta actual, por eso primero entramos a dist\mirar:

New-Item -ItemType Directory -Force dist\mirar | Out-Null
cd dist\mirar
jar xf ..\..\target\Totito-1.0-SNAPSHOT.jar META-INF/MANIFEST.MF
Get-Content META-INF\MANIFEST.MF
cd ..\..

Este es el manifiesto real del Totito, compilado con el JDK 21:

Manifest-Version: 1.0
Created-By: Maven JAR Plugin 3.4.2
Build-Jdk-Spec: 21
Main-Class: TotitoApp

Cuatro líneas, cada una con la forma Nombre: valor:

LíneaQué significa¿Importa?
Manifest-Version: 1.0La versión del formato del manifiesto. Siempre es 1.0Obligatoria, pero nunca cambia
Created-By: Maven JAR Plugin 3.4.2Quién fabricó el .jarSolo informativa
Build-Jdk-Spec: 21La versión del JDK con que se compiló (el tuyo, el 21)Solo informativa: el bytecode es para Java 17, por el release 17 del pom.xml
Main-Class: TotitoAppLa clase cuyo main se ejecuta al arrancar el .jarLa clave de todo

La línea Main-Class no apareció por arte de magia: la pediste tú en el pom.xml del capítulo 5, en la configuración del maven-jar-plugin:

<plugin>
    <!-- Deja el .jar ejecutable con doble clic o con java -jar. -->
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-jar-plugin</artifactId>
    <version>3.4.2</version>
    <configuration>
        <archive>
            <manifest>
                <mainClass>TotitoApp</mainClass>
            </manifest>
        </archive>
    </configuration>
</plugin>

Ese bloque dice: «cuando fabriques el .jar, escribe en su manifiesto que la clase principal es TotitoApp». Como las clases del Totito no tienen paquete (están en <default package>), el nombre es solo TotitoApp. En un proyecto con paquetes sería el nombre completo, por ejemplo gt.totito.TotitoApp.

Si escribes un manifiesto a mano. El formato es quisquilloso: cada línea termina con un salto de línea, incluida la última. Si la última línea no lo tiene, Java la ignora en silencio y tu Main-Class desaparece. Tampoco puede haber espacios antes de los dos puntos. Es una de las razones por las que es mejor dejar que Maven o la herramienta jar lo escriban.

¿Y si no hubiera Main-Class?

Probé a crear un .jar con las mismas clases pero sin esa línea. Al ejecutarlo, esto es lo que respondió Java:

no main manifest attribute, in SinMain.jar

«No hay atributo principal en el manifiesto». Java abre el .jar, lee la nota de la tapa, no encuentra «empieza por aquí» y se rinde. Si alguna vez ves ese mensaje con un proyecto tuyo, revisa la configuración del maven-jar-plugin en el pom.xml.

Ejecutar el .jar

Con java -jar

java -jar target\Totito-1.0-SNAPSHOT.jar

La opción -jar le dice a Java: «el argumento siguiente es un .jar; abre su manifiesto, busca Main-Class y ejecuta su main». La ventana del Totito aparece igual que en NetBeans. Compáralo con lo que usabas antes:

ComandoQué le dices a Java
java -cp out TotitoApp«Busca clases en la carpeta out y ejecuta TotitoApp». Tú dices la clase
java -cp target\classes herramientas\X.java«Compila y ejecuta este archivo suelto, usando las clases de target\classes»
java -jar target\Totito-1.0-SNAPSHOT.jar«Ejecuta este .jar; la clase te la dice su manifiesto»

Un detalle curioso: como el .jar también trae JuegoMain, puedes arrancar la versión vieja usando el .jar como si fuera una carpeta de clases, con -cp:

java -cp target\Totito-1.0-SNAPSHOT.jar JuegoMain

Aquí el manifiesto se ignora: -cp (classpath, «ruta de clases») dice dónde buscar y tú nombras la clase.

Sin ventana negra: javaw

Cuando ejecutas con java, la ventana de PowerShell se queda ocupada mientras el juego está abierto: ahí aparecerían los mensajes de System.out y los stack traces. En Windows existe una variante, javaw (la w es de window), que arranca el programa sin consola y te devuelve el control de PowerShell enseguida:

javaw -jar target\Totito-1.0-SNAPSHOT.jar

Úsalo para jugar; usa java cuando quieras ver los errores (capítulo 62).

Con doble clic

Si al instalar el JDK quedó asociada la extensión .jar (el instalador de Temurin suele ofrecer esa opción), un doble clic sobre el archivo en el Explorador abre el juego con javaw. Si en cambio Windows te pregunta con qué programa abrirlo, o lo abre un programa de archivos comprimidos como 7-Zip o WinRAR, la asociación no está hecha. No pasa nada: no la necesitas, porque en los capítulos siguientes vas a tener un Totito.exe de verdad.

Crear el .jar sin Maven

Para entender que no hay magia, puedes fabricar un .jar a mano con las dos herramientas del JDK. Primero compilas a la carpeta out (capítulo 11) y después empaquetas esa carpeta:

javac -encoding UTF-8 -d out src\*.java
jar --create --file dist\Totito-manual.jar --main-class TotitoApp -C out .
java -jar dist\Totito-manual.jar
ParteSignificado
jar --createCrear un .jar nuevo
--file dist\Totito-manual.jarCómo se llamará y dónde quedará
--main-class TotitoAppEscribe Main-Class: TotitoApp en el manifiesto
-C out .«Cámbiate (C) a la carpeta out y mete todo lo que hay ahí (. = esta carpeta)». Sin el -C, las clases quedarían dentro de una subcarpeta out/ en el ZIP y Java no las encontraría

Funciona igual. Su manifiesto dice Created-By: con la versión de tu JDK en vez de Maven JAR Plugin, y no lleva la carpeta META-INF/maven. Para el resto del libro seguimos usando el de Maven, target\Totito-1.0-SNAPSHOT.jar, que es el que fabrica NetBeans.

El gran problema: el .jar necesita Java

Un .jar no es un programa de Windows. Es bytecode, y el bytecode no lo entiende el procesador: lo entiende la JVM. Por eso, para abrir tu Totito, la otra persona necesita:

  1. Tener Java instalado,
  2. que sea Java 17 o más nuevo,
  3. que esté en el PATH o que el .jar esté asociado a él, y
  4. saber qué hacer con un archivo de extensión desconocida.

Ahora piensa en tu tía, en tu compañero de clase o en un desconocido que encontró tu juego en GitHub. La mayoría no cumple el punto 1, y los que sí, quizás no cumplen el 2. Pedirles que instalen un JDK de 300 MB para jugar al totito es pedir demasiado: lo van a cerrar.

Fíjate en la penúltima fila: el .jar tiene una virtud que el .exe no tiene. El mismo archivo funciona en Windows, Linux y macOS, porque cada sistema pone su propia JVM. Es la famosa promesa de Java: «escríbelo una vez, ejecútalo en cualquier parte». El precio es que la JVM tiene que estar.

La solución: llevar la JVM dentro. Si el problema es que la otra persona no tiene Java, la solución es regalarle un Java junto con el juego: uno pequeñito, recortado a la medida, que solo use el Totito y que no se instale en su sistema. Eso hace jpackage, una herramienta que viene en tu JDK 21. Toma tu .jar, le añade un Java recortado y un lanzador Totito.exe con tu icono. Lo verás en el capítulo 65, después de fabricar ese icono en el 64. Por eso el .jar no es el final del camino, sino la materia prima de lo que sigue.
Git Este capítulo no tiene commit: el .jar se fabrica a partir del código, que ya está en GitHub. Compruébalo: 
git status
No aparece ni target\ ni dist\, porque están en el .gitignore. Es a propósito: los archivos que se generan no se suben al repositorio. Se pueden volver a fabricar en segundos, cambian con cada compilación (llenarían el historial de versiones binarias imposibles de comparar) y pesan. El lugar correcto para compartir un archivo generado es una Release de GitHub (capítulo 67), no el código fuente.
Hito Tienes el Totito en un único archivo, sabes exactamente qué lleva dentro y lo arrancas con java -jar. Es la pieza con la que jpackage va a fabricar el .exe.

Resumen

  • Un .jar (Java ARchive) es un ZIP con tus .class y una carpeta META-INF con el manifiesto.
  • Clean and Build ejecuta las fases de Maven: clean, resources, compile, test y jar. El resultado es target\Totito-1.0-SNAPSHOT.jar (unos 77 KB).
  • Las clases internas y anónimas generan archivos con $; por eso 29 fuentes dan 42 .class.
  • El manifiesto META-INF/MANIFEST.MF lleva Main-Class: TotitoApp, que sale del maven-jar-plugin del pom.xml. Sin esa línea, Java responde no main manifest attribute.
  • java -jar ejecuta el .jar leyendo el manifiesto; javaw -jar hace lo mismo sin consola.
  • jar tf lista el contenido, jar xf extrae y jar --create --main-class fabrica un .jar a mano.
  • Un .jar exige tener Java 17 o más nuevo instalado; con un Java viejo aparece UnsupportedClassVersionError. Por eso existe jpackage.
  • Los archivos generados (target, dist) no se suben a Git.
Aplícalo fuera del Totito
  • Una herramienta para ti o para tu equipo de trabajo (un conversor de archivos, un generador de reportes): si todos tienen Java, un .jar de pocos KB es la forma más ligera de compartirla. Basta un java -jar herramienta.jar.
  • Un programa para un servidor: las aplicaciones web con Spring Boot (capítulo 69) se entregan como un único .jar que se arranca con java -jar. Lo que aprendiste del manifiesto es exactamente lo que usan, con una Main-Class especial de Spring.
  • Cualquier .jar que descargues de internet: ahora puedes mirar qué lleva dentro con jar tf y leer su manifiesto antes de ejecutarlo, para saber qué clase arranca y con qué versión de Java se fabricó.
  • Librerías: cuando un proyecto usa una librería (por ejemplo, el conector de MySQL o JUnit), lo que Maven descarga son .jar sin Main-Class. No se ejecutan solos: son cajas de clases para que tu programa las use mediante -cp.
