Capítulo 35Teoría del color para programadores

Para la computadora, un color es un trío de números. En este capítulo aprendes qué significan esos números, cómo se escriben (RGB, hexadecimal, HSB), qué es la transparencia, cómo se arma una paleta que se vea bien y se lea bien, y cómo se fabrica el brillo de neón del Totito con nada más que capas de color transparente.

Por qué un programador necesita saber de color

En la Parte VII vas a escribir cosas como new Color(0xFF, 0x3B, 0xD4), Tema.conAlfa(color, 125) o Tema.aclarar(color, 0.6f). Si no sabes qué significan esos números, solo puedes copiarlos; si lo sabes, puedes inventar los tuyos: cambiar la paleta del juego, crear un modo claro o elegir colores para cualquier otro programa sin que se vea feo ni sea difícil de leer.

La buena noticia es que el color en pantalla es mucho más sencillo que el color en pintura. Todo se reduce a mezclar tres luces.

La pantalla mezcla luz: el modelo RGB

Si miras la pantalla de tu computadora con una lupa verás que cada punto (cada píxel) está formado por tres lucecitas diminutas: una roja, una verde y una azul. Variando cuánto brilla cada una, el ojo ve millones de colores distintos. Por eso el modelo se llama RGB, por sus iniciales en inglés: Red, Green, Blue.

Esto es mezcla de luz, llamada mezcla aditiva: cuanta más luz sumas, más claro se vuelve. Es al revés que con las pinturas (mezcla sustractiva), donde cuanto más mezclas, más oscuro y sucio queda. Por eso en la escuela aprendiste que «amarillo + azul = verde», y en la pantalla en cambio:

Luces encendidasResultadoMuestra
Rojo + verdeAmarillo
Verde + azulCian (celeste)
Rojo + azulMagenta (fucsia)
Las tres a topeBlanco
NingunaNegro

Fíjate: el rosa del Totito (mucho rojo, un poco de verde, bastante azul) está cerca del magenta, y el blanco del centro del neón aparece cuando las tres luces se acercan al máximo. Ese hecho explica el truco del «centro blanco» que verás al final del capítulo.

Cada canal va de 0 a 255

Cada una de las tres luces se llama canal, y su intensidad se guarda en un número entero entre 0 (apagada) y 255 (a tope). ¿Por qué 255 y no 100? Porque cada canal ocupa un byte, es decir, 8 bits, y con 8 bits se pueden escribir 28 = 256 valores distintos: del 0 al 255. Con tres canales hay 256 × 256 × 256 = 16 777 216 colores posibles, más de los que el ojo distingue.

En Java un color es un objeto de la clase java.awt.Color y se crea con sus tres canales:

Color rojo   = new Color(255, 0, 0);
Color negro  = new Color(0, 0, 0);
Color blanco = new Color(255, 255, 255);
Color gris   = new Color(128, 128, 128);   // los tres iguales = gris
Color rosa   = new Color(255, 59, 212);    // el ROSA del Totito

Una regla útil: cuando los tres canales son iguales, el resultado es un gris (más claro cuanto mayor el número). Cuanto más distintos son entre sí, más «colorido» (saturado) es el color.

Hexadecimal: el mismo color escrito de otra forma

En diseño casi nunca verás «255, 59, 212». Verás #FF3BD4. Es exactamente el mismo color, escrito en hexadecimal: un sistema de numeración en base 16.

Contar en base 16

Nosotros contamos en base 10: diez dígitos (0 a 9) y, al pasar del 9, agregamos una columna (10). En base 16 hay dieciséis dígitos. Como solo tenemos diez símbolos numéricos, se usan letras para los otros seis:

Hexadecimal01…9ABCDEF
Decimal01…9101112131415

Un número hexadecimal de dos dígitos vale (primer dígito × 16) + segundo dígito, igual que en decimal «47» vale 4 × 10 + 7. Con dos dígitos hexadecimales se llega exactamente a FF = 15 × 16 + 15 = 255: un canal cabe justo en dos dígitos hexadecimales. Por eso un color se escribe con seis: dos para el rojo, dos para el verde y dos para el azul.

#FF3BD4 paso a paso

  1. Quita el # (solo avisa que viene un color) y parte el resto en tres pares: FF | 3B | D4.
  2. Rojo, FF: F vale 15. 15 × 16 + 15 = 240 + 15 = 255.
  3. Verde, 3B: 3 vale 3 y B vale 11. 3 × 16 + 11 = 48 + 11 = 59.
  4. Azul, D4: D vale 13 y 4 vale 4. 13 × 16 + 4 = 208 + 4 = 212.
  5. Resultado: (255, 59, 212), el rosa de la X.

Y al revés, de decimal a hexadecimal: divide entre 16; el cociente es el primer dígito y el residuo el segundo. Para 212: 212 ÷ 16 = 13, residuo 4 → «D4». Para 59: 59 ÷ 16 = 3, residuo 11 → «3B».

Hexadecimal en Java

Java entiende números hexadecimales si los escribes con el prefijo 0x (cero, equis). Por eso Tema declara sus colores así:

public static final Color ROSA = new Color(0xFF, 0x3B, 0xD4);

Para Java, 0xFF es exactamente el número 255; solo cambia cómo lo escribiste. La ventaja es que puedes copiar los pares tal cual vienen de una herramienta de diseño, sin convertir nada a mano. Hay otras formas equivalentes que te encontrarás:

Color a = new Color(0xFF, 0x3B, 0xD4);   // tres canales en hexadecimal
Color b = new Color(255, 59, 212);       // los mismos en decimal
Color c = new Color(0xFF3BD4);           // un solo número con los seis dígitos
Color d = Color.decode("#FF3BD4");       // a partir del texto con almohadilla

Las cuatro crean el mismo color. El camino inverso, de un Color a su texto #RRGGBB, lo hace Tema.hex con String.format("#%02X%02X%02X", …): %02X significa «escribe este entero en hexadecimal con mayúsculas (X), con 2 dígitos y rellenando con 0 a la izquierda». El Totito lo usa para colorear la X y la O dentro del texto HTML de las instrucciones (capítulo 57). Puedes comprobar todo esto en jshell:

jshell> Integer.parseInt("3B", 16)
$1 ==> 59

jshell> Integer.toHexString(212)
$2 ==> "d4"

jshell> java.awt.Color.decode("#FF3BD4")
$3 ==> java.awt.Color[r=255,g=59,b=212]

El cuarto canal: alfa y la transparencia

Además de rojo, verde y azul, un color puede tener un cuarto número: el canal alfa, que indica cuán opaco es. También va de 0 a 255: 0 es completamente invisible, 255 es completamente opaco (tapa lo que hay detrás) y los valores intermedios dejan ver el fondo en parte. En Java se pasa como cuarto argumento:

public static final Color SUPERFICIE = new Color(0x2B, 0x23, 0x63, 125);

Cómo se mezcla un color transparente con el fondo

Cuando pintas un color con alfa sobre otro, la pantalla calcula una mezcla canal por canal. La fórmula, para cada canal, es:

resultado = color × (alfa ÷ 255) + fondo × (1 − alfa ÷ 255)

Es un promedio ponderado: con alfa 255 el resultado es el color; con alfa 0 es el fondo; con alfa 125 (casi la mitad) es casi mitad y mitad. Calculemos la SUPERFICIE de las tarjetas (43, 35, 99, alfa 125) pintada sobre FONDO_ARRIBA (28, 23, 64):

CanalCálculoResultado
Rojo(43 × 125 + 28 × 130) ÷ 255 = 9015 ÷ 25535
Verde(35 × 125 + 23 × 130) ÷ 255 = 7365 ÷ 25529
Azul(99 × 125 + 64 × 130) ÷ 255 = 20695 ÷ 25581

(130 es 255 − 125, la parte del fondo). La tarjeta se ve de color (35, 29, 81): un poco más clara que el fondo, pero teñida por él.

Por qué la SUPERFICIE tiene alfa 125

Mira la captura del menú: a través de la tarjeta se adivinan, muy tenues, la X y la O gigantes del fondo. Ese efecto se llama cristal o, en la jerga del diseño, glassmorphism: superficies semitransparentes que parecen láminas de vidrio esmerilado. Lo consigue el alfa 125, que es aproximadamente el 49 % de opacidad. Con un número mayor (200, por ejemplo) la tarjeta taparía casi del todo el fondo y se perdería la sensación de profundidad; con uno menor (60) el texto encima competiría con los adornos y costaría leerlo. El valor 125 es el equilibrio entre «se ve el fondo» y «se lee lo de encima».

Otros alfas del Tema siguen la misma lógica:

  • DECORACION, alfa 70 (≈ 27 %): las X y O gigantes del fondo deben verse, pero sin llamar la atención.
  • CASILLA, alfa 170 (≈ 67 %): las casillas del tablero deben destacar más que la tarjeta para que se vea dónde hacer clic.

Cambiar solo la transparencia: conAlfa

Muy a menudo se necesita «este mismo color, pero más transparente». Para eso Tema tiene un método:

public static Color conAlfa(Color color, int alfa) {
    return new Color(color.getRed(), color.getGreen(), color.getBlue(),
            Math.max(0, Math.min(255, alfa)));
}

Copia los tres canales y pone el alfa pedido, recortado para que nunca se salga del rango 0–255 (si se saliera, el constructor de Color lanzaría una IllegalArgumentException, capítulo 26). Es probablemente el método más usado de toda la interfaz: el relleno de los botones del menú es conAlfa(color, 65), el de los adornos de puntos es conAlfa(LAVANDA, 45), y el halo del neón son seis llamadas a conAlfa con alfas crecientes.

Dos maneras de hacer transparencia El alfa de un Color afecta solo a lo que pintes con ese color. En el capítulo 37 verás otra herramienta, AlphaComposite, que vuelve transparente todo lo que se dibuje a continuación, sea del color que sea. El Totito la usa para apagar un botón desactivado (todo al 40 %) y para la ficha «fantasma» del tablero (todo al 28 %).

HSB: pensar el color como lo piensa una persona

RGB es cómo funciona la pantalla, pero no es cómo pensamos las personas. Nadie dice «quiero subir el verde a 80 y bajar el azul a 190». Decimos «quiero este mismo morado, pero más oscuro» o «más apagado». Para eso existe otro modelo: HSB.

LetraNombreQué mideRango
H (Hue)Matiz o tono«Qué color es»: rojo, naranja, verde, azul… Se mide como un ángulo en el círculo cromático.0° a 360°
S (Saturation)SaturaciónCuán puro o intenso es. 0 % es un gris; 100 % es el color más vivo posible.0 % a 100 %
B (Brightness)BrilloCuánta luz tiene. 0 % es negro siempre; 100 % es el color con toda su luz.0 % a 100 %

El rosa #FF3BD4 en HSB es: matiz 313° (entre el magenta, 300°, y el rosa, 330°), saturación 77 % y brillo 100 %. Java convierte en las dos direcciones, pero con una particularidad: los tres valores van de 0 a 1 en lugar de en grados y porcentajes. El matiz 313° se escribe 313 ÷ 360:

float[] hsb = Color.RGBtoHSB(255, 59, 212, null);   // {0.87, 0.77, 1.0}
Color rosa  = Color.getHSBColor(313 / 360f, 0.77f, 1f); // vuelve a dar (255, 59, 212)

(La f de 360f indica un número float; sin ella, 313 / 360 sería una división entera y daría 0.)

¿Para qué sirve? Para crear variantes coherentes de un color. Si mantienes el matiz y solo mueves la saturación o el brillo, el resultado «es de la misma familia». Mira cómo lo hace la paleta del Totito:

ConstanteMatizSaturaciónBrilloLectura

FONDO_ABAJO247°69 %14 %El mismo, más oscuro aún
SUPERFICIE248°65 %39 %El mismo, algo más claro

¡Seis colores de la paleta comparten casi el mismo matiz (247°–252°)! Solo cambian saturación y brillo. Por eso el fondo, las tarjetas, las casillas y los textos secundarios combinan tan bien: son el mismo color en distintas intensidades.

HSB y HSL no son lo mismo En páginas web verás HSL (Lightness, luminosidad) en lugar de HSB. El matiz y la idea son iguales, pero la tercera medida cambia: en HSL, el 50 % es el color puro y el 100 % es siempre blanco; en HSB, el 100 % es el color puro con toda su luz. Si copias valores de una herramienta, fíjate en cuál de los dos usa. Java trae HSB.

El círculo cromático

Si pones los matices en un círculo, de 0° a 360°, obtienes el círculo cromático. El rojo está en 0°, el amarillo en 60°, el verde en 120°, el cian en 180°, el azul en 240° y el magenta en 300°; luego se vuelve al rojo. Los colores del Totito ocupan un sector bien definido:

Armonías: qué colores combinan

Las combinaciones de colores que «se ven bien juntas» siguen patrones geométricos sobre el círculo. Los cinco más conocidos:

ArmoníaCómo se eligeSensaciónEjemplo
MonocromáticaUn solo matiz con distintas saturaciones y brillos.Tranquila, elegante.El fondo, las tarjetas y los textos suaves del Totito (247°–252°).
AnálogaColores vecinos en el círculo, dentro de unos 30°–150°.Armoniosa, natural.Azul → morado → rosa del Totito.
ComplementariaDos colores opuestos (a 180°).Contraste máximo, enérgica, puede «vibrar».Azul y naranja de un cartel de cine.

El Totito combina dos: una base monocromática (todo el fondo y las superficies, en violeta oscuro) y unos acentos análogos (cian, azul, morado, rosa y fresa, que van de 197° a 339° sin saltar a la otra mitad del círculo). Esa mezcla es la receta típica de la estética «neón» o synthwave: noche violeta con luces frías y rosadas.

¿Y los complementarios? El opuesto del rosa (313°) es un verde (133°) y el del azul (215°) es un naranja (35°). El Totito no los usa a propósito: un verde brillante junto al rosa rompería el ambiente. Pero guárdalos en la cabeza: el complementario es la mejor herramienta cuando algo tiene que destacar sobre todo lo demás, como un aviso de error o un botón de compra.

¿Cómo se distinguen la X y la O si son «vecinas»? El rosa (313°) y el azul (215°) están a casi 100° de distancia: lo bastante lejos para no confundirse, lo bastante cerca para pertenecer a la misma familia. Y el morado (265°), que está justo en medio, sirve de «puente» entre los dos: por eso es el color de los bordes neutros (tarjetas, tablero, botón «Salir»).

Cómo se construyó esta paleta

  1. Muestrear: con el cuentagotas (capítulo 34) se tomaron colores del diseño en zonas lisas: el fondo arriba y abajo, el interior de las tarjetas, el centro de los bordes brillantes, los textos.
  2. Agrupar: las muestras parecidas se juntaron en roles. Hubo decenas de rosas ligeramente distintos (la compresión JPG y el halo los alteran); todos eran «el rosa de la X».
  3. Elegir un representante por rol y redondearlo a un valor limpio, a veces subiendo la saturación para que en pantalla brillara tanto como en el diseño.
  4. Comprobar el contraste de los textos sobre los fondos (lo verás enseguida) y corregir si hacía falta.
  5. Ponerle nombre y guardarlo en un solo sitio: la clase Tema.

Nombres de color: por apariencia o por función

Fíjate en que los nombres de Tema son de dos tipos. Unos describen cómo se ve el color (ROSA, AZUL, LAVANDA); otros, para qué sirve (FONDO_ARRIBA, TEXTO, SUPERFICIE, CASILLA). Los segundos son más robustos: si mañana decides que el texto sea crema en lugar de blanco, TEXTO sigue siendo un buen nombre; si decides que la X sea verde, ROSA se vuelve un nombre mentiroso. Por eso Tema agrega una capa de función encima de los nombres de apariencia:

public static Color colorDeFicha(char ficha) {
    return ficha == 'X' ? ROSA : AZUL;
}

Las pantallas nunca preguntan «¿es rosa?»; preguntan «¿de qué color es esta ficha?». Si un día cambias el color de la X, cambias una línea aquí y el juego entero obedece.

La regla 60-30-10 Una guía clásica para repartir una paleta: un color dominante en el 60 % de la superficie (en el Totito, el violeta oscuro del fondo), uno secundario en el 30 % (las superficies de cristal y los bordes morados) y los acentos en el 10 % (rosa, azul, cian). Los acentos funcionan precisamente porque son escasos: si todo brilla, nada destaca.

El color tiene significado

Los colores comunican antes que las palabras. Algunas asociaciones son culturales (en muchos países el rojo es peligro o error y el verde es correcto o continuar); otras las crea el propio programa, y una vez creadas hay que respetarlas siempre.

La X es rosa, la O es azul

Es la regla de color más importante del Totito, y está escrita en el comentario de colorDeFicha: «La X siempre es rosa y la O siempre es azul, la juegue quien la juegue». Se cumple en todas partes:

  • En el tablero, las fichas.
  • En el marcador, el lado de cada jugador toma el color de su ficha.
  • En el letrero de turno y en el título de la victoria, el degradado sale del color de la ficha del ganador: si gana la O, «¡Ganó Luis!» es celeste; si gana la X, rosa.
  • En la raya ganadora.
  • Incluso en el texto de las instrucciones, donde la letra «X» va en rosa y la «O» en azul.

Después de una partida, el jugador asocia sin pensarlo «rosa = X». Si en alguna pantalla la X apareciera azul, se confundiría. Esta consistencia es lo que convierte el color en un lenguaje.

Hay un caso sutil: la tarjeta del Jugador 1 en Configuración es FRESA, no ROSA. ¿Por qué otro color? Porque el Jugador 1 puede elegir jugar con la O. Si su tarjeta fuera del mismo rosa que la X, el color diría «este jugador es la X» aunque no lo sea. El rosa-rojizo de la tarjeta identifica al jugador; el rosa de la X identifica a la ficha. Son conceptos distintos y merecen colores distintos (aunque parecidos, para que la pantalla siga en armonía).

Colores neutros para «nadie»

Cuando hay empate, el título «¡Empate!» va de lavanda a morado. No es casualidad: el morado es el punto medio entre el rosa y el azul, el color que no pertenece a ningún jugador. Por la misma razón los bordes de las tarjetas genéricas y del tablero son morados.

Nunca dependas solo del color

Alrededor de un 8 % de los hombres y un 0,5 % de las mujeres tienen alguna forma de daltonismo (dificultad para distinguir ciertos colores). Si la única diferencia entre dos cosas es el color, para esas personas son iguales. El Totito lo resuelve sin esfuerzo: la X y la O se distinguen por su forma, no solo por su color. Y el estado «seleccionado» de las opciones se marca con un circulito relleno además del brillo. Aplica siempre esta regla: el color refuerza un mensaje, pero el mensaje debe entenderse también sin él (con una forma, un icono o una palabra).

Contraste y accesibilidad: que se pueda leer

Un texto bonito que no se lee es un texto inútil. El contraste es la diferencia de luminosidad entre un texto y su fondo. Hay una forma estándar de medirlo, definida por las pautas internacionales de accesibilidad web, WCAG (Web Content Accessibility Guidelines), que se aplica igual a cualquier programa.

Luminancia relativa: cuánta luz «ve» el ojo

El primer paso es calcular la luminancia relativa de cada color: un número de 0 (negro) a 1 (blanco) que dice cuánta luz percibe el ojo. No basta con promediar los canales, porque el ojo es mucho más sensible al verde que al azul: un verde puro parece mucho más luminoso que un azul puro. La fórmula tiene dos pasos:

  1. Cada canal se pasa de 0–255 a una escala «lineal» de luz (una pequeña fórmula de la norma sRGB que deshace la corrección que aplican las pantallas).
  2. Se suman los tres con pesos distintos: L = 0,2126 × R + 0,7152 × G + 0,0722 × B. El verde pesa el 72 %; el azul, apenas el 7 %.

La relación de contraste

Con las dos luminancias (la del color más claro, L1, y la del más oscuro, L2):

contraste = (L1 + 0,05) ÷ (L2 + 0,05)

El resultado va de 1 (dos colores iguales, contraste nulo) a 21 (blanco sobre negro). El 0,05 representa la luz ambiente que siempre se refleja en la pantalla. Las pautas piden:

QuéMínimo (nivel AA)Recomendado (nivel AAA)
Texto normal4,5 : 17 : 1
Texto grande (desde unos 24 px, o 19 px en negrita)3 : 14,5 : 1
Bordes de controles, iconos importantes3 : 1—

Ejemplo calculado: TEXTO sobre FONDO_ARRIBA

El texto blanco tiene luminancia 1 (es el máximo). Para FONDO_ARRIBA (28, 23, 64):

  1. Canales lineales: rojo 28 → 0,0116; verde 23 → 0,0086; azul 64 → 0,0513.
  2. L = 0,2126 × 0,0116 + 0,7152 × 0,0086 + 0,0722 × 0,0513 = 0,0025 + 0,0061 + 0,0037 = 0,0123.
  3. Contraste = (1 + 0,05) ÷ (0,0123 + 0,05) = 1,05 ÷ 0,0623 = 16,85 : 1.

El contraste bajo es una decisión, no un descuido Que DECORACION tenga contraste 2,19 está bien porque es decoración. El error sería usarla para un texto. Cada vez que agregues texto a una interfaz, comprueba su contraste con el fondo real sobre el que se dibuja (no con el fondo «teórico»): un texto encima de una tarjeta transparente se ve sobre la mezcla.

Un programa para analizar colores

No tienes que hacer estas cuentas a mano. Este programa pequeño recibe un color en hexadecimal y te dice sus canales, su HSB, su luminancia y su contraste con el fondo del Totito. Para no mezclarlo con el proyecto, crea una carpeta de prácticas fuera de Totito (así no se cuela en el repositorio ni en el .jar):

New-Item -ItemType Directory -Force $HOME\Proyectos\Practicas | Out-Null
Set-Location $HOME\Proyectos\Practicas
notepad Colores.java

El Bloc de notas preguntará si quieres crear el archivo: di que sí, pega este código y guarda.

import java.awt.Color;

/** Analiza un color: RGB, HSB y contraste contra el fondo del Totito. */
public class Colores {

    public static void main(String[] args) {
        String hex = args.length > 0 ? args[0] : "#FF3BD4";
        Color color = Color.decode(hex);
        Color fondo = Color.decode("#1C1740");

        System.out.println("Color:  " + hex.toUpperCase());
        System.out.println("RGB:    " + color.getRed() + ", " + color.getGreen() + ", " + color.getBlue());

        float[] hsb = Color.RGBtoHSB(color.getRed(), color.getGreen(), color.getBlue(), null);
        System.out.printf("HSB:    matiz %.0f grados, saturacion %.0f %%, brillo %.0f %%%n",
                hsb[0] * 360, hsb[1] * 100, hsb[2] * 100);

        System.out.printf("Luminancia relativa: %.4f%n", luminancia(color));
        System.out.printf("Contraste con el fondo #1C1740: %.2f a 1%n", contraste(color, fondo));
    }

    /** Pasa un canal de 0-255 a luz "lineal" (formula de la norma sRGB). */
    static double lineal(int canal) {
        double c = canal / 255.0;
        return c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4);
    }

    /** Cuanta luz percibe el ojo: el verde pesa mucho, el azul muy poco. */
    static double luminancia(Color c) {
        return 0.2126 * lineal(c.getRed()) + 0.7152 * lineal(c.getGreen()) + 0.0722 * lineal(c.getBlue());
    }

    /** Relacion de contraste WCAG: de 1 (igual) a 21 (blanco sobre negro). */
    static double contraste(Color a, Color b) {
        double claro = Math.max(luminancia(a), luminancia(b));
        double oscuro = Math.min(luminancia(a), luminancia(b));
        return (claro + 0.05) / (oscuro + 0.05);
    }
}

Lo que hay de nuevo aquí: args son los textos que escribes después del nombre del programa al ejecutarlo (si no escribes ninguno, se usa el rosa); Color.decode convierte el texto en color; printf con %.2f escribe un decimal con dos cifras, %% escribe un signo de porcentaje y %n salta de línea (capítulo 17); y Math.pow(a, b) calcula a elevado a b. Ejecútalo directamente desde el código fuente (Java 11 o superior compila en memoria un programa de un solo archivo, sin javac):

java Colores.java "#FF3BD4"
java Colores.java "#A89BE2"

Color:  #A89BE2

Escribe siempre el color entre comillas. Y si tu Windows usa coma decimal, verás 5,48 en lugar de 5.48: printf respeta la configuración regional.

Modo oscuro

El Totito es una interfaz de modo oscuro: fondo oscuro y texto claro. No es solo una moda; para el estilo neón es obligatorio, y tiene sus propias reglas.

  • El brillo solo existe sobre lo oscuro. Un halo es luz que se suma al fondo. Sobre un fondo blanco no hay luz que sumar: el mismo halo se vería como una mancha borrosa. Por eso el neón y el modo oscuro van juntos.
  • Nada de negro puro. El fondo más oscuro del Totito es #0E0B24, no #000000. Un negro absoluto junto a colores muy brillantes produce un contraste agresivo que cansa la vista y hace que el texto blanco parezca «sangrar». Un fondo teñido del matiz de la paleta, además, hace que todo combine.
  • La profundidad se marca con claridad, no con sombras. En un modo claro, una tarjeta «flota» gracias a su sombra. Sobre un fondo casi negro las sombras no se ven. En su lugar, lo que está «más cerca» es más claro: el fondo (brillo 14–25 %) < las tarjetas (≈ 30 %) < las casillas < los bordes brillantes.
  • Satura con mesura las áreas grandes. Los colores muy saturados funcionan en líneas finas (bordes, letras, fichas), pero en superficies grandes «vibran». Por eso los rellenos del Totito son colores con alfa bajo (conAlfa(color, 30), conAlfa(color, 65)) y el color puro se reserva para el trazo.
  • Jerarquía con dos blancos. El texto importante es blanco puro; el secundario, TEXTO_SUAVE. Con un fondo oscuro, bajar el brillo del texto es la forma más elegante de restarle importancia.
¿Y un modo claro? Gracias a que todos los colores viven en Tema, un modo claro sería, en principio, cambiar unas pocas constantes: fondos claros, texto oscuro, superficies blancas con alfa. Pero el neón tendría que replantearse (por ejemplo, convertir los halos en sombras suaves). Es un buen ejercicio de diseño para cuando termines el libro.

Degradados

Un degradado es un paso gradual de un color a otro. Java calcula los colores intermedios mezclando los canales, igual que la fórmula del alfa pero a lo largo de una distancia. El Totito usa dos tipos.

Degradado lineal: GradientPaint

Se define con dos puntos y dos colores: en el primer punto el color es el primero, en el segundo es el segundo, y en medio se mezclan. La dirección del degradado es la línea que une los puntos.

// Fondo de todas las pantallas (PantallaBase): de arriba (y = 0) hacia abajo (y = alto).
g2.setPaint(new GradientPaint(0, 0, Tema.FONDO_ARRIBA, 0, alto, Tema.FONDO_ABAJO));
g2.fillRect(0, 0, ancho, alto);

Los dos puntos tienen la misma x (0) y distinta y: el degradado es vertical. Si tuvieran la misma y y distinta x, sería horizontal, como el de la palabra «Totito» del encabezado, que va de ROSA a la izquierda a CIAN a la derecha. Y si los dos colores son el mismo pero con distinto alfa, el resultado es un desvanecido: las líneas a los lados de «JUGADORES» van de morado transparente (alfa 0) a morado visible (alfa 170) y parecen apagarse hacia afuera.

Las píldoras rellenas de los botones (BotonNeon) llevan además un segundo degradado encima: de blanco con alfa 50 a blanco con alfa 0, solo en la mitad de arriba. Es un reflejo que imita la luz sobre un cristal curvo, y es lo que hace que «Comenzar partida» parezca abultado.

Degradado radial: RadialGradientPaint

En lugar de ir de un punto a otro, va del centro hacia afuera en círculos. Se define con un centro, un radio, una lista de posiciones (de 0 = centro a 1 = borde) y un color para cada posición:

// Resplandor morado suave en el centro de cada pantalla (PantallaBase).
g2.setPaint(new RadialGradientPaint(new Point2D.Float(ancho / 2f, alto * 0.55f), ancho * 0.65f,
        new float[]{0f, 1f},
        new Color[]{Tema.conAlfa(Tema.MORADO, 40), Tema.conAlfa(Tema.MORADO, 0)}));
g2.fillRect(0, 0, ancho, alto);

En el centro (un poco por debajo de la mitad de la ventana) hay morado con alfa 40; hacia el borde del círculo, morado con alfa 0. El efecto es una luz difusa que ilumina el centro de la pantalla, justo donde está la tarjeta, como si el neón alumbrara la habitación.

Más de dos colores GradientPaint solo admite dos colores. Si necesitas tres o más (por ejemplo, rosa → morado → azul), usa LinearGradientPaint, que funciona como el radial: una lista de posiciones entre 0 y 1 y un color para cada una.

Cómo se fabrica el neón

Un tubo de neón real es un tubo de vidrio con gas que brilla. Lo que el ojo ve son tres cosas: el centro del tubo, casi blanco de tanta luz; el tubo en sí, del color del gas; y un halo de luz que se difunde en el aire alrededor y se va apagando con la distancia. La pantalla no puede emitir «luz que se difunde», pero se puede imitar con capas. Esta es la idea completa de Dibujo.trazoNeon (su código se explica línea por línea en el capítulo 41):

  1. El halo: se dibuja la misma figura seis veces, de la más gruesa y transparente a la más fina y menos transparente.
  2. El tubo: se dibuja la figura una vez más, con su grosor real y el color casi opaco.
  3. El centro: si el trazo es grueso (5 píxeles o más, como el de las fichas), se dibuja una línea finita en el centro con el color aclarado hacia el blanco.

Las seis capas del halo, para un trazo de grosor g:

Capa (i)GrosorAlfaOpacidad
6 (la primera que se pinta)g + 14,462 %
5g + 12,0114 %
4g + 9,6166 %
3g + 7,2218 %
2g + 4,82610 %
1 (la última)g + 2,43112 %

Ninguna capa por sí sola es visible: la más opaca apenas llega al 12 %. El truco está en que se acumulan. Un punto del borde exterior del halo solo queda cubierto por la capa 6 (2 %): casi no se nota. Un punto pegado al tubo queda cubierto por las seis capas, y la opacidad acumulada llega a un 37 %. El resultado es un brillo que se va apagando suavemente hacia afuera, que es exactamente lo que el ojo interpreta como luz.

El método tiene además un parámetro intensidad que escala la opacidad de todas las capas: con 1 el brillo es normal; con 1,5 brilla más (un botón con el ratón encima); con 0,35 se ve apagado (la opción no elegida, el jugador que no tiene el turno). Así, un solo número controla el «encendido» de cualquier elemento del juego. En el capítulo 37 compilarás un programa pequeño que dibuja un círculo con y sin este truco, para que veas la diferencia con tus propios ojos.

Aclarar un color: mezclar con blanco

El centro del tubo de neón necesita «el mismo color, pero casi blanco». Para eso Tema tiene aclarar, que mezcla un color con el blanco:

public static Color aclarar(Color color, float factor) {
    int r = Math.round(color.getRed() + (255 - color.getRed()) * factor);
    int g = Math.round(color.getGreen() + (255 - color.getGreen()) * factor);
    int b = Math.round(color.getBlue() + (255 - color.getBlue()) * factor);
    return new Color(r, g, b, color.getAlpha());
}

Para cada canal, 255 - canal es «lo que le falta para llegar al blanco», y el factor dice qué parte de eso se agrega: 0 lo deja igual, 1 lo vuelve blanco, 0,5 lo deja a medio camino. Con el rosa y un factor de 0,6 (el que usa el centro del neón):

CanalCálculoResultado
Rojo255 + (255 − 255) × 0,6 = 255 + 0255
Verde59 + (255 − 59) × 0,6 = 59 + 117,6177
Azul212 + (255 − 212) × 0,6 = 212 + 25,8238

El resultado, (255, 177, 238), es un rosa muy pálido: sigue siendo «de la familia» porque conserva el matiz, pero tiene mucha más luz.

En el Totito, aclarar aparece con distintos factores según cuánto se quiere aclarar:

  • 0,15–0,2: los iconos y la flechita de los botones del menú y el borde de las píldoras, para que destaquen un poco sobre su propio relleno.
  • 0,35: el inicio del degradado de los títulos «Turno de…» y «¡Ganó…!» (de color aclarado a color puro, un brillo que recorre la palabra).
  • 0,6: el centro del tubo de neón.

Esta fórmula es un caso particular de una idea general que te encontrarás en cualquier programa gráfico: la interpolación lineal (en inglés, lerp): «ir de A hacia B una fracción t del camino», que se escribe A + (B − A) × t. Aclarar es interpolar hacia el blanco; oscurecer sería interpolar hacia el negro (canal × (1 − t)); un degradado es interpolar entre dos colores a lo largo de una distancia; y una animación es interpolar a lo largo del tiempo.

Resumen

  • La pantalla mezcla luz (mezcla aditiva): rojo, verde y azul, cada canal de 0 a 255; los tres al máximo dan blanco.
  • Hexadecimal (#RRGGBB) es la misma información en base 16: dos dígitos por canal. En Java se escribe con el prefijo 0x.
  • El canal alfa (0–255) controla la opacidad; el resultado es una mezcla ponderada con el fondo. La SUPERFICIE usa alfa 125 para el efecto de cristal.
  • HSB (matiz, saturación, brillo) sirve para crear variantes coherentes de un color: el Totito tiene seis colores del mismo matiz.
  • La paleta combina una base monocromática violeta con acentos análogos (cian, azul, morado, rosa); todos viven en Tema y nadie inventa colores sueltos.
  • El color tiene significado: la X siempre rosa, la O siempre azul, morado para lo neutral; y nunca debe ser la única pista.
  • El contraste se mide de 1 a 21; el texto normal necesita al menos 4,5. El blanco sobre el fondo del Totito da 16,85.
  • El neón son capas: seis trazos cada vez más finos y opacos, el tubo y un centro aclarado hacia el blanco con aclarar.
Aplícalo fuera del Totito
  • Una página web o una app: crea desde el primer día un único lugar con los colores (en CSS se llaman «variables»; en Android, un archivo de colores) y nómbralos por su función: fondo, texto, primario, peligro. Así podrás ofrecer modo claro y oscuro cambiando solo ese archivo.
  • Gráficos y reportes (por ejemplo, las ventas de la tienda del capítulo 68): usa una armonía análoga para las series de datos y reserva un color complementario para lo que debe alarmar, como el stock bajo. Comprueba el contraste de las etiquetas con el programa Colores.
  • Botones con estados: el patrón de conAlfa (mismo color, distinto alfa) y aclarar sirve para generar los colores de «normal», «ratón encima», «pulsado» y «desactivado» de cualquier botón a partir de un solo color base.
  • Accesibilidad en cualquier proyecto: antes de entregar, mide el contraste de cada texto con su fondo real y revisa que ningún mensaje dependa solo del color (añade un icono o una palabra).
